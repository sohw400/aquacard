# Aqua Reserve·리워드 정책 초안

작성일: 2026-10-13 · 상태: 제품 기본안, 실제 금융 조건 미확정

PoC는 연환산 단리 5%, 원화 기준 보상 대상 잔액 상한 1천만원, 리워드의 정수 원 단위 수령을 적용한다. Basic 페이백은 1%·월 1만원, Plus는 1.5%·월 3만원이다. [정책 파일](../src/lib/policy.ts)과 [경쟁 비교·파라미터](benchmark-and-parameters.md)를 기준으로 한다. 아래 실제 금융 조건은 별도 확정 대상이다.

## 1. 참고한 정보와 채택할 제품 경험

사용자는 KAST Reserve에 대해 다음과 같이 설명했다.

- 입금한 잔액에 약 8%로 보이는 보상이 적용되며 보상률이 가끔 변한다.
- 충전 후 바로 실시간으로 적립된다.
- Reserve 인출에 제한이 없다.
- 보상은 달러로 표시되지만 카드 결제에만 사용할 수 있다.

공식 약관으로 검증한 정보는 아니다. KAST나 제3자가 원자산을 운용하고 일부 수익을 남긴 뒤 지급한다는 부분은 사용자의 추정이다. 8%의 연환산 여부·APR/APY·지급 산식은 미확인이다.

이를 참고한 **Aqua Reserve 기본안**은 다음과 같다.

| 항목 | 제품 기본안 |
| --- | --- |
| 목적 | 사용자가 소비할 자금과 보유할 자금을 구분하고 보유 보상을 받는다 |
| 적립 | 충전 완료 시점부터 보유 잔액·시간에 따라 산정하고 실시간으로 표시한다 |
| 보상률 | 변동 가능하며 현재 보상률·적용 시점·이력을 안내한다 |
| 원자산 인출 | 별도 락업·중도 인출 패널티 없이 요청 가능하게 설계한다 |
| 원자산 결제 | 사용자 설정에 따라 결제 잔액 부족분을 즉시 사용 가능한 Reserve 자금으로 보충한다 |
| 리워드 | 원화 표시 카드 결제 전용 보상, 가칭 Aqua Rewards |
| 결제 페이백 | 적격 카드 결제 후 Aqua Rewards 적립, Reserve 보유 보상과 출처 구분 |
| 잔액 관리 | Reserve 원자산, 결제 잔액, 결제 전용 리워드를 분리한다 |

앱에 일반 코인을 입금할 수 있다는 조건과 그 자산을 Reserve에서 지원한다는 조건은 구분한다. Reserve 지원 자산과 보상 기준 단위는 파트너 구조에 맞춰 별도로 정한다.

## 2. 보상 산정 기본안

실제 보상률은 출시 전에 정한다. PoC의 초기값은 연환산 단리 5%이며 데모 설정에서 3%·5%·8%로 변경해 구간별 적립을 확인한다. **8%는 사용자 관찰과 계산 설명용 수치**이며 Aqua Card의 실제 지급 약정이 아니다.

단순 연 보상률로 설계할 경우 구간별 계산 예시는 다음과 같다.

> 구간 적립액 = 보상 기준 잔액 × 해당 구간의 연 보상률 × 보유 시간 ÷ 1년의 기준 시간

계산 예시는 연 365일과 비복리 기준이다. 기준 잔액 1,000,000원·연 8%·잔액 변화 없음이라면 하루 약 219.18원 상당이 적립된다. 실제 상품 산식과 표시 방식은 아직 확정하지 않았다.

- 충전 요청 시점이 아닌 **충전 완료·반영 시점**부터 해당 금액의 보상을 산정한다.
- 추가 충전·부분 인출·보상률 변경 시점마다 계산 구간을 나눈다.
- 보상률 변경 전 시간은 이전 보상률, 변경 후 시간은 새 보상률을 적용한다. 이미 적립한 보상을 새 보상률로 다시 계산하지 않는다.
- 인출 중인 금액의 산정 종료 시점과 실패 시 복원 규칙은 파트너 처리 흐름을 확인해 정한다.
- 카드 결제용으로 보류·이동한 Reserve 금액은 산정에서 제외하며 남은 적격 금액은 계속 적립한다. 취소로 실제 Reserve에 복원된 금액은 적립을 재개한다. 보류 기간의 보상 정산 규칙은 별도 결정한다.
- 계산용 소수 금액을 유지하고, 화면 표시와 실제 사용 가능 단위의 차이를 정의한다. 새로고침마다 반올림해 적립액이 늘거나 사라지지 않게 한다.
- 결제 전용 리워드는 Reserve 원자산에 자동 재투자하지 않는 기본안이다. 복리 산식이나 APY 표기를 자동으로 적용하지 않는다.

실시간으로 증가하는 화면과 실제로 결제에 사용할 수 있는 잔액은 구분한다. 초안에서는 **적립 중**과 **결제에 사용 가능**을 각각 표시한다. 적립액을 언제 사용 가능으로 확정할지는 지급·정산 구조에 따라 결정한다.

## 3. 원자산 인출

원하는 사용자 경험은 락업 없이 Reserve에서 자산 지갑 또는 결제 경로로 이동하는 것이다. 자유롭게 인출을 요청할 수 있는 것과 외부 네트워크·파트너의 실제 처리 시간은 구분한다.

기본 흐름:

**인출 가능액 확인 → 목적지·비용·예상 시간 확인 → 요청 → 처리 중 → 완료 또는 확인 필요**

- 부분 인출 후에는 남은 적격 잔액에 대해 계속 적립한다.
- 인출로 이미 적립한 리워드를 소급 회수하지 않는 기본안을 잡는다. 예외가 필요하면 사전에 정책으로 정한다.
- 원자산 인출과 리워드 현금화를 구분한다. 리워드는 현금 출금액에 포함하지 않는다.
- 잔액 대조 중이거나 파트너 처리 상태가 불확실하면 확인 가능한 상태와 다음 행동을 안내한다.

실제 외부 출금의 지원 경로·한도·비용·처리 시간은 파트너 조건 확인 전에는 확정하지 않는다.

## 4. 리워드 표시와 카드 사용

원화 표시는 결제 시 적용할 혜택의 단위다. 리워드가 원화 현금이나 원화 스테이블코인이라고 표시하지 않는다. 포인트형 화면 경험과 실제 권리·사업상 성격은 별도로 정한다.

카드 사용 기본안:

**카드 요청 → 적용 가능한 리워드 우선 반영 → 결제 잔액 적용 → 허용한 Reserve로 부족분 보충 → 승인 보류 → 거래 확정**

예를 들어 10,000원 거래에 리워드 3,000원 상당과 결제 잔액 7,000원을 쓸 수 있다. 실제 가맹점에 지급할 10,000원은 카드·정산 경로에 필요하며 리워드 사용분의 부담 주체와 자금을 정해야 한다.

- 리워드 사용 가능 거래·최소 단위·상한·우선순위를 정의한다.
- 승인 시 리워드와 결제 잔액을 각각 보류한다. 확정 후 사용 처리한다.
- 카드 승인 실패·승인 취소 시 각각의 보류를 해제한다.
- 환불은 사용자 자금과 리워드의 사용 구성을 보존해 복원하는 기본안이다. 확정 거래의 사용자 자금 환불은 결제 잔액, 리워드 환불은 리워드 기록에 반영한다. 부분 환불 배분, 만료 리워드 복원, 수수료 처리를 별도로 정한다.
- 리워드 사용 후 환불했다고 리워드가 현금성 잔액으로 전환되지 않게 한다.

### Reserve 원자산으로 결제

카드 자금 설정에서 Reserve 자동 사용을 켜고 대상 자산·전환 조건·한도를 확인하는 기본안이다. 대상은 즉시 결제 자금으로 연결할 수 있는 적격 잔액이다. 사용 가능한 자금이 부족하면 승인하지 않으며 별도 신용 제공을 전제하지 않는다.

- 결제 잔액에서 충당하고 부족한 금액만 Reserve에서 보류·이동한다.
- 일반 코인의 평가액 전체를 자동 사용 가능액으로 합산하지 않는다. 새로운 매도·전환이 필요한 자산은 시간·비용·실패 대응을 확인해야 한다.
- 결제 상세에 리워드·결제 잔액·Reserve 사용액을 각각 표시한다.
- 미전환 동일 자산의 보류 해제와 실제 코인 전환 이후 취소를 구분한다. 전환이 체결된 자산은 같은 코인 수량으로 복원한다고 약속하지 않는다.
- 확정 거래 환불의 사용자 자금 부분은 결제 잔액으로 반영하는 기본안이다. 다시 Reserve로 이동하는 경로를 제공한다.

### 결제 페이백

페이백은 적격 카드 결제에 따른 Aqua Rewards 적립을 기본안으로 한다. Reserve 보유 잔액·시간에 따른 보상과 별도로 계산하고 원거래와 연결해 기록한다.

**승인 시 예상 → 거래 확정·적격 확인 → 확정·사용 가능 → 다음 카드 결제 사용 또는 원거래 환불에 따른 조정**

- 초기 산정 기준은 수수료·리워드 사용분을 제외한 적격 사용자 자금 결제액이다. Reserve에서 사용한 사용자 자금도 포함한다.
- PoC는 Basic 1%·월 1만원, Plus 1.5%·월 3만원이며 모의 거래 확정 시 지급한다. 실제 조건은 미정이다.
- 취소·부분 환불에 해당하는 페이백만 취소·조정한다.
- 이미 사용한 페이백은 향후 혜택에서 상계하는 등 사전 정책을 정한다. 고객 원자산을 임의로 차감하는 기본안은 두지 않는다.
- 확정 페이백 사용분의 부담 주체와 정산 재원을 별도로 정한다.

예를 들어 결제 잔액·리워드가 없고 적격 Reserve 자금이 100,000원인 상황에서 자동 사용을 켜고 10,000원을 결제하면, 사용한 금액을 제외한 90,000원이 계속 보상 산정 대상이다. 1% 페이백을 설명용으로 가정하면 거래 확정 후 100원 상당이 별도 적립된다. 실제 비율·지원 조건은 확정하지 않았다.

## 5. Reserve 화면 초안

우선 표시할 내용:

1. Reserve 자산 수량과 평가 기준.
2. 현재 적용 보상률, 연환산 여부, 적용 시점.
3. 이번 구간 적립 중인 보상과 결제에 사용 가능한 보상.
4. 충전·인출 버튼과 인출 가능액.
5. 보상률 이력·적립 내역·결제 사용·복원 기록.
6. 카드 자동 사용 설정·적격 금액·승인 보류액과 Reserve 보상·페이백의 적립 출처.

실시간 표시가 실제 적립 기록과 어긋나지 않도록 기준 시점을 보여준다. 적립이 중단되거나 지원 조건을 충족하지 못하면 이유를 안내한다.

## 6. 재원과 운영 구조

제품 경험은 정했지만 보상 재원은 확정하지 않았다.

**일반 카드 결제대금은 사용자 선입금에서 지급한다.** Reserve 결제도 사용자의 자금으로 충당한다. 회사가 일반 결제대금 전체를 별도 비용으로 부담한다는 뜻이 아니다. 고객 자산을 카드 파트너가 요구하는 정산 자금으로 연결하는 과정은 필요하다.

Reserve 자산을 운용하지 않고 즉시 사용할 형태로 확보하면 운용 회수 문제는 없다. 운용 중인 경우에는 고객 잔액과 즉시 결제·인출에 사용할 수 있는 자금을 구분해야 한다. 실제 파트너의 승인·전환·정산 시점도 확인한다.

Reserve 보유 리워드와 결제 페이백은 추가 혜택이며 사용 시 사용자 원자산을 추가로 차감해 충당하는 구조를 전제하지 않는다. 해당 혜택 비용은 회사·제휴사의 실제 예산·수익과 연결한다.

| 검토할 재원 | 필요한 확인 |
| --- | --- |
| Aqua Card·제휴사의 보상 예산 | 지급 비용, 상한, 지속 가능한 보상률 |
| 실제 제휴 수익 | 계약상 당사 몫, 지급 시점, 고객 보상 부담 |
| 고객 자산 운용에서 생기는 수익 | 제공·운용 주체, 고객 동의·허용 범위, 손실 부담, 회수·인출 조건 |

자산을 운용하는 경우 **락업 없는 인출 요구와 운용 자산 회수 시간의 차이**를 해결해야 한다. 즉시 사용할 유동성, 회수 가능한 범위, 지급 재원과 장애 시 대응을 확인한다. 포인트 지급 자체가 유동성이나 손실 문제를 해결하지는 않는다.

카드 결제에 리워드가 사용되면 정산 비용이 발생한다. 사용률과 사용 시점, 이미 확정한 미사용 리워드를 함께 관리한다. 낮은 사용률이나 소멸만을 지속 가능한 재원으로 가정하지 않는다.

## 7. 프로토타입에서 검증할 상황

- 충전 완료 직후 적립 시작과 실시간 증가 표시.
- 중간 추가 충전·부분 인출 이후 적립 변화.
- 보상률 변경 전후 구간 계산과 변경 이력.
- 전체 인출 후 원자산 잔액과 이미 적립한 리워드의 분리.
- 리워드·결제 잔액 혼합 결제, 승인 실패·취소·부분 환불.
- Reserve 자동 사용 켜짐·꺼짐, 부분 보충·잔액 부족·전환 실패, 결제 중 보상 산정 제외·복원.
- 페이백 예상·확정·사용·부분 환불 조정과 이미 사용한 페이백의 상계.
- 중복 거래 알림·요청 재시도에서 잔액과 보상이 중복 반영되지 않는지 확인.
