# 합성 카드 동기 승인

로컬 테스트 발급사는 승인 여부를 한 요청에서 확인하고, 승인된 보류 금액을 기존 이벤트 수신 경로로 매입·취소·환불한다. 이 시뮬레이터는 TEST_KRW 원장의 발급·잠금·회원 자격 검사와 결제 재원 배분을 사용한다. 요청에 대한 HTTP 웹훅 접수와 별개로 실행하는 전용 명령이다. [비동기 이벤트 수신](card-event-inbox.md) · [승인 정책](card-authorization-policy.md)

## 실행

관리자가 `DATABASE_AUTHORIZATION_SIMULATOR_ROLE`에 지정한 테스트 전용 로그인에 마이그레이션으로 실행 권한을 부여한다. 작업자는 `AUTHORIZATION_SIMULATOR_DATABASE_URL`과 `DATABASE_SCHEMA`를 설정한다. 공개 API나 프로덕션에는 이 로그인을 배포하지 않는다. 실행 파일은 `NODE_ENV=production`에서 명령을 거절한다.

입력 UTF-8 JSON 파일의 필드는 `requestId`(소문자 UUID), `issuedAt`(발급사 역할의 시뮬레이터가 요청을 만든 Unix 밀리초), `userId`(합성 회원), `merchantName`(합성 가맹점), `amountWon`(양의 정수)이다. 승인 가능한 테스트 회원과 잠금 해제된 테스트 카드, 결제 재원을 준비한 뒤 현재 시각으로 파일을 만들고 즉시 실행한다. 같은 영수증을 다시 확인할 때는 최초 시각과 전체 내용을 보존한다.

```bash
npm run --silent server:authorization:simulate -- decide "$REQUEST_FILE"
npm run --silent server:authorization:simulate -- lookup "$REQUEST_UUID"
```

이미지에서는 `node dist-server/authorization-simulator.js`에 같은 인수를 전달한다. 기한은 발급사 생성 시각부터 2,000ms로 고정한 합성 시험값이다. DB 시계보다 앞선 생성 시각은 거절한다. 신속한 응답을 위해 처리 중인 같은 요청의 잠금은 기다리지 않는다. 응답 확인에는 최대 1,000ms의 여유를 두고, 이 시간에도 연결·커밋 결과를 확인할 수 없으면 `unconfirmed`로 종료한다. 입력은 로컬 파일이며 이 시간 측정은 입력 검증 이후부터 적용한다.

| 결과 | 처리 |
| --- | --- |
| `approved` | 한 번 기록된 결제 보류와 승인 결정이다. 후속 매입은 영수증의 `paymentId`를 사용한다. |
| `declined` | 각종 카드·회원 정책 또는 재원 부족으로 승인하지 않았다. 같은 요청의 재시도는 잔액·카드 상태가 바뀌어도 같은 결정을 반환한다. |
| `timed_out` | 처음부터 기한이 지났거나 잠금·승인 처리 중 기한을 넘겼다. 내부에서 이미 계산한 보류도 해당 거래 단위에서 되돌리고 시간 초과를 영구 기록한다. |
| `unconfirmed` | 커밋 결과, 진행 중인 요청 또는 요청의 도달 여부를 확인할 수 없다. `lookup`으로 조회하거나 같은 파일을 다시 보내 최종 결정을 확인한다. 새로운 요청 번호 발급이나 임의 환불로 처리하지 않는다. |

영수증은 요청 번호, 결제 번호, 결정, 기한과 결정 시각을 담는다. CLI의 `delivery`는 이번 응답을 확인한 경로와 시점이다. `within_window`는 기한 내, `after_deadline`는 응답 도착 시 이미 기한이 지났음을, `lookup`은 과거 결과 조회를 뜻한다. 늦게 확인한 승인을 새 승인 응답으로 보내지 않는다. 합성 발급사가 결제를 포기한 경우 확정된 보류를 기존 취소 이벤트로 정리한다. 확인한 결정 세 종류의 명령 종료값은 0이고 미확인·무효 입력은 2다. 보류·회원 상태·가맹점 원문·정책 거절 사유는 CLI 영수증에 넣지 않는다.

시뮬레이터는 `sync-auth:<요청 UUID>`와 `sync-pay:<요청 UUID>`를 사용한다. 같은 UUID에 다른 입력을 제출하면 충돌로 종료하며 기존 결정을 보존한다. 비동기 경로는 성공한 보류를 정산할 수 있고, 거절 또는 시간 초과된 동기 요청을 다시 승인할 수 없다. 이전 릴리스의 일반 텍스트 참조는 계속 처리하며, 과거 결제가 이미 생성 규칙의 UUID를 사용했다면 그 결제의 매입·환불을 유지하고 시뮬레이터 쪽 새 요청을 거절한다.

실제 발급사 연동에는 서명·카드 매핑 방식, 시계 오차, 네트워크 왕복을 포함한 응답 기한, 커밋 뒤 응답 유실, 대행 승인과 보류 취소·지연 매입의 계약상 책임을 확인해야 한다. 합성 CLI의 2초 설정과 로컬 시험은 제휴사 응답 시간이나 처리량의 실측 증빙이 아니다.
