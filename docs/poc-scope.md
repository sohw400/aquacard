# Aqua Card PoC 범위와 후속 기획

작성일: 2026-10-13 · 상태: 구현·검증 대상 정의

## PoC에서 결정한 기본안

스탠다드·프리미엄·프라이빗 세 멤버십의 카드, 코인 충전(받는 즉시 원화 스테이블로 전환), 원화 스테이블 잔액, Aqua 회원에게 보내기와 지갑 주소로 보내기, Reserve 보유 보상, 결제 페이백을 한 경험으로 연결한다. 앱은 코인을 보유 자산으로 들고 있지 않으며 코인 화면도 없다. 멤버십은 KAST의 구조를 따르고 요금과 요율은 한국 카드 시장에 맞췄다([기획 v0.7](kast-alignment.md)). 수치는 [경쟁 비교·파라미터](benchmark-and-parameters.md)와 [policy.ts](../src/lib/policy.ts)를 기준으로 한다. 시세·자금·본인 확인·카드 대행사 응답은 전부 모의 데이터다.

카드 신청 전에 실제 입금을 요구하지 않는다. 초기 화면에 표시하는 잔액은 체험을 위한 샘플 데이터다. 원화 스테이블은 제휴 준비 대상으로 표시하며 PoC가 원화 토큰을 발행했다고 설명하지 않는다.

## 추가로 정한 제품 원칙

- 카드가 활성화되기 전에는 결제를 허용하지 않는다. 잠금 중에도 같은 원칙을 적용한다.
- 받은 코인은 보유하지 않는다. 코인은 충전과 지갑 주소로 보내기 안에서만 고른다.
- Reserve 자동 사용은 사용자가 켠 경우에만 적용한다. 끈 상태에서는 리저브를 카드로 쓸 수 있는 돈에 넣지 않는다.
- 일반 결제대금은 사용자 자금에서 지급한다. 보유 보상·페이백은 별도 재원과 사용 기록을 가진다.
- 기본 페이백은 리워드·수수료를 제외한 적격 사용자 자금 결제액으로 계산한다. 월 상한은 한국 시간 기준으로 관리한다.
- 리워드 사용 후 환불해도 현금으로 바뀌지 않게 한다. 이미 사용한 페이백 회수는 향후 혜택에서 상계하며 고객 원금을 임의 차감하지 않는다.
- 카드 거래마다 실제 사용 출처를 기록한다. Reserve에서 이미 이동한 돈을 잔액과 Reserve 양쪽에서 차감하지 않는다.
- 코인 전환 후 카드 환불은 같은 코인 수량 재구매를 보장하지 않는다. 사용자 자금은 잔액으로, 리워드는 리워드로 복원한다.
- 모의 화면의 카드 번호·프로필·주소는 샘플이다. 배송지 검색은 가상의 예시 주소만 찾는다. 비밀번호는 해시만, 카드 비밀번호는 정했다는 사실만 저장한다.
- 카드 비용은 유료 멤버십의 연회비뿐이고 잔액에서만 낸다. 실물카드 발급·재발급은 무료다. 반려·보완 요청이면 낸 연회비를 돌려주고, 등급을 올리거나 해지할 때 이미 낸 연회비는 돌려주지 않는다.
- 보내기는 잔액에서만 나간다. 리워드와 리저브는 보내기에 쓰지 않는다.

## 실제 연동 전에 구체화할 것

### 카드 운영

대행사의 신청·심사·발급·카드 상태·승인·환불 인터페이스와 중복·지연 응답 처리, 카드 분실·도난·재발급, 기존 카드 종료, 배송 실패·반송, 이의 제기·분쟁·부정 사용 지원을 구체화한다. 발급·취소·재발급 비용과 고객 지원 책임을 계약에서 확정한다.

### Reserve·입출금

보관과 운용의 실제 주체, 한국 거주자 지원 범위, 인출·결제에 쓸 유동성, 보상 산정 기준·확정 시점·운용 재원, 자산별 출금 한도·네트워크 비용·오입금 대응, 회원 간 보내기의 태그 조회·받는 쪽 장부·한도·사업자 요건을 정한다.

### 요금·혜택

페이백 제외 거래와 가맹점 분류, 프로모션, 보상률 변경 고지, 미사용 혜택 비용과 재원을 설계한다. 연회비 청구와 갱신, 등급 변경, 해지는 PoC 모의 잔액으로 동작한다. 실제 청구·환불 규칙(일할 계산 여부 등)과 출시 요금은 발급사 계약과 재원 계산으로 확정한다.

### 기술·운영

서버 인증·권한, 고객별 금융 장부·잔액 대조, 이벤트 중복 방지와 재처리, 비밀 정보·카드 정보 보호, 오류·보안 모니터링, 고객 문의 이관을 준비한다. 브라우저 데모 장부를 서버 금융 장부로 그대로 옮기지 않는다.

### 모바일 앱

아이폰·안드로이드 앱은 React Native + Expo로 만들고 `src/lib`의 규칙을 공유 패키지로 옮기는 안을 제안했다. 스토어 배포 자격(가상자산사업자 신고), 금융 보안, 본인확인, 전자지갑 준비와 단계별 계획은 [모바일 앱 준비](mobile-app-plan.md)에 있다.

위 항목은 후속 기획 범위이며 실제 연동이 완료됐다는 뜻이 아니다. PoC 검증 결과는 실행 후 README와 작업 보고에 기록한다.
