# 기술 선택과 운영 방향

상태: 채택. 제품 화면과 서버 계약을 이어서 개발할 수 있도록 웹·API·원장의 기반을 정한다. 배포 대상과 앞으로 만들 기능을 현재 구현과 구분한다.

## 채택한 기반

| 영역 | 선택 | 이유 |
| --- | --- | --- |
| 언어·런타임 | TypeScript, Node.js 24 LTS | 웹과 API 계약을 공유하고 지원되는 LTS 런타임을 쓴다. |
| 웹 | React, Vite | 검증한 화면과 흐름을 유지한다. 계정·카드 앱에 불필요한 서버 렌더링 체계를 추가하지 않는다. |
| API | Fastify 5, JSON Schema, OpenAPI | 요청·응답 경계를 명시하고 API 문서를 같은 스키마에서 만든다. 직접 만든 HTTP 라우터를 유지하지 않는다. |
| DB | PostgreSQL 18, `pg` 비동기 연결 풀 | 인증·세션·원장을 서버 DB에서 관리하고 다른 프로세스의 동시 송금을 트랜잭션과 잠금으로 처리한다. |
| DB 변경 | 버전별 SQL 마이그레이션 | 적용 이력과 체크섬을 확인하고 advisory lock으로 중복 적용을 막는다. 시작 과정에 DDL을 숨기지 않는다. |
| 패키징 | Docker 다단계 빌드, 컴파일한 Node 서버 | 개발용 TypeScript 실행기 없이 동일한 운영 이미지를 검증·배포한다. |

SQLite는 초기 서버 실험에 사용했으며 현재 서버 원장의 기준 저장소로 유지하지 않는다. 이전 브라우저 체험 잔액이나 SQLite 테스트 데이터를 실제 자금으로 이전하지 않는다. PostgreSQL도 현재는 **테스트 금액 원장**이며 은행 원화·발행된 스테이블·카드 정산과 연결하지 않았다.

## 서버 구조

계정·인증, 원장, HTTP 경계와 마이그레이션을 모듈로 나눈 하나의 서버를 운영 단위로 삼는다. 같은 저장소에 웹 클라이언트와 공유 API 타입을 둔다. 웹 화면이 장부를 직접 수정하거나 로그인 계정을 지정해 권한을 얻을 수 없다.

송금은 서버 세션에서 보내는 계정을 결정한다. 계정 잠금과 DB 트랜잭션 안에서 검증·기록·양쪽 잔액 반영을 완료하고, 재시도는 같은 요청 키와 내용으로 확인한다. 브라우저 탭의 계정과 쿠키의 계정이 달라지면 송금·로그아웃을 거절한다.

금액은 부동소수 계산으로 저장하지 않고 정수 단위로 다룬다. 적용된 SQL을 나중에 고치는 대신 다음 번호의 변경을 추가한다. 데이터 모델과 API는 결제·파트너 연동을 붙일 기반이며 운영 통제를 모두 끝냈다는 뜻은 아니다.

## 현재 구현과 후속 작업

| 구분 | 내용 |
| --- | --- |
| 현재 구현 | PostgreSQL 계정·세션·테스트 원장, 회원 송금, 요청 키 중복 방지, 비밀번호 재설정의 개발용 전달, Fastify API 스키마, SQL 마이그레이션, 연결 웹 화면, 컨테이너 빌드와 CI. |
| 배포 대상 결정 | AWS 서울 리전 ECS Fargate와 RDS PostgreSQL. 파일·정산 자료·백업 연계 대상으로 S3와 KMS를 검토한다. |
| 아직 배포하지 않음 | AWS 리소스, ECS 서비스·RDS·로드 밸런서·네트워크·권한·키·비밀값 주입과 유료 인프라는 생성하지 않았다. 대상 결정은 서비스 가동 주장이 아니다. |
| 후속 구현 | 카드·KYC·발행사·보관·전환 파트너, 외부 입출금, 실제 메일, 웹훅 처리, outbox와 재처리, 대사·백업 복구·운영 관측. |

외부 호출을 DB 트랜잭션 안에 섞지 않는다. 파트너 연동이 생길 때 DB outbox와 중복 방지·재처리 정책을 구현한다. 현재 outbox가 구현됐다고 가정하지 않는다. Redis·Kafka·Kubernetes·별도 마이크로서비스는 현재 필수 구성에 넣지 않으며 실제 부하나 격리 요구가 확인되면 추가한다.

## 웹과 모바일

현재 산출물은 모바일 화면을 지원하는 React 웹 앱이다. iOS·Android 네이티브 앱이나 앱스토어 빌드는 아직 없다. 모바일 개발 기준은 React Native와 안정판 Expo 개발 빌드로 정한다. 발급사·본인확인 SDK가 요구하는 기능은 네이티브 모듈로 연결한다. 구현 시점에 호환되는 안정 버전을 확인하고 lockfile로 고정하며 프리뷰나 임의의 미래 버전에 의존하지 않는다.

모바일에서도 인증·권한·원장·송금·파트너 처리는 같은 API를 사용한다. 플랫폼 화면과 지갑·푸시·생체인증은 별도 구현·실기기 검증이 필요하다. 웹 DOM 화면 전체가 그대로 네이티브 화면으로 바뀐다고 약속하지 않는다.

## 배포와 변경 원칙

GitHub Pages는 공개 브라우저 데모를 계속 제공한다. 연결 화면은 API와 함께 별도 배포 대상으로 둔다. DB 접속 정보와 비밀값은 브라우저 빌드나 Pages에 넣지 않는다.

운영 이미지는 Node 24와 PostgreSQL 18의 확인한 digest를 사용하고 의존성은 lockfile로 설치한다. 런타임은 비루트 사용자로 컴파일한 JS를 실행한다. DB 마이그레이션 소유자와 제한된 애플리케이션 역할을 분리하고, 운영 API가 관리자·스키마 변경·직접 잔액 수정 권한을 가지면 시작을 거절한다. 배포 전에 별도 마이그레이션을 수행하고 API를 시작한다. 원격·운영 DB 연결은 서버 인증서를 검증하는 TLS를 사용한다.

DB 권한 분리, 백업 복구, 네트워크 경계, 로그·알림, 보존 정책과 파트너 장애 대응은 출시 전 검증할 작업이다. 자세한 절차는 [서버 개발 안내](server-development.md)를 따른다.
