# Aqua Card 신청·발급·운영 플로우

이 문서는 한국 대상 Aqua Card PoC의 카드 신청부터 활성화, 배송까지를 정의한다. 실제 카드 발급·본인확인·배송 요청은 없다. 모든 개인정보와 카드번호는 샘플이며 발급 대행사, 카드 네트워크, 국내 이용 조건은 아직 확정되지 않았다.

## 1. 제품 기본안

- 성인 사용자, 대한민국 프로필을 기준으로 카드·지갑 앱부터 시작한다.
- 기본 선택은 Basic 플랜과 무료 가상카드다. 실물카드는 신청 단계의 선택 옵션이다.
- Basic: 월 이용료 무료, 결제 페이백 1%, 월 지급 상한 10,000원.
- Plus: 월 4,900원, 결제 페이백 1.5%, 월 지급 상한 30,000원.
- 실물카드 일회성 발급비: 9,900원. 배송 안내: 영업일 5–7일.
- 위 값은 PoC 정책값이다. PoC에서 월 이용료·발급비를 실제 또는 모의 잔액에서 청구하지 않으며 실제 출시 전 수익성 및 파트너 비용 검증이 필요하다.
- 카드 결제는 활성화된 상태에서만 가능하다. 잠금 상태에서는 새 결제를 차단한다.

## 2. 신청 흐름과 화면

사용자가 입력·확인하는 신청 화면은 다음 3개다. 카드 준비 과정은 신청 후 자동으로 이어진다.

| 사용자 화면 | 내용 | 행동 |
| --- | --- | --- |
| 1. 본인확인 | 대한민국 성인 샘플 프로필, 실제 개인정보를 입력하지 않는 체험 안내 | 필수 확인 1개: ‘샘플 본인확인과 체험 안내를 확인했습니다.’ → 다음 |
| 2. 카드 선택 | Basic / Plus 비용·페이백·상한 비교, 무료 가상카드 기본 포함, ‘실물카드도 신청’ 선택 옵션, 실물 비용·배송 예상·샘플 주소 | 다음 |
| 3. 신청 확인 | 신청자, 플랜, 이용료, 페이백, 카드 종류, 발급비 요약. 비용과 혜택이 체험 조건이며 실제 청구하지 않음을 안내 | ‘선택한 플랜과 신청 조건을 확인했습니다.’ 확인 → 신청하기 |

사용자 화면과 엔진 상태는 구분한다. 엔진의 기존 신청 순서는 유지하며, 카드 선택 화면의 다음 버튼 한 번으로 `plan` → `details` → `review`를 순서대로 처리한다. `details` 상태에서도 같은 카드 선택 화면을 표시하므로 이전으로 돌아가 선택을 수정할 수 있다.

| 엔진 상태 | 사용자가 보는 것 | 전환 |
| --- | --- | --- |
| `not_applied` | 카드 혜택, 무료 가상카드, 실물카드 비용 | 카드 신청하기 → `identity` |
| `identity` | 본인확인 화면 | 샘플 체험 안내 확인 후 다음 → `plan` |
| `plan` | 카드 선택 화면 | 다음 클릭에서 먼저 `details`로 전환 |
| `details` | 같은 카드 선택 화면 | 같은 다음 클릭에서 `review`로 전환 |
| `review` | 신청 확인 화면 | 조건 확인 후 신청하기 → `submitted` |
| `submitted` | 카드 준비 중, 접수번호, 모의 심사·발급 안내 | 약 1,400ms 후 자동 `approved`; 체험 도구에서 보완 요청 → `needs_info`, 신청 거절 → `rejected`, 심사 승인 → `approved` |
| `needs_info` | 샘플 본인확인 재진행 안내, 기존 접수번호 | 다시 확인하기 → `identity`, 기존 접수번호 유지 |
| `rejected` | 승인되지 않았다는 안내, 지갑 자산 유지 설명 | 다시 신청하기 → `identity`, 신규 신청으로 초기화 |
| `approved` | 카드 준비 중, 가상카드 발급 중 안내 | 약 500ms 후 자동 `issued` |
| `issued` | 카드 준비 중, 활성화 중 안내 | 약 350ms 후 자동 `active` |
| `active` | 카드 정보, 이용 한도, 잠금·해제, 실물 배송 | 데모 결제 및 카드 관리 |

입력 중인 신청 화면에서 이전으로 돌아갈 수 있다. 신청 도중 카드 발급을 완료하지 않았어도 지갑 기능은 독립적으로 이용할 수 있다. 신청 상태는 브라우저에 저장되므로 다음 접속에서 이어서 확인할 수 있다.

기본 경로는 카드 화면에서 모의 심사·발급·활성화를 자동으로 시뮬레이션하며, 접수부터 사용 가능까지 약 2.25초가 걸린다. 화면에 모의 처리임을 명시하고 실제 대행사 요청은 보내지 않는다. 사용자는 심사 승인·발급·가상카드 활성화 버튼을 연속으로 누르지 않는다. 카드 화면 이탈이나 상태 변경 시 타이머를 정리하고, 복귀 시 현재 상태에서 자동 진행을 재개한다. 실시간 잔액 갱신 등 같은 상태의 재렌더링으로 타이머를 다시 시작하지 않는다.

심사 중 화면의 ‘체험 도구’는 기본적으로 접혀 있다. 도구를 열면 자동 심사를 일시정지하며, 보완 요청·신청 거절·심사 승인을 직접 시뮬레이션할 수 있다. 닫으면 자동 심사를 재개한다. 보완·거절 상태에서는 승인 타이머를 유지하지 않는다.

실제 출시에서는 샘플 확인을 실제 공급사의 KYC·고객 적격성 확인으로 대체하고, 공급사의 심사 결과와 발급·활성화 API 또는 검증된 웹훅에 따라 상태를 변경해야 한다. PoC 타이머가 실제 승인이나 카드 활성화의 근거가 되어서는 안 된다.

## 3. 실물카드 배송·활성화

1. 가상카드 발급 시 실물카드가 선택되어 있으면 `preparing`으로 진입한다.
2. 가상카드가 자동으로 활성화된 뒤, 카드 관리 화면에서 기본으로 접힌 ‘체험 도구’를 열고 배송 시작 버튼으로 `shipped`를 시뮬레이션한다.
3. 같은 도구 안의 배송 완료 버튼으로 `delivered`를 시뮬레이션한다. 제작·배송 조작은 일반 카드 이용 화면에서 드러나지 않는다.
4. 배송 완료 뒤에는 일반 카드 관리 화면의 실물카드 활성화 버튼을 눌러 `physicalActive=true`로 전환한다. 실물카드 활성화는 가상카드 자동 활성화와 구분한다.

가상카드는 배송을 기다리지 않고 활성화해 사용할 수 있다. 가상·실물카드는 같은 지갑 잔액과 정책을 공유하는 기본안이다. 실제 출시 시 분실 배송, 주소 변경, 배송 실패, 재배송 비용, 수령인 확인, 실물카드 PIN 설정과 재설정, 실물카드별 잠금·해지 범위는 파트너와 확정한다. PoC의 잠금은 전체 카드 결제를 차단한다.

## 4. 카드 이용·보안

- 모의 카드번호 `4242 4242 4242 2048`, 유효기간 `12/30`, 보안코드 `123`은 데모 데이터다. 실제 PAN이나 토큰을 발급하지 않는다.
- 기본 표시는 끝 4자리만 제공한다. 카드 정보 보기 / 숨기기를 선택할 수 있다.
- 실제 출시에서는 카드정보 열람 전 생체인증 또는 앱 인증을 요구한다. PAN/CVV를 Aqua의 일반 서버·로그·분석 이벤트·브라우저 로컬 저장소에 보관하지 않고 대행사의 PCI 범위 내 보안 SDK 또는 호스팅 화면을 사용한다.
- 일시 잠금은 새 결제 요청을 차단하며 환불·취소는 계속 처리한다.
- PoC 한도는 1회 500,000원, 일 1,000,000원, 월 5,000,000원이다. 실제 한도는 본인확인 등급, 리스크 정책과 발급사 조건에 따른다.
- 분실·도난 신고, 재발급, 카드 폐기 및 해지, 본인확인 실패, 고객지원 이관은 출시 전에 추가할 필수 운영 흐름이다.

## 5. 발급 대행사 인터페이스 기획

다음은 특정 공급업체 API를 확정한 것이 아니라 필요한 업무 인터페이스다.

| 인터페이스 | 필요한 책임 |
| --- | --- |
| 고객 등록 / 고객 상태 조회 | 고객 식별자, KYC 결과 참조, 적격성 상태; 원문 신분증을 앱이 직접 보관하지 않음 |
| 카드 신청 | 고객 ID, 플랜 ID, 가상·실물 선택, 약관 버전, 적절한 보안 수집 경로를 거친 배송 참조, idempotency key |
| 신청 상태 조회 / 보완 제출 | 대행사 접수 ID, 상태, 사유 코드, 요청 항목, 제출 기한, 재신청 가능 여부 |
| 카드 발급 / 활성화 | 카드 ID 및 안전한 표시 정보, 개별 활성화 상태; PAN 대신 토큰·끝 4자리 |
| 카드정보 열람 | 단기 세션 토큰, 서버 인증, 민감정보 마스킹, 인증 기록 |
| 카드 잠금 / 해제 / 해지 / 재발급 | 사용자 요청과 대행사 결과의 일치, 실패 시 재조회 및 롤백 안내 |
| 실물 제작 / 배송 조회 | 배송 상태, 마스킹 배송 정보, 운송장 접근, 수령·재배송 처리 |
| 카드 승인 / 매입 / 취소 / 환불 | 잔액 예약과 확정, 불일치 정산, 부분 환불, 중복 처리 방지 |

실제 카드 신청의 약관은 Aqua 서비스, 지갑·자산 보관, 카드 발급사, 개인정보·본인확인 위탁/제공, 실물 배송 등 필요한 내용을 구분한다. 마케팅 수신은 선택 동의로 분리하고 거절해도 신청을 진행할 수 있게 한다. 필수 동의마다 버전·일시·증거를 남긴다.

## 6. 웹훅·중복·실패 처리

- 카드 신청, 발급, 발급비 청구에는 각 작업의 고유 idempotency key를 사용한다. 클릭 반복, 네트워크 재시도, 새로고침으로 중복 카드나 중복 비용이 생기지 않아야 한다.
- 대행사 웹훅은 서명·시간을 검증하고 이벤트 ID를 저장해 중복을 무시한다. 처리 트랜잭션과 상태 전이를 함께 기록한다.
- 순서가 바뀐 웹훅은 공급업체 버전 또는 발생 시각 및 상태 조회로 조정한다. 이미 활성화된 카드를 늦게 도착한 심사 중 이벤트로 되돌리지 않는다.
- 응답 지연은 접수 여부를 먼저 조회한 후 재시도한다. 실패한 요청을 무조건 다시 생성하지 않는다.
- 발급 실패 시 카드가 생성되었는지 조회한다. 사용 불가·미완료 발급 상태를 명확히 표시하고 청구한 발급비는 대행사 정책에 따라 환불 또는 예약 해제한다. 기존 지갑 원금은 이동시키지 않는다.
- 실물 제작·배송 실패는 가상카드 이용 상태와 분리한다. 고객지원 케이스, 재배송 또는 발급비 회수 여부를 기록한다.
- 카드 해지·재발급 시 기존 카드의 폐기 여부, 토큰·자동결제의 처리, 아직 정산되지 않은 거래와 환불을 추적한다.
- 모든 운영 상태 변경에는 감사 기록과 사용자에게 이해 가능한 사유를 남긴다. 원문 인증자료·PAN·비밀키는 로그에 기록하지 않는다.

## 7. 실제 출시 전 확정할 조건

발급 대행사 및 국내 이용 지원, 적용 법률과 사업자 역할, 고객 확인·자금세탁방지 책임, 자산 보관·환전·정산 파트너, 원화 스테이블 발행사 연결 조건, 카드 승인 시 결제 가능한 자금 확보, Reserve 자산 운용·인출 조건, 리워드 사용분의 실재 정산 재원, 이용료·발급비 환불 정책, 사고 보상과 고객지원 책임을 실제 계약·법률 검토로 확정해야 한다. 원화 스테이블을 존재하는 자산이나 확정된 지급수단으로 표시하지 않는다.

현재 PoC의 목적은 신청·발급·자금 사용 경험을 검증하는 것이다. 실제 출시 가능성, 금융 수익 보장 또는 실제 카드 발급 승인을 의미하지 않는다.
