# Aqua Card 신청·발급·운영 흐름

이 문서는 한국 대상 Aqua Card PoC의 카드 신청부터 활성화, 배송, 멤버십 갱신, 재발급과 해지까지를 정의한다. 실제 카드 발급·본인확인·배송 요청은 없다. 모든 개인정보와 카드번호는 샘플이며 발급 대행사, 카드 네트워크, 국내 이용 조건은 아직 확정되지 않았다. 멤버십을 KAST 구조에 맞춘 배경은 [기획 v0.7](kast-alignment.md)에 있다.

## 1. 제품 기본안

- 성인 사용자, 대한민국 프로필을 기준으로 시작한다. 카드는 가입할 때 마친 본인확인으로 신청한다.
- 멤버십은 KAST와 같은 세 등급 구조이고, 요금과 요율은 한국 카드 시장에 맞췄다([한국 시장에 맞춘 파라미터](kast-alignment.md#한국-시장에-맞춘-파라미터)). 정책 값은 [policy.ts](../src/lib/policy.ts)의 `PLANS`에 있다.

| | 스탠다드 | 프리미엄 | 프라이빗 |
| --- | --- | --- | --- |
| 연회비 | 무료 | 100,000원 | 500,000원 |
| 카드 페이백 | 1%, 월 100만원 결제까지(최대 10,000원) | 1.5%, 월 200만원 결제까지(최대 30,000원) | 2%, 월 500만원 결제까지(최대 100,000원) |
| 리저브 보상 | 기본 연 5%, 1천만원까지 | 기본 + 0.5%p(연 5.5%), 3천만원까지 | 기본 + 1%p(연 6%), 5천만원까지 |
| 가상카드 | 무료, 신청하면 바로 발급 | 같음 | 같음 |
| 실물카드 | 선택, 무료 | 메탈 카드 포함 | 골드 카드 포함 |
| 실물카드 재발급 | 무료 | 무료 | 무료 |

- 기본 선택은 스탠다드와 무료 가상카드다. 실물카드 배송 안내는 5~7영업일이다.
- 카드 비용은 유료 멤버십의 연회비뿐이고 **잔액(원화 스테이블)**에서 낸다. 리워드·리저브로는 내지 않는다. 실물카드 발급과 재발급은 모든 등급에서 무료다. PoC는 이 규칙을 모의 잔액에 그대로 적용한다. 위 금액은 PoC 정책값이며 실제 출시 전 수익성과 파트너 비용 검증이 필요하다.
- 리저브 보상률과 상한은 카드가 사용 중일 때의 멤버십을 따른다. 카드가 없거나 신청 중이면 스탠다드 조건이다.
- 카드 결제는 활성화된 상태에서만 가능하다. 잠금 상태에서는 새 결제를 막는다.

## 2. 신청 흐름과 화면

카드가 없을 때 카드 탭은 3D 카드 이미지, 세 멤버십 요약(등급별 카드 이미지, 페이백, 리저브 추가 보상, 카드, 연회비)과 `카드 만들기` 버튼을 보여 준다. 홈의 카드 제안에서 `카드 만들기`를 누르면 카드 탭의 본인확인 단계로 바로 간다.

사용자가 입력·확인하는 신청 화면은 3개이고, 위에 `본인확인 · 멤버십 · 신청 확인` 진행 표시가 있다. 카드 준비 과정은 신청 후 자동으로 이어진다.

| 사용자 화면 | 내용 | 행동 |
| --- | --- | --- |
| 1. 본인확인 | 가입 때 확인한 이름, 생년월일, 휴대폰 번호(가운데 가림)와 `확인됨` 표시. 다시 촬영하지 않는다 | 필수 동의 1개: `본인확인 정보를 카드 발급사에 제공하는 데 동의해요.` → 다음. `그만두기`로 처음으로 |
| 2. 멤버십 | 세 멤버십의 연회비, 페이백, 리저브 추가 보상, 카드 비교. 스탠다드는 `실물카드도 받기`(무료, 배송 5~7영업일)를 고를 수 있고, 프리미엄·프라이빗은 메탈·골드 카드가 함께 나온다고 안내한다. 실물카드가 있으면 배송지(주소 찾기 → 상세 주소 → 받는 분 본인)를 넣어야 다음으로 간다 | 다음 |
| 3. 신청 확인 | 신청하는 분, 멤버십, 페이백(요율과 월 최대), 카드(가상카드 또는 가상카드와 실물카드), 받을 주소. 아래에 **지금 낼 금액**(유료 멤버십의 첫해 연회비)과 지금 잔액. 잔액이 모자라면 부족액과 `충전하기` 버튼을 보여 주고 신청 버튼을 막는다 | 유료 멤버십은 `멤버십과 낼 금액을 확인했어요.` 확인 → `100,000원 내고 신청하기`(프리미엄), `500,000원 내고 신청하기`(프라이빗). 스탠다드는 실물카드를 받아도 지금 낼 금액이 `없음`이고 `멤버십과 신청 내용을 확인했어요.` 확인 → `신청하기` |

사용자 화면과 엔진 상태는 구분한다. 엔진의 신청 순서는 유지하며, 멤버십 화면의 다음 버튼 한 번으로 `plan` → `details` → `review`를 순서대로 처리한다. `details` 상태에서도 같은 멤버십 화면을 보여 주므로 이전으로 돌아가 선택을 고칠 수 있다.

| 엔진 상태 | 사용자가 보는 것 | 전환 |
| --- | --- | --- |
| `not_applied` | 카드 소개와 세 멤버십 요약 | `카드 만들기` → `identity` |
| `identity` | 본인확인 화면 | 동의 후 다음 → `plan` |
| `plan` | 멤버십 화면 | 다음 클릭에서 먼저 `details`로 전환 |
| `details` | 같은 멤버십 화면 | 같은 다음 클릭에서 `review`로 전환 |
| `review` | 신청 확인 화면 | 확인 후 `SUBMIT_CARD` → 잔액에서 비용을 내고 `submitted` |
| `submitted` | `카드를 만들고 있어요`, 진행 막대, 접수번호 | 약 1,400ms 후 자동 `approved`. 체험 도구에서 `승인하기` → `approved`, `보완 요청` → `needs_info`, `거절하기` → `rejected` |
| `needs_info` | 본인확인을 한 번 더 해 달라는 안내와 기존 접수번호. 낸 비용은 돌려줬고 다시 신청할 때 낸다는 안내 | `다시 확인하기` → `identity`, 기존 접수번호 유지 |
| `rejected` | 승인되지 않았다는 안내, 낸 비용 환불 안내 | `다시 신청하기` → `identity`, 새 신청으로 초기화 |
| `approved` | 가상카드를 발급하고 있다는 안내 | 약 500ms 후 자동 `issued` |
| `issued` | 카드를 쓸 수 있게 준비한다는 안내 | 약 350ms 후 자동 `active` |
| `active` | 카드 면, 빠른 동작, 휴대폰 결제, 멤버십, 카드 설정 | 4장 |

입력 중인 신청 화면에서 이전으로 돌아갈 수 있다. 충전과 보내기는 카드 신청과 상관없이 쓸 수 있다. 신청 상태는 브라우저에 저장되므로 다음 접속에서 이어서 확인할 수 있고, 홈의 카드 자리에 `신청을 이어서 할 수 있어요`와 `신청 이어서 하기` 버튼이 보인다. 심사 중에는 `만드는 중이에요`와 `진행 상황 보기`, 승인되지 않았으면 `다시 신청하기`가 보인다.

기본 경로는 카드 탭에서 모의 심사·발급·활성화를 자동으로 시뮬레이션하며, 접수부터 사용 가능까지 약 2.25초가 걸린다. 화면에는 `체험판이라 잠시 뒤 자동으로 끝나요.`라고 알리고 실제 대행사 요청은 보내지 않는다. 사용자는 심사 승인·발급·가상카드 활성화 버튼을 연달아 누르지 않는다. 카드 화면 이탈이나 상태 변경 때 타이머를 정리하고, 돌아오면 현재 상태에서 자동 진행을 이어 간다. 실시간 잔액 갱신 같은 같은 상태의 재렌더링으로 타이머를 다시 시작하지 않는다.

심사 중 화면의 `체험 도구`는 기본적으로 접혀 있다. 도구를 열면 자동 심사를 멈추고 승인·보완 요청·거절을 직접 고를 수 있다. 닫으면 자동 심사를 다시 시작한다. 보완·거절 상태에서는 승인 타이머를 두지 않는다.

실제 출시에서는 샘플 확인을 실제 공급사의 KYC·고객 적격성 확인으로 대체하고, 공급사의 심사 결과와 발급·활성화 API 또는 검증된 웹훅에 따라 상태를 바꿔야 한다. PoC 타이머가 실제 승인이나 카드 활성화의 근거가 되어서는 안 된다.

### 신청 비용 처리

- `SUBMIT_CARD`는 `review` 상태에서만 받는다. 비용은 첫해 연회비(프리미엄 100,000원, 프라이빗 500,000원)다. 실물카드는 무료라 비용에 더하지 않는다. 잔액이 모자라면 신청 자체를 거절하고 아무것도 바꾸지 않는다(`잔액이 N원 부족해요. 충전한 뒤 신청해 주세요.`).
- 프리미엄·프라이빗은 실물카드가 함께 나오므로 배송지가 없으면 접수하지 않는다. 화면에서도 이 등급을 고르면 실물카드가 자동으로 선택된다.
- 낸 금액은 카드에 `chargedFee`로 남기고 거래 내역에 `카드 신청 비용`(−)으로 기록한다. 메모에는 `프리미엄 첫해 연회비 100,000원. 승인되지 않으면 돌려드려요.`처럼 적는다. 스탠다드는 비용이 없어 이 기록이 생기지 않는다.
- 심사가 `needs_info` 또는 `rejected`로 끝나면 `chargedFee`를 잔액으로 돌려주고 `카드 신청 비용 환불`(+)을 남긴다.
- 발급(`issued → active`)되면 `chargedFee`는 0이 되고, 유료 멤버십은 그날부터 1년 뒤 같은 날을 갱신일(`billingAt`)로 잡는다.
- 화면에서 보내는 카드 정보(`SET_CARD`)로는 비용·갱신일·예약 등급·비밀번호 설정 여부를 바꿀 수 없다. 접수(`submitted`)는 `SUBMIT_CARD`로만 되고, 접수한 뒤에는 멤버십과 실물카드 여부도 `SET_CARD`로 바꿀 수 없다.

## 3. 실물카드 배송·활성화

| 등급 | 실물카드 | 앱의 카드 면 |
| --- | --- | --- |
| 스탠다드 | 선택, 무료 | 네이비 |
| 프리미엄 | 메탈 카드 포함 | 그래파이트 메탈 |
| 프라이빗 | 골드 카드 포함 | 골드 |

카드 면은 등급을 따르므로 가상카드도 같은 색으로 보인다.

1. 가상카드 발급 때 실물카드가 있으면 `preparing`(만드는 중)으로 시작한다. 배송지는 이 단계까지 카드 설정의 `변경`으로 바꿀 수 있고, 배송이 시작되면 바꿀 수 없다.
2. 가상카드는 자동으로 활성화된다. 카드 탭 아래 접힌 `체험 도구`에서 `배송 시작`으로 `shipped`(배송 중)를 시뮬레이션한다.
3. 같은 도구의 `배송 완료`로 `delivered`(도착)를 시뮬레이션한다. 제작·배송 조작은 일반 카드 화면에 드러나지 않는다.
4. 도착 뒤 `받은 카드 쓰기 시작`을 눌러 **카드 비밀번호 4자리**를 두 번 넣는다. 같은 숫자 4개(1111)나 이어지는 숫자(1234, 9876)는 거절한다. 엔진은 비밀번호를 검사만 하고 저장하지 않으며 `pinSet=true`만 남긴다(`ACTIVATE_PHYSICAL`). 활성화 뒤에는 `카드 비밀번호 바꾸기`(`SET_CARD_PIN`)를 쓸 수 있다.

배송지 입력은 주소 찾기(도로명·지역 이름) → 상세 주소(동·호수, 없으면 비움) → 받는 분(가입자 본인) 순서다. 체험판은 실제 주소가 저장되지 않도록 가상의 예시 주소(예: 서울특별시 중구 아쿠아로 1)만 검색한다. 출시하면 도로명주소 검색 API를 연결한다.

가상카드는 배송을 기다리지 않고 바로 쓸 수 있다. 가상·실물카드는 같은 잔액과 정책을 공유한다. 실제 출시 때 분실 배송, 배송 실패, 재배송 비용, 실물카드별 잠금·해지 범위는 파트너와 확정한다. PoC의 잠금은 모든 카드 결제를 막는다.

## 4. 카드 이용·관리·보안

발급된 카드의 카드 탭은 위에서부터 다음 순서다.

- 큰 카드 면, 멤버십 이름과 `사용 중` 또는 `잠금`.
- 빠른 동작 3개: `카드 정보`(번호 보기·숨기기), `잠그기`(잠근 뒤에는 `잠금 풀기`), `결제해 보기`.
- 휴대폰 결제: 삼성페이, Apple Pay 추가(약관 동의 → 가입 휴대폰 인증번호 → 추가). 잠근 동안에는 추가할 수 없다.
- 멤버십: 지금 등급의 페이백과 리저브 추가 보상, 다음 갱신일(내리기를 예약했으면 바뀌는 날), 세 등급 목록과 `바꾸기`·`사용 중`·`예약됨`·`계속 쓰기`.
- 카드 설정: 결제 한도, 온라인·해외 결제, 실물카드 받기(없을 때) 또는 배송·활성화 상태, 분실·도난 신고, 카드 해지.

### 멤버십 변경과 연회비

| 동작 | 처리 |
| --- | --- |
| 올리기 (`CHANGE_PLAN` 더 높은 등급) | 새 등급의 연회비 전액을 잔액에서 바로 내고 즉시 바뀐다. 페이백 요율과 리저브 추가 보상도 바로 적용된다. 지금 등급의 남은 기간 연회비는 돌려주지 않는다(일할 계산 없음). 다음 갱신일은 바꾼 날부터 1년 뒤 같은 날이다. 확인 버튼은 `100,000원 내고 바꾸기`(프리미엄)처럼 금액을 보여 준다. 잔액이 모자라면 확인 시트가 부족액과 `충전하기`를 보여 주고 버튼을 막으며, 엔진도 거절한다 |
| 내리기 (`CHANGE_PLAN` 더 낮은 등급) | 바로 바꾸지 않고 **갱신일에 바뀌도록 예약**(`nextPlan`)한다. 그때까지 지금 혜택을 쓰고, 이미 낸 연회비는 돌려주지 않는다. 프라이빗에서 프리미엄으로 내리면 갱신일에 프리미엄 연회비가 나가고, 스탠다드로 내리면 더 나가지 않는다. 확인 버튼은 `{갱신일}에 바꾸기`다 |
| 예약 취소 (`CHANGE_PLAN` 지금 등급) | `계속 쓰기`. 예약만 지우고 비용은 없다 |
| 갱신일 | 그대로 쓰면 잔액에서 연회비를 내고 다음 갱신일을 1년 뒤로 미룬다. 예약한 등급이 있으면 그 등급으로 바꾸고 그 등급의 연회비를 낸다. 잔액이 모자라면 스탠다드로 바꾸고 거래 내역에 이유를 남긴다(`스탠다드로 변경`). 충전한 뒤 다시 올릴 수 있다 |

갱신일은 한국 시간 기준 같은 날짜다. 2월 29일에 시작했으면 평년에는 2월 28일로 맞춘다. 체험 시계가 여러 해를 건너뛰면 해마다 한 번씩 처리한다.

등급을 바꾼 달에는 그달에 이미 잡힌 페이백을 새 월 최대에서 뺀다. 전체 › 요금에는 지금 멤버십의 연회비와 다음 갱신일(또는 바뀌는 날)이 나온다.

카드 탭의 체험 도구 `갱신일(날짜)로 이동`(`ADVANCE_TO_BILLING`)으로 갱신일 처리를 바로 확인할 수 있다. 체험 시간이 그날로 옮겨지므로 그동안의 리저브 보상도 함께 쌓인다. 갱신일이 없는 스탠다드에서는 프리미엄으로 바꾸면 갱신일 이동을 해 볼 수 있다고 안내한다.

### 실물카드 추가, 재발급, 해지

| 동작 | 처리 |
| --- | --- |
| 실물카드 추가 (`ADD_PHYSICAL_CARD`) | 가상카드만 쓰던 사람이 카드 설정의 `실물카드 받기`(프리미엄은 `메탈 카드 받기`, 프라이빗은 `골드 카드 받기`)에서 배송지를 넣고 신청한다. 모든 등급에서 무료다. `preparing`부터 배송한다 |
| 분실·도난 신고 (`REISSUE_CARD`) | 지금 카드 번호를 바로 막고 새 끝번호로 재발급한다. 잠금은 풀리고 휴대폰 결제 등록은 지워져 다시 추가해야 한다. 실물카드가 있으면 같은 배송지로 새 카드를 보내고 `preparing`부터 다시 활성화한다. 재발급도 무료다 |
| 카드 해지 (`CLOSE_CARD`) | 확인 체크 후 해지한다. 카드 번호와 휴대폰 결제가 바로 멈추고 카드는 처음(`not_applied`, 스탠다드)으로 돌아간다. 유료 멤버십도 끝나고 이미 낸 연회비는 돌려주지 않는다. 리저브 보상률도 스탠다드 조건이 된다. 잔액·리저브·리워드는 그대로 남고, 리워드는 카드를 다시 만들면 쓸 수 있다. 확정 전 결제와 환불은 그대로 처리한다. 다음 카드는 새 끝번호로 나온다 |

등급을 올릴 때(`CHANGE_PLAN`) 실물카드는 아래처럼 처리한다. 실물카드가 어느 등급용인지는 `physicalPlan`, 보내는 중인 새 등급 카드는 `replacement`에 남긴다.

| 올릴 때의 실물카드 | 처리 |
| --- | --- |
| 없음 | 보내지 않는다. 카드 설정의 `메탈 카드 받기`(프라이빗은 `골드 카드 받기`)에서 주소를 넣으면 새 등급 카드를 무료로 보낸다 |
| 만드는 중(`preparing`) | 같은 카드를 새 등급 소재로 바꿔 만든다 |
| 배송 중·도착·사용 중 | 새 등급 카드를 등록한 배송지로 무료로 보낸다. 받을 때까지 지금 카드를 그대로 쓴다. 새 카드를 만드는 동안에는 배송지를 바꿀 수 있다 |
| 같은 등급 이상의 카드를 이미 가짐 | 보내지 않는다. 예를 들어 프라이빗에서 내렸다가 프리미엄으로 다시 올리면 골드 카드를 그대로 쓴다 |

새 카드가 도착하면 카드 설정의 `새 카드 쓰기 시작`(`ACTIVATE_REPLACEMENT`)으로 바꾼다.

- 이전 실물카드는 그때 결제가 막힌다.
- 카드 번호, 휴대폰 결제, 카드 비밀번호는 그대로다. 비밀번호를 정한 적이 없으면 이때 정한다.

그 밖의 경우는 이렇게 처리한다.

- **등급을 내릴 때.** 가진 실물카드는 그대로 쓴다.
- **분실·도난 재발급.** 지금 멤버십의 카드를 보내고, 보내던 교체 카드는 막는다.
- **교체 카드가 오는 중에 더 높게 올릴 때.**
  - 그 카드가 아직 만드는 중이면 새 등급으로 바꿔 만든다.
  - 이미 보냈으면 그 카드를 막고 새로 보낸다.
- **체험판.** 카드 탭의 `체험 도구`에서 교체 카드의 배송 단계를 넘긴다(`ADVANCE_REPLACEMENT`).

메탈·골드 카드의 제작·배송 원가는 출시 전에 재원과 함께 정한다.

### 결제 한도와 결제 방식

- 최대 한도는 1회 500,000원, 일 1,000,000원, 월 5,000,000원이다. 사용자는 **결제 한도** 화면에서 1만원 단위로 낮출 수 있다(1회 ≤ 하루 ≤ 한 달). 결제는 사용자가 정한 한도로 검사한다.
- 한도는 멤버십과 상관없이 같다. 월 최대 500만원은 프라이빗의 페이백 대상 월 결제액과 같아서 세 등급 모두 페이백 한도까지 쓸 수 있다.
- **온라인·해외 결제**를 각각 끌 수 있다. 꺼진 방식의 결제는 바로 거절하고, 매장 결제와 휴대폰 결제는 그대로 된다. 결제마다 방식(`store`·`online`·`overseas`)을 기록해 거래 상세에 보여 준다.

### 카드 정보와 보안

- 모의 카드번호 `4242 4242 4242 {끝번호}`, 유효기간 `12/30`, 보안코드 `123`은 데모 데이터다. 실제 PAN이나 토큰을 발급하지 않는다. `카드 정보`를 누르면 `체험용 카드 정보예요. 실제로 결제되지 않아요.`와 함께 보인다.
- 기본 표시는 끝 4자리만 제공한다. `카드 정보` / `정보 숨기기`로 바꾼다.
- 실제 출시에서는 카드정보 열람 전 생체인증 또는 앱 인증을 요구한다. PAN/CVV를 Aqua의 일반 서버·로그·분석 이벤트·브라우저 로컬 저장소에 보관하지 않고 대행사의 PCI 범위 내 보안 SDK 또는 호스팅 화면을 사용한다.
- 일시 잠금은 새 결제 요청을 막으며 환불·취소는 계속 처리한다.
- 실제 한도는 본인확인 등급, 리스크 정책과 발급사 조건에 따른다.
- 본인확인 실패와 고객지원 이관, 해지 후 재가입 제한 같은 운영 흐름은 출시 전에 파트너와 확정한다.

## 5. 발급 대행사 인터페이스 기획

다음은 특정 공급업체 API를 확정한 것이 아니라 필요한 업무 인터페이스다.

| 인터페이스 | 필요한 책임 |
| --- | --- |
| 고객 등록 / 고객 상태 조회 | 고객 식별자, KYC 결과 참조, 적격성 상태. 원문 신분증을 앱이 직접 보관하지 않음 |
| 카드 신청 | 고객 ID, 멤버십 ID, 가상·실물 선택, 약관 버전, 적절한 보안 수집 경로를 거친 배송 참조, idempotency key |
| 신청 상태 조회 / 보완 제출 | 대행사 접수 ID, 상태, 사유 코드, 요청 항목, 제출 기한, 재신청 가능 여부 |
| 카드 발급 / 활성화 | 카드 ID 및 안전한 표시 정보, 개별 활성화 상태. PAN 대신 토큰·끝 4자리 |
| 카드정보 열람 | 단기 세션 토큰, 서버 인증, 민감정보 마스킹, 인증 기록 |
| 카드 잠금 / 해제 / 해지 / 재발급 | 사용자 요청과 대행사 결과의 일치, 실패 시 재조회 및 롤백 안내 |
| 실물 제작 / 배송 조회 | 배송 상태, 마스킹 배송 정보, 운송장 접근, 수령·재배송 처리, 등급 변경 때 카드 교체 |
| 카드 승인 / 매입 / 취소 / 환불 | 잔액 예약과 확정, 불일치 정산, 부분 환불, 중복 처리 방지 |

실제 카드 신청의 약관은 Aqua 서비스, 잔액·자산 보관, 카드 발급사, 멤버십 연회비와 갱신, 개인정보·본인확인 위탁/제공, 실물 배송 등 필요한 내용을 구분한다. 마케팅 수신은 선택 동의로 분리하고 거절해도 신청을 진행할 수 있게 한다. 필수 동의마다 버전·일시·증거를 남긴다.

## 6. 웹훅·중복·실패 처리

- 카드 신청, 발급, 연회비 청구에는 각 작업의 고유 idempotency key를 사용한다. 클릭 반복, 네트워크 재시도, 새로고침으로 중복 카드나 중복 비용이 생기지 않아야 한다. 연회비 갱신 청구는 갱신일마다 한 번만 일어나야 한다.
- 대행사 웹훅은 서명·시간을 검증하고 이벤트 ID를 저장해 중복을 무시한다. 처리 트랜잭션과 상태 전이를 함께 기록한다.
- 순서가 바뀐 웹훅은 공급업체 버전 또는 발생 시각 및 상태 조회로 조정한다. 이미 활성화된 카드를 늦게 도착한 심사 중 이벤트로 되돌리지 않는다.
- 응답 지연은 접수 여부를 먼저 조회한 후 재시도한다. 실패한 요청을 무조건 다시 생성하지 않는다.
- 발급 실패 시 카드가 생성되었는지 조회한다. 사용 불가·미완료 발급 상태를 명확히 표시하고 청구한 연회비는 대행사 정책에 따라 환불 또는 예약 해제한다. 기존 잔액은 건드리지 않는다.
- 실물 제작·배송 실패는 가상카드 이용 상태와 분리한다. 고객지원 케이스와 재배송 여부를 기록한다.
- 카드 해지·재발급 때 기존 카드의 폐기 여부, 토큰·자동결제의 처리, 아직 정산되지 않은 거래와 환불을 추적한다.
- 모든 운영 상태 변경에는 감사 기록과 사용자에게 이해 가능한 사유를 남긴다. 원문 인증자료·PAN·비밀키는 로그에 기록하지 않는다.

## 7. 실제 출시 전 확정할 조건

발급 대행사 및 국내 이용 지원, 적용 법률과 사업자 역할, 고객 확인·자금세탁방지 책임, 자산 보관·환전·정산 파트너, 원화 스테이블 발행사 연결 조건, 카드 승인 시 결제 가능한 자금 확보, Reserve 자산 운용·인출 조건, 리워드 사용분의 실재 정산 재원, 출시 요금(연회비와 페이백 한도), 연회비 환불 정책(일할 계산 여부 포함), 무료 실물카드의 제작·배송 원가 부담, 등급 변경 때 실물카드 교체, 사고 보상과 고객지원 책임을 실제 계약·법률 검토로 확정해야 한다. 원화 스테이블을 존재하는 자산이나 확정된 지급수단으로 표시하지 않는다.

### 연말정산 소득공제와 영수증 (2026-10-14 검토)

- **현금영수증은 Aqua 카드 결제와 관계없다.** 카드로 결제하면 가맹점이 카드 매출전표를 준다. 현금영수증은 현금·계좌이체 결제에 발행한다.
- **사용자에게 중요한 것은 연말정산 소득공제다.**
  - 조세특례제한법 제126조의2는 신용카드 사용액을 15%, 여신전문금융업법상 직불카드와 기명식 선불카드 사용액을 30% 공제한다(2026 기준, 2028-12-31까지 적용).
  - 2026-08 기획재정부 개편안이 나와 있지만 국회 통과 전이다.
  - 국내 카드사가 사용 내역을 국세청에 내야 연말정산 간소화에 잡힌다. 출처는 요약 자료라 조문 원문으로 다시 확인한다.
- **해외 발급 카드는 공제를 못 받을 가능성이 크다.**
  - 조문은 여신전문금융업법상 카드를 요건으로 한다. 그래서 해외에서 발급한 카드는 대상이 아니라고 읽힌다(조문 해석, 확인 필요).
  - 이렇게 되면 KAST식 해외 발급 카드는 국내 체크카드보다 사용자에게 불리하다.
- **발급 파트너에게 확인할 것:**
  - 카드의 법적 분류: 직불카드, 기명식 선불카드, 해외 발급 카드 중 무엇인지.
  - 국세청 사용 내역 제출, 연말정산 간소화 반영, 공제 구간.
  - 코인이나 원화 스테이블로 채운 잔액으로 결제한 금액도 똑같이 처리되는지.
  - 매출전표에 찍히는 카드사 이름.
- **세무 검토로 정할 것:**
  - Aqua가 받는 연회비·출금 수수료의 부가가치세와 증빙(영수증, 현금영수증, 세금계산서).
  - 코인을 원화 스테이블로 바꿀 때의 가상자산 과세(2027-01-01 시행 예정). 이는 [KAST 비교의 세금 자료](kast-alignment.md#세금-자료)에서 다룬다.
