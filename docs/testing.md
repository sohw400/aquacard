# Aqua Card 테스트 방법과 지원 범위

작성일: 2026-10-13

## 현재 구현 형태

Aqua Card는 React 기반 반응형 **웹 PoC**다. iPhone과 Android의 화면 크기·터치 입력을 고려하지만 iOS 프로젝트·Android 프로젝트·앱 설치 파일은 아직 없다. TestFlight, APK, Expo Go로 실행하는 버전이 아니다.

본인 확인, 카드 발급·배송, 자금 이동과 시세는 모의 데이터다. 기기별 화면 검증이 실제 금융·카드 파트너 연동을 검증한 결과는 아니다.

## 자동 테스트

기존 개발 서버가 없으면 첫 터미널에서 실행한다.

```bash
cd /workspace/aquacard
npm run dev
```

서버가 실행 중인 상태에서 다른 터미널에서 실행한다.

```bash
cd /workspace/aquacard
npm test
npm run test:browser
npm run test:devices
npm run build
```

- `npm test`: 적립·결제·한도·페이백·환불·입출금·카드 비용·플랜 결제일·재발급·해지·탈퇴·가입·저장 상태의 로직 82개.
- `npm run test:browser`: 데스크톱과 390px 모바일에서 가입·카드 신청(배송지·신청 비용)·심사·발급·실물 활성화(카드 비밀번호)·잠금·결제·환불·적립·복원, 입출금·견적 만료, 결제 한도·온라인 결제 차단·거래 상세, 플랜 변경·재발급·해지, 비밀번호 변경·알림 동의·탈퇴 안내 등 36개 검증.
- `npm run test:devices`: 아래 5개 기기 프로필의 화면·터치·카드 신청·결제·페이백·복원 검증.
- `npm run build`: TypeScript 확인과 배포용 정적 파일 생성.

브라우저 테스트에는 Chromium이 필요하다. 현재 환경의 실행 파일은 `/usr/bin/chromium`이며 `CHROMIUM_PATH`로 바꿀 수 있다. 서버 주소는 `AQUA_BASE_URL`로 설정한다. 결과와 화면 이미지는 `artifacts/`에 저장한다.

## 기기 프로필 검증의 의미

| 프로필 | CSS 화면 너비 | 모사할 조건 |
| --- | --- | --- |
| iPhone SE | 320px | 작은 화면·터치·iPhone 사용자 에이전트 |
| iPhone SE 3세대 | 375px | 표준 소형 iPhone 화면·터치 |
| iPhone 15 Pro Max | 430px | 큰 iPhone 화면·터치 |
| Pixel 7 | 412px | Android 화면·터치·Android 사용자 에이전트 |
| Galaxy S9+ | 320px | 좁은 Android 화면·터치 |

**모든 프로필은 Chromium 엔진에서 실행한다.** iPhone 프로필의 화면 크기·배율·터치·사용자 에이전트를 지정해도 실제 iOS나 Safari/WebKit이 실행되는 것은 아니다. Android 프로필도 실제 Android OS·휴대폰 하드웨어를 사용하지 않는다.

기기 프로필에서는 4개 주 메뉴와 3개 상세 화면의 가로 넘침, 44px 이상 메뉴·뒤로 가기·토글 터치 영역, 입력·선택 글자 크기, 코인·네트워크 선택과 입금 처리, 출금 주소·비용·취소 복원, 모달 포커스·큰 카드 비율, 3화면 신청과 자동 모의 카드 활성화, Reserve 자동 사용 결제, 페이백, 새로고침 후 복원을 확인한다.

홈 인디케이터·노치를 고려한 safe-area CSS, 동적 화면 높이와 16px 이상 텍스트 입력을 반영했다. 실제 시스템 UI·키보드 동작은 실기기에서 별도로 확인한다.

## 직접 눌러 보는 테스트

실제 이름·휴대폰·주소를 넣지 말고 `체험용 주소 넣기`, `샘플 정보 채우기`, 예시 주소 검색을 쓴다.

1. **가입**: 체험용 이메일 → 화면에 보이는 코드 입력 → 비밀번호 → 휴대폰 인증 → 신분증·얼굴 확인 → 고객확인 질문 → 시작하기.
2. **카드 신청**: 홈의 `카드 신청` → 본인확인 동의 → Aqua Plus와 실물카드 선택 → 배송지 입력(아쿠아로 검색 → 상세 주소) → 신청 확인에서 낼 금액 14,800원(Plus 첫 달 4,900원 + 발급비 9,900원)을 확인하고 신청한다. 결제 잔액이 128,500원에서 113,700원이 된다.
3. **실물카드**: 발급이 끝나면 카드 관리의 접힌 체험 도구에서 배송 시작·배송 완료 → 실물카드 활성화. 비밀번호 1234는 거절되고 2580 같은 번호로 활성화된다.
4. **플랜**: `Basic으로 바꾸기`로 다음 결제일에 바뀌도록 예약하고 `Plus 계속 쓰기`로 취소한다. 체험 도구의 `다음 결제일로 이동`을 누르면 결제 잔액에서 4,900원이 나가고 다음 결제일이 한 달 뒤로 밀린다.
5. **충전**: 자산의 `충전할 수 있는 코인`에서 USDC → 국내 거래소 → 주소·보내는 순서 확인 → 보낸 수량 10 → 입금 체험. 확인이 끝나면 14,000원이 수수료 없이 결제 잔액에 들어오고, 자산 탭에는 코인 보유량이 생기지 않는다.
6. **출금**: USDC·Polygon, 예시 주소, 10,000원 → 전환 수수료 50원·네트워크 비용 140원·9,810원 상당 수령 확인 → 이메일 인증 코드 입력 → 접수. 원화 스테이블로 출금하면 전환 수수료가 없다.
7. **결제**: 결제 체험에서 결제 방식(매장·온라인·해외)을 고른다. 전체 › 온라인·해외 결제에서 온라인을 끄면 온라인 결제만 거절된다. 전체 › 결제 한도에서 1회 한도를 10만원으로 낮추면 그보다 큰 결제가 거절된다.
8. **리워드**: 리워드 카드의 소수점 숫자가 1초마다 오르는지, 결제하면 리워드에서 먼저 빠지는지 영수증으로 확인한다.
9. **이용 내역**: 결제 행의 `상세`에서 승인번호·결제 방식·리워드/결제 잔액/리저브 사용액·페이백을 보고 환불한다.
10. **계정**: 전체에서 비밀번호 변경, 알림 설정(광고성 정보 동의·철회 날짜), 자주 묻는 질문, 약관, 회원 탈퇴(남은 할 일 목록)를 연다.
11. **분실·해지**: 카드 관리의 분실·도난 신고로 끝번호가 바뀌고 휴대폰 결제 등록이 지워지는지, 실물카드가 있으면 재발급비가 나가는지 본다. 카드 해지 뒤에도 결제 잔액·리저브·리워드는 남는다.
12. **복원**: 입금 대기 중 새로고침해도 자산의 입출금 현황에서 같은 요청을 다시 열어 마칠 수 있다.

## 실제 휴대폰에서 확인할 것

아이폰은 Safari, Android는 Chrome에서 [공개 웹 데모](https://sohw400.github.io/aquacard/)를 연다. 실제 자금이나 본인확인 자료를 입력하지 않고 샘플 상태로 체험한다. 공개 배포와 HTTPS 파일 응답은 확인했으며, 아래 실기기 검증은 별도로 수행한다.

실기기에서는 다음을 확인한다.

- 노치·홈 인디케이터와 하단 메뉴·버튼이 겹치지 않는지.
- 키보드가 열린 모달의 입력·확인 버튼을 사용할 수 있는지.
- 입력 시 의도하지 않은 화면 확대, 선택창·스크롤 문제 여부.
- 회전·브라우저 주소창 변화·백그라운드 복귀 후 화면과 적립 표시.
- 새로고침·탭 재실행·저장소 제한 상황의 데모 상태 복원.

실제 Safari/WebKit·Android 실기기 검증은 아직 수행하지 않았다. 네이티브 앱 단계에서는 공유 가능한 도메인 로직을 활용하고 모바일 UI·저장·기기 기능을 따로 구현한 뒤, iOS/Android 빌드와 실기기 검증을 추가한다.
