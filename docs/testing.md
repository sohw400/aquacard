# Aqua Card 테스트 방법과 지원 범위

작성일: 2026-10-13

## 현재 구현 형태

Aqua Card는 React 기반 반응형 **웹 PoC**다. iPhone과 Android의 화면 크기·터치 입력을 고려하지만 iOS 프로젝트·Android 프로젝트·앱 설치 파일은 아직 없다. TestFlight, APK, Expo Go로 실행하는 버전이 아니다.

본인 확인, 카드 발급·배송, 자금 이동과 시세는 모의 데이터다. 기기별 화면 검증이 실제 금융·카드 파트너 연동을 검증한 결과는 아니다.

## 자동 테스트

기존 개발 서버가 없으면 첫 터미널에서 실행한다.

```bash
cd /workspace/aquacard
npm run dev
```

서버가 실행 중인 상태에서 다른 터미널에서 실행한다.

```bash
cd /workspace/aquacard
npm test
npm run test:browser
npm run test:devices
npm run build
```

- `npm test`: 적립·결제·한도·페이백·환불·충전·보내기(회원·지갑 주소)·태그 만들기와 바꾸기·휴대폰 번호와 이메일 찾기·회원에게 받기·연간 요약과 복사 내역·카드 비용·멤버십 연회비와 갱신·등급을 올릴 때 실물카드 교체·재발급·해지·탈퇴·가입·저장 상태와 이전 데이터 변환·숫자 뒤 조사의 로직 115개.
- `npm run test:browser`: 데스크톱과 390px 모바일에서 가입, 카드 신청(멤버십·배송지)·심사·발급·실물 활성화(카드 비밀번호)·잠금·결제·환불·적립·복원, 충전과 보내기·견적 만료, 결제 한도·온라인 결제 차단·거래 상세, 멤버십 변경(메탈·골드 카드 교체 배송과 쓰기 시작)·재발급·해지, 내 태그와 QR·태그 바꾸기·휴대폰 번호와 이메일 찾기·QR 찍기·받기 체험과 알림, 연간 거래 내역과 내역 복사, 비밀번호 변경·알림 동의·탈퇴 안내 등 49개 검증.
- `npm run test:devices`: 아래 5개 기기 프로필의 화면·터치·보내기(내 태그와 QR, QR 찍기)·연간 거래 내역·카드 신청·결제·페이백·복원 검증.
- `npm run build`: TypeScript 확인과 배포용 정적 파일 생성.

브라우저 테스트에는 Chromium이 필요하다. 현재 환경의 실행 파일은 `/usr/bin/chromium`이며 `CHROMIUM_PATH`로 바꿀 수 있다. 서버 주소는 `AQUA_BASE_URL`로 설정한다. 결과와 화면 이미지는 `artifacts/`에 저장한다.

## 기기 프로필 검증의 의미

| 프로필 | CSS 화면 너비 | 모사할 조건 |
| --- | --- | --- |
| iPhone SE | 320px | 작은 화면·터치·iPhone 사용자 에이전트 |
| iPhone SE 3세대 | 375px | 표준 소형 iPhone 화면·터치 |
| iPhone 15 Pro Max | 430px | 큰 iPhone 화면·터치 |
| Pixel 7 | 412px | Android 화면·터치·Android 사용자 에이전트 |
| Galaxy S9+ | 320px | 좁은 Android 화면·터치 |

**모든 프로필은 Chromium 엔진에서 실행한다.** iPhone 프로필의 화면 크기·배율·터치·사용자 에이전트를 지정해도 실제 iOS나 Safari/WebKit이 실행되는 것은 아니다. Android 프로필도 실제 Android OS·휴대폰 하드웨어를 사용하지 않는다.

기기 프로필에서는 4개 주 메뉴(홈·카드·혜택·전체)와 상세 화면의 가로 넘침, 44px 이상 메뉴·뒤로 가기·토글 터치 영역, 입력·선택 글자 크기, 충전의 코인·네트워크 선택과 입금 처리, 지갑 주소로 보내기의 주소·비용·취소 복원, 모달 포커스·큰 카드 비율, 3화면 신청과 자동 모의 카드 활성화, Reserve 자동 사용 결제, 페이백, 새로고침 후 복원을 확인한다.

홈 인디케이터·노치를 고려한 safe-area CSS, 동적 화면 높이와 16px 이상 텍스트 입력을 반영했다. 실제 시스템 UI·키보드 동작은 실기기에서 별도로 확인한다.

## 직접 눌러 보는 테스트

실제 이름·휴대폰·주소를 넣지 말고 `체험용 주소 넣기`, `샘플 정보 채우기`, 예시 주소 검색을 쓴다. 아래 순서대로 하면 금액이 적힌 대로 나온다. 가입 직후 잔액은 128,500원, 리저브는 1,250,000원, 리워드는 4,280원이다.

1. **가입**: 체험용 이메일 → 화면에 보이는 코드 입력 → 비밀번호 → 휴대폰 인증(번호 칸 옆에 `인증 완료`) → 신분증·얼굴 확인 → 고객확인 질문 → 시작하기.
2. **카드 만들기**: 카드 탭 › `카드 만들기` → 본인확인 동의 → 멤버십에서 스탠다드와 `실물카드도 받기` → 배송지 입력(`아쿠아로` 검색 → 상세 주소 → `이 주소로 받기`) → 신청 확인에서 지금 낼 금액 `없음` 확인 → 확인 체크 → `신청하기`. 약 2초 뒤 카드가 나오고 잔액은 128,500원 그대로다.
3. **실물카드**: 카드 탭 아래 접힌 `체험 도구`에서 `배송 시작` → `배송 완료` → 카드 설정의 `받은 카드 쓰기 시작`. 비밀번호 1234는 거절되고 2580 같은 번호를 두 번 넣으면 활성화된다.
4. **멤버십**: 카드 › 멤버십 › 프리미엄 `바꾸기` → 시트에서 페이백 1.5%(한 달 200만원 결제까지), 리저브 +0.5%p(3,000만원까지), 연회비 100,000원을 확인하고 `100,000원 내고 바꾸기`. 잔액이 128,500원에서 28,500원이 되고, 홈의 리저브 행이 연 5.5%로 바뀌고, 다음 갱신일이 1년 뒤 같은 날로 잡힌다. 프라이빗 `바꾸기`는 잔액이 471,500원 모자라 버튼이 막히고 `충전하기`만 누를 수 있다. 스탠다드 `바꾸기` → `{갱신일}에 바꾸기`로 예약하고, 프리미엄 줄의 `계속 쓰기`로 취소한다. 3단계에서 실물카드를 받아 쓰는 중이었다면 시트에 메탈 카드를 새로 보낸다는 줄이 나온다. 카드 설정에 `새 메탈 카드 · 만드는 중`이 생기고, 체험 도구의 `새 카드 배송 시작` → `새 카드 배송 완료` → `새 카드 쓰기 시작`으로 바꾼다. 카드 번호와 비밀번호는 그대로이고 연회비 말고는 돈이 나가지 않는다.
5. **갱신**: 카드 탭 아래 `체험 도구` › `갱신일(날짜)로 이동`. 잔액 28,500원으로는 연회비 100,000원을 낼 수 없어 스탠다드로 바뀌고, 거래 내역에 `스탠다드로 변경`이 남는다. 체험 시간이 1년 흐른 만큼 리저브 보상도 리워드에 더해진다. 먼저 충전해 잔액을 100,000원 이상으로 만든 뒤 이동하면 연회비가 나가고 다음 갱신일이 1년 뒤로 밀린다.
6. **결제와 페이백**: 전체 › 결제 순서에서 `리워드 먼저 쓰기`를 끄고 홈의 `결제해 보기`로 한강커피 5,800원을 결제한다. 영수증에 새 페이백 58원(스탠다드 1%)이 보인다. 5단계에서 프리미엄을 유지했다면 87원(1.5%)이다. 다시 켜고 결제하면 리워드가 먼저 빠지고 그만큼 페이백이 줄어든다. 결제 방식(매장·온라인·해외)을 고를 수 있고, 전체 › 온라인·해외 결제에서 온라인을 끄면 온라인 결제만 거절된다. 전체 › 결제 한도에서 1회 한도를 10만원으로 낮추면 그보다 큰 결제가 거절된다.
7. **충전**: 홈 › `충전` → 국내 거래소 → USDC → Polygon → `주소 보기` → 주소와 보내는 순서 확인 → 보낸 수량 10 → `보낸 수량 확인` → 확인 체크 → `입금 체험하기` → `입금 확인 체험`. 처리 중에는 홈 잔액 아래에 `USDC 입금 · 네트워크 확인 중` 같은 줄이 보이고, 끝나면 14,000원이 수수료 없이 잔액에 더해진다. 코인 보유량이나 코인 화면은 생기지 않는다.
8. **Aqua 회원에게 보내기**: 홈 › `보내기` › `Aqua 회원에게` → `@minji.k`(김*지) 선택 → 10,000원 → 받는 사람·수수료 0원·보낸 뒤 잔액 확인 → `10,000원 보내기`. 잔액이 바로 줄고 거래 내역에 `김*지님에게 보냄`이 남는다. 태그 칸에 `minji`만 넣고 `@minji 찾기`를 누르면 회원을 찾지 못했다고 나온다. 같은 칸에 `010-0000-0101`이나 `minji.kim@aqua.example`을 넣고 찾으면 김*지가 나오고, `010-0000-0103`과 `junho@aqua.example`은 그 방법으로 찾기를 끈 회원이라 나오지 않는다. `QR 코드 찍기`에서 체험용 QR을 고르면 바로 금액 단계로 간다. 전체 › `내 태그와 QR`에서 QR을 보고 태그를 바꿔 본다(@junho는 이미 있는 태그라 막힌다). 같은 시트 아래 `받아 보기`의 `받기`를 누르면 시트가 닫히고 `김*지님이 10,000원을 보냈어요` 알림과 함께 잔액이 늘고, 거래 내역에 `김*지님이 보냄 +10,000원`이 남는다.
9. **지갑 주소로 보내기**: 홈 › `보내기` › `지갑 주소로` → USDC · Polygon → `다음` → 받는 사람, `예시 주소`, 10,000원 → `다음` → 전환 수수료 50원·네트워크 비용 140원·수수료를 뺀 금액 9,810원·보낸 뒤 잔액 확인 → 확인 체크 → 이메일 인증 코드 입력 → `10,000원 보내기`. 처리 중에는 잔액 아래 `보내는 중 10,000원`이 보인다. 원화 스테이블로 보내면 전환 수수료가 없다.
10. **리워드와 리저브**: 홈의 어두운 리워드 블록에서 소수점 숫자가 올라가는지 본다. 리저브 행을 눌러 `넣기`·`빼기`를 해 보고, 전체 › 체험 설정의 `1일 진행`으로 하루치 보상이 쌓이는지 확인한다.
11. **거래 내역**: 오른쪽 위 시계 아이콘 → 결제 행의 `상세`에서 승인번호·결제 방식·리워드/잔액/리저브 사용액·페이백을 보고 환불한다. 맨 아래 `연간 거래 내역`에서 그해 요약과 세금 신고 안내를 보고 `내역 복사`로 엑셀이나 구글 시트에 붙여 넣어 본다.
12. **계정**: 전체에서 비밀번호 변경, 알림(광고성 정보 동의·철회 날짜), 자주 묻는 질문, 약관, 회원 탈퇴(남은 할 일 목록)를 연다.
13. **분실·해지**: 카드 설정의 `분실·도난 신고`로 끝번호가 바뀌고 휴대폰 결제 등록이 지워지는지, 실물카드는 비용 없이 다시 배송되는지 본다. `카드 해지` 뒤에도 잔액·리저브·리워드는 남고, 이미 낸 연회비는 돌려받지 않는다.
14. **복원**: 입금 대기 중 새로고침해도 홈의 입출금 줄이나 거래 내역의 `처리 내역`에서 같은 요청을 다시 열어 마칠 수 있다.

## 실제 휴대폰에서 확인할 것

아이폰은 Safari, Android는 Chrome에서 [공개 웹 데모](https://sohw400.github.io/aquacard/)를 연다. 실제 자금이나 본인확인 자료를 입력하지 않고 샘플 상태로 체험한다. 공개 배포와 HTTPS 파일 응답은 확인했으며, 아래 실기기 검증은 별도로 수행한다.

실기기에서는 다음을 확인한다.

- 노치·홈 인디케이터와 하단 메뉴·버튼이 겹치지 않는지.
- 키보드가 열린 시트의 입력·확인 버튼을 사용할 수 있는지.
- 입력 시 의도하지 않은 화면 확대, 선택창·스크롤 문제 여부.
- 회전·브라우저 주소창 변화·백그라운드 복귀 후 화면과 적립 표시.
- 새로고침·탭 재실행·저장소 제한 상황의 데모 상태 복원.

실제 Safari/WebKit·Android 실기기 검증은 아직 수행하지 않았다. 네이티브 앱 단계에서는 공유 가능한 도메인 로직을 활용하고 모바일 UI·저장·기기 기능을 따로 구현한 뒤, iOS/Android 빌드와 실기기 검증을 추가한다.
