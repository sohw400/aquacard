# 리저브 원금과 카드 리워드

서버 연결판의 리저브는 회원이 지갑에서 옮겨 둔 `TEST_KRW` 원금이다. 지갑과 리저브 사이의 이동은 한 거래에서 양쪽 계정에 함께 기록된다. 이동과 결제에는 거래가 허용된 계정이 필요하다. 같은 요청 번호로 같은 작업을 재전송하면 처음 결과를 돌려준다.

## 카드 결제와 환불

승인 시 리워드 사용 설정이 켜져 있으면 카드 전용 리워드를 먼저 확보한다. 다음으로 지갑 원금을 확보하고, 리저브 사용 설정이 켜진 경우에만 부족한 원금을 리저브에서 가져온다. 어느 한 재원이라도 부족해 총액을 확보하지 못하면 승인 전체를 되돌린다. 리저브 사용 설정은 기본 꺼짐이고 설정 버전이 맞아야 바뀐다.

리워드, 지갑 원금, 리저브 원금의 구성은 승인 시점에 기록된다. 이후 설정을 바꿔도 이미 확보한 재원의 구성이 유지된다. 부분 매입액은 누계 기준으로 배분해 여러 번 처리해도 원 단위 반올림이 누적되지 않는다. 매입되지 않은 원금은 승인 해제 시 원래 지갑이나 리저브로 돌아간다. 매입 확정 후 환불된 지갑·리저브 원금은 지갑에 들어오며 리워드 몫은 카드 리워드로 처리한다. 응답의 `funding.principal`에는 두 원금이 함께 들어가고 `funding.reserve`는 그중 리저브 몫이다.

## 합성 보상 운영

보상률 기본값은 0이다. 실제 이자와 자산 운용 수익을 연결하지 않았으며, 아래 금액은 회사가 적립한 테스트 재원으로 지급하는 카드 전용 리워드다. 원금과 별도로 관리한다.

운영자는 로컬 샌드박스에서 테스트 예산과 리워드 프로그램을 준비한다. `reserve-rate`는 연간 기준점, 예상 정책 버전, 고유 작업 번호를 받는다. 예제는 버전 0에서 500bp(연 5% 모의 환산)를 적용한다. 지급을 중단할 때는 현재 버전과 새 요청 번호로 0bp를 설정한다.

```sh
npm run server:rewards -- budget 1000000 reserve-company-budget-01
npm run server:rewards -- program on reserve-program-01
npm run server:rewards -- reserve-rate 500 0 reserve-rate-01
npm run server:reserve:accrue -- --limit 100
```

변경한 요율은 DB에 기록된 시점부터 적용된다. 회원이 리저브에 실제 보관한 원금과 기간에 대해 365일을 한 해로 계산하며, 원 미만 금액은 다음 지급에 이월한다. 입출금·카드 승인의 원금 이동이 발생할 때마다 이전 금액의 누계부터 보존한다. 뒤늦게 수신한 카드 이벤트의 거래일은 이미 계산한 기간을 바꾸지 않는다. 보상이 대기 중이어도 원금은 꺼낼 수 있다.

작업 스케줄러에서 제한된 `WORKER_DATABASE_URL`로 `node dist-server/reserve-accrual-worker.js --limit 100`을 반복 실행한다. 이 명령은 한 번에 최대 지정한 수의 계정을 처리한다. 지급할 것이 없으면 `idle`에서 종료한다. 지급 시 계좌별 누계와 회사 재원 이동을 한 거래로 확정해 중복 실행과 작업자 재시작을 처리한다. 과거 환불에서 회수할 페이백이 있으면 지급액에서 먼저 상계한다. 회원 화면에서 지급된 기록은 ‘리저브 보상 지급’으로 표시된다.

예산 부족이나 리워드 프로그램 비활성 상태에서는 지급 대상액을 보존하고 `deferred`와 사유를 반환한다. 종료값 2가 나오면 예산·리워드 상태를 확인한다. 해당 계정은 1분 뒤부터 다시 처리할 수 있다. 지급 작업 오류는 종료값 1, 정상 종료는 0이다. `--once`는 대상 계정 한 개를 점검한다. 연간 환산율이 양수이거나 미지급 보상이 1원 이상이면 회원의 리저브 조회 결과에 `accrual`이 포함된다. `pendingWon`은 지급 전 원화 환산 금액의 십진 문자열이다.

실물 자산 발행·보관, 지급 주체·재원의 계약, 국내 보유 기반 보상 허용 범위와 운영 스케줄러에 대한 실제 검증은 제휴 및 스테이징 인수 단계에 속한다.
