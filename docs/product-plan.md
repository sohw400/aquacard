# Aqua Card 제품 기획 v0.5 · PoC

작성일: 2026-10-13 · 상태: 사업 모델·기능 구조와 PoC 정책

> v0.6 제안: KAST 구조를 한국에 옮길 때 그대로 가져올 것과 바꿀 것, Reserve 보상의 법적 위험과 대안은 [기획 v0.6 제안](kast-alignment.md)에 정리했다. 엔진과 정책 값에는 아직 반영하지 않았다.

PoC 기본 정책은 [경쟁 비교·파라미터](benchmark-and-parameters.md)와 [policy.ts](../src/lib/policy.ts)에 정했다. Basic 무료·Reserve 연환산 단리 5%·페이백 1%·월 페이백 상한 1만원을 적용한다. Plus는 월 4,900원 안내·페이백 1.5%·월 3만원 상한이다. 회비·발급비는 실제 청구하지 않는다. 실제 서비스 조건은 파트너와 별도로 확정한다.

## 1. 이번 기획의 방향

Aqua Card는 **KAST의 사업 모델을 참고해 한국에 적용하는 가상자산 지갑·카드·Reserve·리워드 서비스**다.

사용자가 지정한 방향은 다음과 같다.

- 한국 사용자를 대상으로 한다. 브랜드는 가칭 **Aqua Card**다.
- 원화 스테이블코인뿐 아니라 지원 일반 코인과 다른 스테이블코인도 받는다.
- 보유 자산을 카드 결제에 사용할 수 있는 잔액으로 연결한다.
- Reserve 원자산도 카드 결제에 사용할 수 있도록 설계한다. 결제 잔액이 부족하면 사용자가 켠 설정에 따라 즉시 사용 가능한 Reserve 자금으로 보충한다.
- 적격 카드 사용에 따라 **페이백**을 제공한다. PoC는 Aqua Rewards 적립으로 Basic 1%·월 1만원, Plus 1.5%·월 3만원을 적용한다.
- 별도의 **Reserve** 영역에서 자체 리워드를 제공한다.
- 리워드는 사용자가 설명한 KAST의 ‘변동 보상률·실시간 적립·자유 인출·달러 표시 결제 전용 보상’을 참고한다. Aqua Card에서는 원화 표시 결제 전용 리워드와 락업 없는 Reserve를 기본안으로 설계한다. 재원·지급률·세부 운영 조건은 미정이다.
- 원화 스테이블코인 발행사와 제휴하는 카드·지갑 앱 사업을 먼저 추진한다.
- 제도와 파트너 준비 속도에 맞춰 실제 서비스 범위를 확정한다.

v0.1에서 두었던 원화 스테이블 전용·리워드 후순위 가정을 변경했다. **다중 자산 수용과 Reserve·리워드는 제품의 핵심 범위**다.

KAST의 최신 지원 자산·Reserve 조건·리워드·요금·수익 구조를 공식 자료로 확인한 문서는 아니다. 공식 사이트 읽기는 네트워크 접근 제한으로 실패했다. 사용자는 약 8%로 보이는 변동 보상률, 충전 후 실시간 적립, 인출 제한 없음, 달러 표시·결제 전용 적립을 설명했다. 연환산 여부·APR/APY·재원·예외 조건은 확인되지 않았다. KAST 또는 제3자가 자산을 운용해 수익 일부를 분배한다는 설명은 사용자의 추정이다. 아래 내용은 이를 참고한 Aqua Card의 기획안이다. KAST를 코드 수준에서 포크할 수 있다고 전제하지 않는다.

## 2. 제품 정의와 핵심 구조

> 코인을 받고, 쓸 돈과 보유할 돈을 나누고, Reserve 리워드를 관리하며, 카드로 일상 결제하는 한국형 금융 앱.

제품은 세 영역으로 나눈다.

| 영역 | 역할 | 먼저 보여줄 정보 |
| --- | --- | --- |
| 자산 지갑 | 지원 코인·스테이블코인의 입금, 보유, 출금 | 자산별 수량, 원화 평가액, 입출금 상태 |
| 결제 지갑·카드 | 결제 잔액과 사용자가 허용한 Reserve 자금으로 카드 결제 | 결제 가능액, Reserve 사용 설정·범위, 승인 보류액 |
| Reserve·리워드 | 선택한 자산을 별도로 보유하고 보상을 적립하며 필요 시 결제에 사용 | Reserve 자산·결제 가능 범위, 보유 보상·페이백 내역 |

자체 리워드는 별도 기록으로 관리한다. 리워드가 결제에 사용 가능한지, 출금 가능한지, 포인트인지 토큰인지에 따라 자산으로 표시하는 방식이 달라진다.

**총자산 평가액, 카드 결제 가능액, Reserve 금액, 리워드는 같은 금액이 아니다.** 홈에서 지금 결제할 수 있는 금액을 명확히 구분한다.

사용자 반복 흐름은 다음을 목표로 한다.

**지원 자산 입금 → 일부는 결제 잔액으로 전환 → 일부는 Reserve에 보유 → 리워드 확인·사용 → 반복 결제·재입금**

Reserve 자동 사용을 켜면 수동으로 이동하지 않고 카드에 연결 가능한 Reserve 자금에서 결제 잔액 부족분을 보충한다. 총자산 평가액 전체를 결제 가능액으로 취급하지 않는다.

리워드 사용 경로의 우선 검토안은 카드 결제 전용이다. 현금 출금·외부 전송·자산 교환 권한을 기본으로 부여하지 않는다. 구체 조건과 사용 가능 거래는 확정할 항목이다.

## 3. 초기 고객과 가치 가설

첫 고객 후보는 **가상자산을 이미 보유하며 그 일부를 소비에 연결하려는 한국 거주 성인**이다.

| 고객 후보 | 확인할 문제 | 검증할 가치 |
| --- | --- | --- |
| 코인·스테이블코인 보유자 | 소비할 때 처분·출금·재충전 단계를 반복하는가? | 자산 입금부터 결제까지의 과정이 실제로 단순해지는가? |
| 보유와 소비를 함께 관리하려는 이용자 | 쓸 돈과 유지할 자산을 나눠 보기 어려운가? | 결제 지갑과 Reserve를 나누는 것이 관리에 도움이 되는가? |
| 제휴 서비스에서 디지털 자산을 받는 이용자 | 받은 자산을 실제 소비에 연결하기 번거로운가? | 받은 잔액을 앱 안에서 관리하고 사용할 이유가 있는가? |

리워드가 사용 동기를 만드는지와 함께 조건·비용·인출 제한을 이해하는지도 확인한다. 기존 국내 체크카드·간편결제의 편의성과 혜택은 비교 기준이다.

한국 대상이라는 이유로 해외 결제를 제외하지 않는다. 국내·해외 사용 범위와 비용은 실제 카드 파트너 조건에 따라 정한다.

## 4. 사업 모델

Aqua Card가 맡을 중심 역할은 고객 경험, 지갑·카드·Reserve 화면, 거래 상태 관리, 리워드 정책, 고객 지원이다. 자산 보관·전환·발행·상환·카드 발급·정산의 제공 주체와 책임은 파트너 구조에 따라 정한다.

| 수익 후보 | 사업상 확인할 조건 |
| --- | --- |
| 카드 사용 수익 | 발급·결제 파트너와 계약상 배분, 국내·해외 결제별 실제 당사 몫 |
| 자산 전환 수익 | 명시한 수수료·스프레드, 체결 비용, 유동성, 국내 제공 가능 범위 |
| 멤버십·유료 부가 서비스 | 사용자가 비용을 낼 구체적 혜택, 제공 비용, 해지·환불 조건 |
| 제휴 수익 | 카드·지갑 이용과 연결되는 제휴, 재원 부담과 고객 데이터 사용 범위 |
| Reserve 관련 제휴 수익 | 실제 상품·계약에 따른 수익과 고객 보상 재원 |

이 항목은 수익 후보이며 KAST의 실제 수익 구조를 확인한 결과가 아니다. 고객 자산을 보유하면 운용 수익이 자동 발생하거나 Aqua Card에 귀속된다고 가정하지 않는다.

> 거래·고객 단위 수익 = 당사 귀속 수익 − 보관·전환·유동성·네트워크·카드 운영 비용 − 본인 확인·고객 지원·손실 비용 − 리워드·혜택 비용

일반 결제대금은 사용자가 입금한 자금에서 차감한다. 사용자 경험은 선충전한 잔액으로 결제하는 방식이며 실제 카드의 법적·발급 상품 유형은 파트너와 정한다. 사용자 자금으로 결제하는 부분과 Reserve 보상·페이백 사용분의 비용은 구분한다.

Reserve 자산을 운용하지 않고 결제에 필요한 형태로 확보하면 운용 자산 회수 문제는 없다. 운용하는 구조에서는 고객 잔액이 있어도 카드 승인·정산에 필요한 시점에 해당 자금이 사용 가능해야 한다. 코인 입금 자산을 카드 파트너가 요구하는 정산 자금으로 연결하는 조건도 확인한다.

리워드에 필요한 비용을 먼저 추정하고 지속 가능한 정책을 설계한다. 자체 토큰 발행으로 비용 문제가 해결된다고 가정하지 않는다.

## 5. 자산 입금부터 카드 결제까지

### 지원 자산

- 원화 스테이블코인: 발행·상환 파트너 확정 후 연동할 핵심 후보.
- 기타 스테이블코인: PoC는 USDT·USDC 모의 입출금·전환을 지원한다. 실제 지원 여부는 미정.
- 일반 코인: PoC는 BTC·ETH 모의 입출금·전환을 지원한다. 실제 지원 여부는 미정.

자산명과 함께 지원 네트워크, 입출금 방식, 최소 금액, 비용, 처리 시간을 확정해야 한다. 지원 자산·네트워크를 무제한으로 늘리지는 않는다.

### 기본 결제 경로

**입금 → 확인 완료 → 전환 견적 확인·동의 → 파트너를 통한 전환 → 결제 잔액 반영 → 카드 사용**

전환 화면에는 내보낼 자산 수량, 받을 결제금액, 가격·비용, 견적 유효시간을 표시한다. 원화 평가액은 결제 가능 금액과 구분한다.

원화 스테이블을 결제 잔액으로 사용하는 경우에도 카드 파트너의 정산 자금과 연결하는 과정이 필요할 수 있다. 가맹점이 해당 코인을 직접 받는 구조라고 가정하지 않는다.

### 확장 경로

Reserve에서 즉시 결제에 연결 가능한 자금의 자동 보충은 핵심 범위에 포함한다. 지원 일반 코인을 카드 승인 시점에 새로 매도·전환하는 방식은 별도 확장안이다. 승인 시간, 가격 변동, 유동성, 전환 실패, 전환 후 카드 승인 실패에 대한 복구 구조를 검증한 뒤 제공한다.

### 취소·환불

기본안은 카드 환불을 결제 잔액으로 반영하는 것이다. 환불 시 원래 입금한 코인을 동일 수량으로 돌려준다고 약속하지 않는다. 실제 환불 자산과 처리 방식은 파트너 조건에 맞춰 확정한다.

## 6. Reserve와 자체 리워드

Reserve는 사용자가 자산을 따로 보유하고 리워드 조건을 관리하는 서비스 영역이다. 스테이블코인 발행사의 준비금 계정과는 역할이 다르다.

**Reserve 자산과 리워드는 각각 기록하고 표시한다.** Reserve 자동 사용 설정과 즉시 처리 가능 조건을 충족한 금액만 카드 결제 재원으로 사용할 수 있다. 사용자가 끈 상태에서는 해당 금액을 일반 결제 가능액에 포함하지 않는다.

### 사용자 설명을 참고한 우선 검토안

**Reserve 보유 잔액·시간에 따라 실시간으로 적립되는 원화 표시 결제 전용 리워드**를 기본안으로 설계한다. 이는 사용자가 설명한 KAST 경험을 한국에 적용하려는 제품안이며, 실제 금융 상품의 확정 조건이나 KAST 공식 약관 요약은 아니다. 상세 정책은 [Reserve·리워드 정책 초안](reserve-rewards.md)에 정리한다.

- Reserve에 배정한 자산과 고객별 원자산 잔액을 기록한다. 실제 보관·운용 구조는 파트너와 확정하며, 원자산과 적립 보상은 분리한다.
- 충전 완료 후 보상 산정을 시작하고, 추가 충전·인출·보상률 변경 시점별로 적립을 계산한다.
- 보상률은 변동 가능하게 설계한다. 변경 이후 구간에 새 보상률을 적용하고 변경 이력을 보여준다.
- Reserve 원자산에는 별도 락업·중도 인출 패널티를 두지 않는 기본안을 잡는다. 자유로운 인출 요청과 실제 처리 시간·외부 출금 조건은 구분한다.
- 보상은 원화 상당의 결제 혜택으로 표시한다. 원화 현금이나 원화 스테이블코인 잔액으로 표시하지 않는다.
- 내부 가칭은 **Aqua Rewards**다. 포인트형 사용자 경험으로 설계하되 법적·회계적 성격을 이름만으로 확정하지 않는다.
- 결제 전용 리워드는 현금 인출 가능 금액과 구분한다.
- 표시 보상률과 실제 산정 기준·지급 주기·상한·유효기간을 함께 정한다. APR/APY와 복리 여부는 실제 산식에 맞춰 표기한다.
- 보유 보상 재원과 고객 자산 운용 여부는 별도로 확인한다. 결제에만 쓸 수 있다는 조건만으로 운용 수익 배분 여부가 결정되지 않는다.

예를 들어 보상 기준 잔액이 1,000달러이고 단순 연 8%로 1년을 계산하면 보상은 80달러 상당이다. 이 산식은 설명용 예시이며 실제 KAST 조건이 아니다. 결제 전용이면 이 금액을 현금으로 인출할 수 있다는 뜻도 아니다. Aqua Card에 8%를 적용하기로 정한 상태도 아니다.

### 리워드를 쓰는 카드 결제

기본 검토안은 **사용 가능한 리워드 → 결제 잔액 → 사용자가 허용한 Reserve 부족분 보충** 순서다. 사용자는 카드 자금 설정에서 Reserve 자동 사용을 켜고 대상 자산·전환 조건·한도를 확인한다. 적격 재원이 부족하면 승인하지 않는다.

- 예: 10,000원 결제에 리워드 3,000원 상당과 결제 잔액 7,000원을 사용한다.
- 실제 카드 승인·가맹점 정산에는 10,000원을 지급할 자금이 필요하다. 리워드 적용분의 부담 주체와 정산 자금을 확정한다.
- 리워드 사용 가능 거래, 적용 순서, 한도, 승인 시 두 잔액의 보류를 정한다.
- 취소·환불은 사용자 자금과 리워드의 사용 구성을 보존해 복원하는 기본안을 검토한다. 확정 거래의 사용자 자금 환불은 결제 잔액, 리워드 환불은 리워드 기록에 반영한다. 부분 환불 배분과 만료 리워드 복원도 정의한다.
- 리워드가 환불을 통해 현금성 잔액으로 바뀌지 않도록 기록과 복원 규칙을 일치시킨다.

Reserve에서 결제용으로 보류·이동한 금액은 보상 산정에서 제외하고, 남은 적격 잔액에는 계속 적립한다. 취소로 실제 Reserve에 복원된 금액은 적립을 재개한다. 보류 기간의 보상 정산 규칙은 별도로 정한다.

동일 자산의 내부 보류를 해제하는 경우와 이미 코인 전환을 체결한 경우를 구분한다. 전환이 체결됐다면 같은 코인 수량으로 복원한다고 약속하지 않는다. 확정 거래 환불의 사용자 자금 부분은 결제 잔액으로 반영하고, 다시 Reserve로 이동하는 경로를 제공한다.

### 결제 페이백

페이백은 적격 카드 결제에 따른 보상이다. Reserve 보유 보상과 별도로 산정·기록하며, 사용 가능한 혜택은 Aqua Rewards에서 함께 보여주는 기본안이다.

- 승인 시 예상 페이백을 보여주고 거래 확정 후 조건 확인을 거쳐 사용 가능으로 반영한다.
- 초기 산정 기준은 수수료와 리워드 사용분을 제외한 적격 사용자 자금 결제액이다. Reserve에서 결제한 사용자 자금도 같은 기준으로 인정한다.
- PoC는 Basic 1%·월 1만원, Plus 1.5%·월 3만원이며 모의 거래 확정 후 적립한다. 실제 지급률·제외 거래·캠페인·운영 확정 시점은 별도로 정한다.
- 취소·부분 환불 시 해당 적격 금액에 대한 페이백을 취소·조정한다.
- 이미 사용한 페이백의 회수는 향후 혜택 상계 등의 사전 정책으로 정한다. 고객 원자산에서 임의 차감하는 기본안은 두지 않는다.
- 페이백 사용분의 재원은 Aqua Card·제휴사 예산 또는 실제 계약 수익과 연결한다.

설명용으로 1% 페이백을 가정하면, Reserve 사용자 자금 10,000원으로 확정 결제할 때 100원 상당을 적립한다. 결제대금 10,000원은 사용자 자금에서 나가고 보상 100원 상당의 비용은 별도로 부담한다. 1%는 실제 지급 조건이 아니다.

### 아직 정할 리워드 구조

| 결정 항목 | 필요한 정의 |
| --- | --- |
| 제공 자산 | 어떤 자산을 Reserve로 옮길 수 있는가? |
| 산정 기준 | 보유 잔액·시간 기반을 기본으로 하되 자산 수량과 원화 평가액 중 어떤 단위를 쓰는가? |
| 형태 | 원화 표시 결제 전용 보상의 권리·약관·회계 구조는 무엇인가? |
| 지급 조건 | 실시간 적립 표시와 실제 결제 가능 시점, 상한·제외 조건은 무엇인가? |
| 사용 경로 | 카드 결제 적용 순서·거래 범위·사용 한도·환불 복원은 어떻게 정하는가? |
| 인출 조건 | 락업 없는 인출을 위한 유동성·처리 시간, 인출 진행 중 적립 종료 시점은 무엇인가? |
| 재원 | Aqua Card 예산, 실제 계약 수익, 제휴 예산, 별도 상품 수익 중 무엇인가? |
| 변경·회수 | 정책 변경 적용 시점과 취소·부정 사용으로 회수되는 조건은 무엇인가? |

사용자 경험은 보유 보상형으로 설계한다. 재원은 Aqua Card·제휴사 예산과 실제 운용·계약 수익을 구분해 검토한다. 고객 자산을 운용하는 구조를 택하면 운용 주체·손실·회수·인출 대응을 별도로 확정한다. 포인트형 지급과 자산 운용 여부는 서로 다른 결정이다.

현재 기본안은 변동 보상률·실시간 적립·락업 없는 원자산 인출·원화 표시 결제 전용 리워드다. PoC는 원화 기준 데모 Reserve에 연환산 단리 5%, 보상 대상 잔액 상한 1천만원을 적용한다. 실제 운용 수익 배분 여부, 재원, 지급률과 권리는 확정하지 않았다. 프로토타입의 적립·사용 가능 리워드는 가상 금액이다.

자체 리워드의 발행과 원화 스테이블코인 발행은 서로 다른 사업 결정이다. 원화 스테이블은 발행사 제휴 모델을 유지한다.

## 7. MVP 기능

일반 코인 수용과 Reserve·리워드는 첫 프로토타입에 포함한다. 실제 자금 서비스는 확인한 자산·네트워크·제휴 조건에 맞춰 연다.

| 기능 | 첫 기획·프로토타입 범위 |
| --- | --- |
| 가입·본인 확인 | 한국 거주자 지원 조건, 심사·보완·발급 상태 |
| 자산 지갑 | 지원 자산 목록, 자산별 수량·원화 평가액, 입출금 |
| 자산 전환 | 견적·비용·유효시간, 동의, 진행·완료·실패 |
| 결제 지갑 | 카드 결제 가능액, 보류액, 충전·환급 |
| 카드 | 발급·정보 보호·잠금·한도, 결제·취소·환불 |
| Reserve | 이동·보유·락업 없는 인출, 실시간 적립·변동 보상률, 카드 자동 사용 설정·보류·복원 |
| 자체 리워드 | 예상·확정·지급·사용 기록, 결제 전용 표시, 혼합 결제·환불 복원, 산정·사용 조건 |
| 결제 페이백 | 예상·확정·사용 가능·환불 조정, Reserve 보상과 적립 출처 구분 |
| 거래 내역 | 입출금·전환·결제·Reserve·리워드 상세와 문의 |
| 고객 지원·보안 | 문제 거래 문의, 추가 인증, 알림·접근 보호 |

멤버십·회원 등급은 수익 후보와 화면 탐색에 포함하되 요금·혜택은 확정하지 않는다. 신용·대출, 전문 거래 기능, 일반 코인 스테이킹, 다수 체인 지원은 별도 확장 판단으로 남긴다. Reserve 자체 리워드를 일반 코인의 스테이킹과 동일하게 취급하지 않는다.

가상 카드로 화면을 검증하되 실제 국내 사용에 필요한 카드 형태는 파트너 확인 후 정한다. 국내 간편결제 등록, 실물 카드, NFC와 해외 이용은 제공 가능 범위를 별도로 확인한다.

## 8. 핵심 사용자 흐름

### 첫 카드 사용

지원 조건 확인 → 샘플 본인 확인·필수 동의 → 카드 등급·실물 여부 선택 → 신청 내용 확인 → 대행사 모의 심사 → 가상 카드 발급 → 활성화 → 카드 결제

심사 보완·거절·재신청, 실물 배송·수령·활성화와 잠금은 [카드 신청·발급 흐름](card-issuance-flow.md)에 정리한다. 샘플 본인 확인은 실제 개인정보 확인이나 대행사 요청을 수행하지 않는다. 지갑은 지원 자산·네트워크 확인 → 모의 입금 → 전환 견적 확인 → 결제 잔액 반영 경로를 제공한다.

카드 이용 가능 여부를 확인하기 전에 결제용 입금을 요구하지 않는다. 자산 입금 가능 상태와 카드 사용 가능 상태가 다르면 명확히 안내한다.

### Reserve 이용

지원 자산·조건 확인 → 자산 지갑에서 Reserve 이동 → 보유·리워드 상태 확인 → 리워드 확정·지급 → 리워드 사용 또는 Reserve 원자산 결제·인출

이동 전 인출 조건과 중도 인출 영향을 보여준다. Reserve 원자산, 리워드, 사용할 수 있는 금액을 따로 표시한다.

### Reserve 자금으로 결제

Reserve 자동 사용 설정·대상 자산 확인 → 카드 결제 요청 → 리워드·결제 잔액 적용 → 부족분의 적격 Reserve 자금 보류·이동 → 승인 → 거래 확정

카드 거래 상세에는 리워드·결제 잔액·Reserve 각각의 사용액과 페이백을 표시한다. 결제 잔액에서 이미 차감한 금액을 Reserve에서 중복 차감하지 않는다.

### 결제 페이백

카드 승인 → 예상 페이백 표시 → 거래 확정·적격 조건 확인 → Aqua Rewards 사용 가능으로 반영 → 다음 카드 결제에 사용

원거래 취소·부분 환불이 발생하면 해당 페이백을 조정하고 내역을 연결한다.

### 취소·환불

문제 거래 선택 → 승인 해제 또는 환불 상태 확인 → 사용한 결제 잔액·리워드의 복원 확인 → 관련 결제 보상 조정 확인 → 완료

승인 취소와 확정 거래 환불을 구분한다. 결제 리워드 회수 정책을 택하는 경우 환불과 연결해 안내한다.

### 외부 출금·원화 환급

자산·경로 선택 → 주소·계좌와 비용 확인 → 예상 수령액·시간 확인 → 추가 인증 → 처리 상태 → 완료 또는 확인 필요

외부 지갑 출금, 원화 계좌 환급, Reserve 인출은 서로 다른 기능이다. 지원되는 경로만 노출한다.

## 9. 화면 구조

PoC의 주 메뉴는 **홈 / 자산 / 혜택 / 전체**다. 카드 관리, 리저브, 이용 내역은 상세 화면으로 연다. 화면별 구성과 시각 원칙은 [화면 설계](ux-remake.md)에 정리했다.

| 화면 | 핵심 내용 |
| --- | --- |
| 홈 | 카드, 결제 가능 금액과 구성, 충전·결제, 이번 달 페이백과 리워드, 최근 이용 |
| 자산 | 총 보유 자산과 구성, 원화 잔액 입출금, 보유 코인 전환·출금, 입출금 진행 상황 |
| 혜택 | 리워드 잔액과 우선 사용, 이번 달 페이백과 한도, 리저브 보상 받기, 리워드 내역 |
| 전체 | 카드 관리, 이용 내역, 결제 설정과 한도, 요금, 체험 설정 |

리워드는 홈과 혜택에서 바로 확인할 수 있게 한다. 거래 상세는 원래 자산 수량, 전환 금액, 비용, 처리 시간을 추적할 수 있어야 한다.

홈은 자산 평가액보다 결제 가능액을 명확히 보여준다. 충전·전환·Reserve 이동처럼 돈의 용도가 달라지는 행동에서는 사용자가 바뀌는 금액과 제한을 이해하도록 안내한다.

## 10. 금액과 거래 상태

### 금액 구분

- **자산 수량:** 자산별 실제 보유 수량.
- **원화 평가액:** 해당 시점의 가격으로 계산한 참고 금액.
- **결제 가능액:** 현재 설정과 처리 조건에서 카드 결제에 실제 사용할 수 있는 금액. 결제 잔액과 사용 허용된 적격 Reserve 금액의 구성을 표시하고, 결제 전용 리워드는 별도로 안내한다.
- **승인 보류액:** 진행 중인 카드 거래로 사용이 제한된 금액.
- **Reserve 잔액·인출 가능액:** 별도 보유 금액과 현재 이동 가능한 금액.
- **리워드:** Reserve 보유 보상과 결제 페이백을 구분한 예상·확정·지급·사용·만료·회수 기록.

가격이 변하는 일반 코인의 평가액을 확정 원화 금액처럼 표시하지 않는다. 원화 스테이블도 상환·비용·운영 조건을 확인해 결제금액과 연결한다.

### 상태와 실패 처리

| 유형 | 반드시 다룰 상태 |
| --- | --- |
| 입출금 | 확인 대기, 완료, 실패, 지원하지 않는 자산·네트워크 |
| 전환 | 견적 만료, 진행, 체결 완료, 실패, 체결 후 잔액 반영 지연 |
| 카드 | 신청·심사·발급, 잠금 요청·적용, 결제 승인·확정·실패 |
| 취소·환불 | 승인 해제, 환불 대기·처리·반영, 확인 필요 |
| Reserve | 이동 요청·완료, 인출 가능·제한·대기·완료, 카드 결제 보류·이동·복원 |
| 리워드 | 예상, 확정, 지급 대기·완료, 사용·승인 보류·환불 복원, 해당 시 만료·회수 |
| 페이백 | 승인 시 예상, 거래 확정 후 적격 확인·지급, 취소·부분 환불 조정, 사용 후 상계 |

기준 거래 기록과 파트너 기록을 대조한다. 반복 요청·중복 알림으로 잔액이나 리워드가 두 번 바뀌지 않아야 한다. 체결 완료 후 결제 지갑 반영에 실패한 경우처럼 부분 완료도 추적한다.

## 11. 한국 적용과 파트너 구조

한국 적용은 한국어·원화 표시뿐 아니라 한국 거주자의 가입, 자산 입출금, 전환, 보관, 카드 이용, Reserve·리워드의 실제 제공 가능 범위를 포함한다.

| 영역 | 확정할 내용 |
| --- | --- |
| 발행·상환 | 원화 스테이블 발행사, 상환 조건, 고객 대상 설명 주체 |
| 지갑·전환 | 보관·입출금·전환 제공 주체, 지원 자산·네트워크, 고객 자산 관리 |
| 카드·정산 | 한국 거주자 발급, 국내·해외 가맹점 이용, 정산 자금·비용·한도 |
| Reserve·리워드 | 보유·운용 여부, 인출 조건, 지급 형태·재원·책임 |
| 운영 | 본인 확인·거래 확인, 보안, 장애·분쟁·부정 사용 대응과 고객 지원 |

한국에서 각 역할을 수행할 수 있는 주체와 제휴 범위를 검토한 뒤 자금 경로를 확정한다. 이 문서는 해당 구조에 대한 법률 검토 결과가 아니다.

개념적인 연결 구조는 다음과 같다. 화살표는 서비스 연결이며 실제 자금 이동 순서나 보관 책임을 뜻하지 않는다.

~~~mermaid
flowchart LR
    U[한국 사용자] --> A[Aqua Card 앱]
    A --> W[자산 지갑·보관 파트너]
    W --> X[자산 전환 파트너]
    X --> P[결제 잔액·카드 파트너]
    P --> M[지원 가맹점]
    A --> R[Reserve·자체 리워드 관리]
    P --- K[원화 스테이블 발행·상환사]
~~~

원화 스테이블 파트너 준비 전에도 일반 코인·기타 스테이블 기반 기능의 준비와 출시 가능성 검토는 진행할 수 있다. 실제 선출시는 해당 기능의 국내 운영 가능성과 파트너 조건을 확인한 뒤 결정한다.

## 12. 개발·출시 단계

### 단계 A — 전체 경험 프로토타입

일반 코인·스테이블 입금, 전환, 결제, Reserve 이동·인출·자동 결제 사용, 보유 리워드와 페이백을 가상 잔액으로 구현한다. 실제 자금 수령·카드 발급 없이 데모임을 표시하고 고객 테스트를 진행한다.

### 단계 B — 파트너 샌드박스

지원 자산 입출금·전환, 카드 승인·정산·환불, Reserve 자동 사용·보상 산정, 페이백 적립·회수를 테스트한다. 잔액 대조와 중복·지연·순서 변경·부분 실패 복구를 확인한다.

### 단계 C — 확인한 범위로 실제 출시

자금·보관·전환·발급·정산·리워드 책임과 비용을 확정하고, 검증한 자산·네트워크·카드·Reserve 조건으로 제한된 출시를 준비한다.

### 단계 D — 확장

원화 스테이블 발행사 연동, 지원 자산 확대, 일반 코인의 승인 시점 자동 매도·전환, 실물 카드·간편결제, 멤버십 등을 실제 수요와 제휴 조건에 따라 확장한다. 원화 스테이블 파트너가 먼저 준비되면 초기 출시부터 포함할 수 있다.

화면 개발 일정, 각 금융 기능의 준비 일정, 실제 출시 일정은 따로 산정한다. Reserve·리워드는 처음부터 설계하고, 실제 제공 시점은 해당 구조의 준비 상태에 맞춘다.
