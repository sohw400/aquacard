# Aqua Card 기획서

작성일: 2026-10-14 · 버전 1.0 · 상태: 웹 체험판(PoC)까지 만들었다. 실제 출시는 법률 의견, 금융정보분석원(FIU) 신고, 제휴 계약이 끝나야 할 수 있다.

> 코인을 보내면 바로 원화 스테이블 잔액이 되고, 그 잔액으로 카드 결제와 회원 송금을 하고, 리저브에 둔 돈과 카드 결제로 리워드를 받는 한국용 카드 앱이다. KAST의 구조를 옮기고 요금과 요율은 한국 카드 시장에 맞췄다.

## 1. 요약

- **만든 것:** 가입부터 탈퇴까지 모든 흐름이 도는 [웹 체험판](https://sohw400.github.io/aquacard/)이다. 돈, 카드, 본인확인은 브라우저 안의 모의 처리다. 로직 테스트 121개, 브라우저 검사 57개, 기기 프로필 5개가 통과한다([테스트 안내](testing.md)).
- **제품 구조:** 잔액 하나(원화 스테이블), 카드(세 멤버십), 리저브와 리워드 세 영역이다. 받은 코인은 들고 있지 않고 원화 입출금도 없다(2장).
- **출시를 막는 것:** 네 가지다(8장).
  1. 원화 스테이블을 발행할 근거 법(디지털자산기본법)이 아직 없다.
  2. Aqua는 가상자산사업자 신고(ISMS 선행)와 가상자산이전업 등록을 해야 한다.
  3. 국내 카드사 제휴는 2017년 행정지도에 막혀 있다.
  4. 리저브 보상은 유사수신행위법과 이자 금지 법안에 걸린다.
- **다음 할 일:** 법률의견서와 FIU·금융위 질의로 구조를 정하고, 그 답으로 제휴를 시작한다(10장). 연락할 곳, 곳마다 물을 질문, 법과 규제는 [Aqua 사업 준비 핸드북](https://claude.ai/artifact/G6ZGp3dpmLtdagiBYXVKpb)(claude.ai 문서, 공유받은 사람만 열린다)에 모았다.

## 2. 방향과 원칙

제품 책임자가 정한 방향이다.

1. **KAST를 거의 그대로 옮긴다.** 받은 코인 자동 매도, 세 멤버십, 회원 간 무료 송금, 리저브 구조를 가져온다. 요금과 요율은 KAST를 따르지 않고 한국 카드 시장에 맞춘다. 제품 구조를 옮긴다는 뜻이고 KAST 코드를 쓴다는 뜻은 아니다.
2. **받은 코인은 들고 있지 않는다.** 입금이 확인되면 바로 원화 스테이블 잔액으로 바꾼다. 코인 지갑과 코인 화면이 없다. 코인은 충전과 지갑 주소로 보내기 안에서만 고른다.
3. **원화(법정화폐) 입출금은 없다.** 돈이 들어오는 길은 코인·원화 스테이블 입금뿐이고, 나가는 길은 카드 결제, 회원에게 보내기, 지갑 주소로 보내기다.
4. **입금은 무료다.** 수수료는 밖으로 보낼 때만 받는다(네트워크 비용, 원화 스테이블이 아닌 코인으로 보낼 때 0.5%).
5. **원화 스테이블은 발행하지 않는다.** 인가받은 발행사와 제휴한다. 체험판은 `KRWS`라는 자리표시자를 쓴다.
6. **리워드는 카드 결제 전용이다.** 출금하거나 코인·현금으로 바꾸지 않는다. 환불해도 현금이 되지 않는다.
7. **체험판은 실제 돈과 개인정보를 받지 않는다.** 화면이 실제 이름·전화번호·신분증·주소·계좌를 넣지 말라고 안내한다. 비밀번호는 해시만, 카드 비밀번호는 정했다는 사실만 저장한다. 주소 검색은 가상의 예시 주소만 찾는다.
8. **앱 문구는 해요체다.** 홍보 문구 대신 금액, 날짜, 조건을 쓴다([화면 설계](screen-design.md#문구)).

## 3. 고객과 가설

첫 고객은 **가상자산을 이미 갖고 있고 그 일부를 소비에 쓰려는 한국 거주 성인**이다.

| 고객 후보 | 확인할 문제 | 검증할 가치 |
| --- | --- | --- |
| 코인·스테이블코인 보유자 | 쓸 때마다 처분·출금·재충전을 반복하는가 | 입금부터 결제까지가 실제로 단순해지는가 |
| 보유와 소비를 함께 관리하려는 사람 | 쓸 돈과 둘 돈을 나눠 보기 어려운가 | 잔액과 리저브를 나누는 것이 관리에 도움이 되는가 |
| 카드 결제액이 큰 사람 | 연회비를 내고 페이백 한도를 넓힐 만큼 쓰는가 | 연회비와 페이백·리저브 보상을 비교해 등급을 고르는가 |
| 제휴 서비스에서 디지털 자산을 받는 사람 | 받은 자산을 소비에 연결하기 번거로운가 | 받은 잔액을 앱 안에서 관리하고 쓸 이유가 있는가 |

비교 기준은 국내 체크카드와 간편결제의 편의성과 혜택이다. 해외 결제는 빼지 않고, 범위와 비용은 카드 파트너 조건으로 정한다.

고객 테스트에서 물을 것:

1. 잔액, 카드로 쓸 수 있는 돈, 리저브, 리워드를 구분하는가.
2. 도움 없이 충전부터 첫 결제까지 마치는가. 코인 화면이 없어도 보낸 코인이 잔액이 됐다는 것을 아는가.
3. 연회비와 페이백 한도를 비교해 등급을 고르는가. 내리기 예약, 갱신일 납부, 해지 때 돌려받는 연회비를 이해하는가.
4. 회원에게 보내기와 지갑 주소로 보내기의 비용, 시간, 한도 차이를 아는가.
5. 리저브 자동 사용을 켜고 끌 때 결제할 수 있는 돈과 거절 조건이 어떻게 바뀌는지 예측하는가.
6. 리저브에서 빼는 조건과 리워드를 쓰는 조건(결제 전용, 출금 불가)을 이해하는가.
7. 카드 신청, 보완, 심사, 발급, 배송, 활성화, 잠금의 각 상태에서 다음에 할 일을 아는가.
8. 리저브 연 5%와 스탠다드 페이백 1%만으로 지금 쓰는 카드 대신 쓸 이유가 있는가.

실제 운영에서는 가입·본인확인·첫 입금·첫 결제 전환율, 전환 비용, 결제 승인·거절, 반복 사용, 등급 선택·갱신·내리기, 회원 간 보내기, 리저브 유지·인출, 리워드·페이백의 비용과 사용, 환불·문의, 잔액 대조 차이를 잰다.

## 4. 제품 구조

### 세 영역

| 영역 | 역할 | 먼저 보여 줄 것 |
| --- | --- | --- |
| 잔액 | 받은 코인을 바로 바꾼 원화 스테이블. 충전, 회원에게 보내기, 지갑 주소로 보내기, 카드 결제와 연회비가 모두 여기서 오간다 | 잔액 하나, 처리 중인 입출금, 보내는 중인 금액 |
| 카드 | 잔액과 사용자가 허용한 리워드·리저브로 결제한다. 멤버십과 연회비 | 카드 상태, 멤버십, 카드로 쓸 수 있는 돈 |
| 리저브·리워드 | 잔액 일부를 리저브에 두고 보상을 받는다. 페이백과 리저브 보상은 결제 전용 리워드로 쌓인다 | 리저브 금액과 보상률, 실시간 리워드, 이번 달 페이백 |

반복 흐름은 **코인 보내기 → 받는 즉시 원화 스테이블 잔액 → 일부는 리저브에 두기 → 리워드 확인 → 카드 결제·회원에게 보내기 → 다시 충전**이다.

### 금액 구분

- **잔액:** 원화 스테이블로 들고 있는 돈.
- **카드로 쓸 수 있는 돈:** 잔액에 사용자가 켠 리워드와 리저브를 더한 금액. 홈의 큰 숫자는 잔액이고, 이 금액은 카드 아래에 따로 둔다.
- **보내는 중인 금액:** 지갑 주소로 보내기가 끝날 때까지 잔액에서 떼어 둔 금액.
- **승인 보류액:** 진행 중인 카드 거래로 묶인 금액.
- **리저브:** 따로 둔 금액. 수수료 없이 잔액으로 뺄 수 있다.
- **리워드:** 리저브 보상과 결제 페이백. 예상·확정·사용·환불 복원 기록을 따로 둔다.
- **코인 수량과 원화 환산 금액:** 충전하거나 밖으로 보낼 때만 쓴다. 입금 확인 시점의 가격으로 한 번만 원화로 바꾸고, 그 뒤 시세는 잔액에 반영하지 않는다.

### 화면

주 메뉴는 **홈 / 카드 / 혜택 / 전체**다. 리저브, 거래 내역, 연간 거래 내역은 상세 화면이다. 모바일은 하단 탭, 넓은 화면은 왼쪽 사이드바를 쓰고 다크 모드를 지원한다. 화면별 구성과 시각 원칙은 [화면 설계](screen-design.md)에 있다.

| 화면 | 내용 |
| --- | --- |
| 홈 | 잔액, 충전·보내기, 처리 중인 입출금, 내 카드(없으면 3D 카드와 카드 만들기), 갱신 안내, 실시간 리워드와 리저브, 최근 거래 |
| 카드 | 카드 신청 또는 발급된 카드: 카드 정보·잠그기·결제해 보기, 휴대폰 결제, 멤버십, 카드 설정 |
| 혜택 | 실시간 리워드, 리워드 먼저 쓰기, 이번 달 페이백과 한도, 리저브 보상, 리워드 내역 |
| 전체 | 프로필, 내 태그와 QR, 카드·결제 순서·계정·요금·도움말, 체험 설정 |

### 상태와 실패 처리

| 유형 | 다뤄야 할 상태 |
| --- | --- |
| 입출금 | 확인 대기, 완료, 실패, 지원하지 않는 자산·네트워크, 견적 만료, 트래블룰 거절, 회원 간 보내기 완료·거절 |
| 카드 | 신청·심사·보완·거절·발급, 배송·활성화, 잠금, 결제 승인·확정·거절 |
| 멤버십 | 올리기 납부(남은 연회비 차감), 내리기 예약·취소, 갱신 30일·7일 전 안내, 갱신 납부, 잔액 부족으로 스탠다드 전환, 해지 환불 |
| 환불 | 승인 해제, 부분·전액 환불, 사용한 잔액·리워드·리저브 복원, 페이백 조정과 상계 |
| 리저브·리워드 | 넣기·빼기, 결제 보류·이동·복원, 적립, 사용, 환불 복원 |

같은 요청이나 알림이 두 번 와도 잔액과 리워드가 두 번 바뀌지 않아야 한다. 체결은 됐는데 잔액 반영이 늦는 것처럼 일부만 끝난 상태도 추적한다. 실제 서버의 처리 순서는 [입출금과 백엔드 설계](funding-architecture.md)에 있다.

## 5. 기능

체험판에서 되는 것이다. 자세한 흐름은 오른쪽 문서에 있다.

| 기능 | 체험판에서 되는 것 | 문서 |
| --- | --- | --- |
| 가입·고객확인 | 약관(필수 세 가지, 법정 확인은 안내) → 이메일·비밀번호 → 휴대폰 → 신분증(사본·가림 거절)과 얼굴(민감정보 동의, 영상통화 대안) → 1원 계좌 인증(5번 틀리면 무효, 하루 5번) → 고객확인 질문(직업, 목적, 자금 출처, 집 주소, 실제 소유자, 외국 정치적 주요인물). 추가 서류, 자동 거절과 재심, 다음 고객확인일(고위험 1년, 그 밖 3년), 만 19세 이상 | [KYC·AML 검토](kyc-aml-review.md), [모바일 앱 준비](mobile-app-plan.md#본인확인과-고객확인) |
| 충전 | 보내는 곳(국내·해외 거래소, 내 지갑, 주소로 받기), 코인(원화 스테이블·USDC·USDT·BTC·ETH), 네트워크, 받는 주소. 입금 무료, 확인 즉시 원화 스테이블로 전환, 새로고침해도 처리 상태 유지 | [입출금 흐름](funding-flows.md#충전-보내는-곳) |
| 회원에게 보내기 | 태그·이름·휴대폰 번호·이메일·QR로 찾기, 이름 가림, 수수료 없이 바로. 한 번에 100만원·하루 200만원·한 달 500만원(가입 30일 동안과 추가 확인 계정은 절반). 내 태그와 QR, 받기 체험과 알림 | [입출금 흐름](funding-flows.md#보내기-aqua-회원에게) |
| 지갑 주소로 보내기 | 받는 곳(국내 거래소, 해외 거래소, 내 지갑), 목록 밖 거래소 차단, 받는 사람 이름, 내 지갑 서명, 비용 확인, 이메일 인증, 보내는 중·실패 복원 | [입출금 흐름](funding-flows.md#보내기-지갑-주소로) |
| 카드 | 신청(본인확인 → 멤버십·배송지 → 확인), 모의 심사(승인·보완·거절), 가상카드 발급, 실물 배송·비밀번호·활성화, 잠금, 결제 한도, 온라인·해외 결제 차단, 삼성페이·Apple Pay 추가 체험, 분실 재발급, 해지 | [카드 흐름](card-issuance-flow.md) |
| 멤버십 | 세 등급. 올리기(남은 연회비를 빼고 냄, 메탈·골드 카드 교체 배송), 내리기 예약과 취소, 갱신 30일·7일 전 안내, 갱신일 납부, 모자라면 스탠다드, 해지 때 남은 연회비 환불 | [카드 흐름](card-issuance-flow.md#멤버십-변경과-연회비) |
| 결제·환불 | 리워드 → 잔액 → (켠 경우) 리저브 순서. 결제 방식(매장·온라인·해외), 확정되면 페이백. 부분·전액 환불은 원래 구성대로 복원하고 페이백을 조정한다 | [요금과 정책](policy.md#결제와-환불) |

## 6. 요금과 한도

기준 파일은 [policy.ts](../src/lib/policy.ts)이고, 산식과 근거는 [요금과 정책](policy.md)에 있다. 모두 체험판 값이고 출시 요금은 재원 계산 뒤 정한다.

| | 스탠다드 | 프리미엄 | 프라이빗 |
| --- | --- | --- | --- |
| 연회비 | 무료 | 100,000원 | 500,000원 |
| 카드 페이백 | 1%, 월 100만원 결제까지(최대 1만원) | 1.5%, 월 200만원까지(최대 3만원) | 2%, 월 500만원까지(최대 10만원) |
| 리저브 보상 | 연 5%, 1천만원까지 | 연 5.5%, 3천만원까지 | 연 6%, 5천만원까지 |
| 카드 | 가상카드, 실물카드 선택(무료) | 메탈 카드 | 골드 카드 |

| 모든 등급 공통 | 값 |
| --- | --- |
| 입금 | 무료 |
| 회원에게 보내기 | 무료. 한 번에 100만원, 하루 200만원, 한 달 500만원(가입 30일 동안과 추가 확인 계정은 절반) |
| 지갑 주소로 보내기 | 네트워크 비용. 원화 스테이블이 아닌 코인은 전환 수수료 0.5% |
| 결제 한도 | 1회 50만원, 하루 100만원, 한 달 500만원. 사용자가 낮출 수 있다 |
| 연회비 | 잔액에서 먼저 내고 1년마다 갱신한다. 해지하면 남은 날수 ÷ 365만큼 돌려주고, 올리면 그만큼 빼고 낸다. 내리기는 갱신일에 바뀌고 돌려주지 않는다 |

유료 등급은 결제가 많은 회원이 연회비를 돌려받게 잡았다. 프리미엄은 월 약 122만원, 프라이빗은 월 약 317만원부터 아래 등급보다 유리하다.

## 7. 사업 모델

Aqua가 맡는 일은 고객 경험, 잔액·카드·리저브 화면, 거래 상태 관리, 리워드 정책, 고객 지원이다. 자산 보관·전환, 원화 스테이블 발행·상환, 카드 발급·정산은 파트너가 맡는다(8장).

| 수익 후보 | 확인할 것 |
| --- | --- |
| 카드 결제 수익 | 발급사와 나누는 몫. 2025-02-14부터 영세 가맹점 우대수수료율이 신용 0.40%, 체크 0.15%라 가맹점 수수료만으로는 1% 페이백 재원이 나오지 않는다 |
| 출금 전환 수수료 | 원화 스테이블이 아닌 코인으로 보낼 때 0.5%. 입금 전환 비용은 Aqua가 낸다 |
| 멤버십 연회비 | 연 10만원·50만원. 결제가 많은 회원은 페이백으로 돌려받으므로 연회비만으로 페이백을 메우지 못한다 |
| 해외 결제 환전 차익, 제휴 가맹점 예산 | 계약 조건 |
| 리저브 관련 제휴 수익 | 리저브 D안(제휴 금융회사가 이자 지급)의 수수료 구조 |

> 고객 단위 수익 = Aqua 몫의 수익 − 보관·전환·유동성·네트워크·카드 운영 비용 − 본인확인·고객 지원·손실 비용 − 리워드·혜택 비용

- **사용자 원금은 매출이 아니다.** 카드 결제대금은 사용자 잔액에서 나가지만, 리저브 보상과 페이백은 Aqua나 제휴사가 따로 내는 비용이다. 리워드로 결제한 몫을 고객 원금에서 더 빼서 메우지 않는다.
- 월 한도가 있어 회원 한 명의 연간 페이백은 최대 12만원, 36만원, 120만원이다.
- 고객 자산을 맡으면 운용 수익이 저절로 생기거나 Aqua 것이 된다고 가정하지 않는다. 낮은 리워드 사용률이나 소멸을 재원으로 삼지 않는다.
- 출시 요금은 카드 파트너 배분, 보관·전환 비용, 실물카드 원가, 리워드 사용률, 부정 거래·지원 비용을 넣어 다시 정한다.

## 8. 규제와 출시 조건

아래는 공개 자료로 한 1차 검토이고 법률 자문이 아니다. 근거와 확인 수준은 [KYC·AML 규제와 법률 검토](kyc-aml-review.md), [앱스토어·구글 플레이 심사 준비](store-review.md), [KAST 비교와 한국 적용](kast-alignment.md#출시-조건)에 있다.

| 조건 | 지금(2026-10) | 할 일 |
| --- | --- | --- |
| 원화 스테이블 | 디지털자산기본법 국회 계류. 발행 주체(은행 과반 컨소시엄 등) 미정 | 법 통과 뒤 인가 발행사와 제휴. 그전에는 원화 스테이블을 실제 자산으로 내놓지 않는다 |
| 가상자산사업자 신고 | 코인 보관·교환·이전을 하므로 대상이다. ISMS, 대주주 요건, 부채비율 200%(2026-08-20부터). 실명계정이 필요한지는 FIU 유권해석이 필요하다 | ISMS 예비인증 뒤 신고 |
| 가상자산이전업 등록 | 해외 사업자와 개인지갑으로 보내는 것이 대상. 재정경제부 장관에게 등록, 2026-12-03 시행 예정 | 전산설비와 외국환 인력 2명 |
| 카드 발급 | 2017년 행정지도로 국내 카드사 제휴가 어렵다(2026-05 완화 검토). 해외 발급사 우회는 미신고 영업이 될 수 있고 연말정산 소득공제도 어렵다 | 카드사 타진, 카드 분류 확인 |
| 리저브 보상 | 잔액 × 연율 × 기간 보상은 유사수신행위법과 이자 금지 법안 쟁점이다 | 출시안은 D(제휴 금융회사가 지급) 기본, 늦으면 C(결제 혜택만) |
| 회원 간 보내기 | 송금업에 해당하는지 판단 전 | 법률 의견, 체험판은 카드 결제 수준의 한도를 넣었다 |
| 앱 스토어 | 구글은 한국에서 FIU 신고를 마친 개발자만 수탁 지갑·거래소 앱을 받는다(2026-01-28). 애플은 잔액에서 빼는 연회비가 인앱결제(3.1.1)에 걸릴 수 있다 | 신고 수리 뒤 제출, 애플 사전 문의 |

출시 순서 가설: 법 통과 → 발행사 인가 → 발행사·카드사 제휴 → 원화 스테이블 입금만 받는 제한 출시 → 다른 코인 입금 추가. 원화 스테이블 파트너가 늦으면 다른 코인 기반으로 먼저 낼 수 있는지도 같은 법률 검토에서 본다.

역할별 연결은 다음과 같다. 화살표는 서비스 연결이고 돈이 움직이는 순서나 보관 책임을 뜻하지 않는다.

~~~mermaid
flowchart LR
    U[한국 사용자] --> A[Aqua Card 앱]
    A --> W[입금 주소·수탁 파트너]
    W --> X[자동 전환 파트너]
    X --> P[잔액·카드 파트너]
    P --> M[가맹점]
    A --> R[리저브·리워드 관리]
    P --- K[원화 스테이블 발행·상환사]
~~~

받은 코인은 제휴 거래소·OTC가 받자마자 원화 스테이블로 바꿔 넘기는 구조를 권한다. 체결, 보관, 트래블룰을 허가받은 제휴사가 맡고 Aqua는 결과를 장부에 반영한다([KAST 비교](kast-alignment.md#받은-코인의-전환-kast는-어떻게-하나)).

## 11. 체험판 범위와 한계

- 돈, 카드, 본인확인, 시세, 카드 대행사 응답은 모두 브라우저 안의 모의 처리다. 상태는 그 브라우저의 localStorage에만 남는다.
- 가입 직후 체험 잔액은 128,500원이다. 시세는 고정 예시다(1 USDC·USDT = 1,400원, 1 BTC = 1억5천만원, 1 ETH = 400만원).
- 회원에게 보내기는 가상 회원 5명에게만 되고 받는 쪽 장부는 없다. 1원 인증은 실제로 보내지 않고, 계좌번호와 주민등록번호를 받지 않는다.
- 연회비는 모의 잔액에서만 빠지고 실제로 청구하지 않는다.
- 기기 프로필 검사는 Chromium의 화면 크기와 터치 모사이고 실제 기기 검증이 아니다.
- 브라우저 장부는 실제 금융 장부나 인증 시스템으로 쓸 수 없다. 실제 연동 전에 정할 것:
  - **카드 운영:** 대행사의 신청·심사·발급·승인·환불 인터페이스, 중복·지연 응답, 분실·도난·재발급, 배송 실패·반송, 분쟁·부정 사용, 비용과 고객 지원 책임.
  - **입출금과 리저브:** 보관·운용 주체, 인출·결제 유동성, 보상 산정과 재원, 자산별 출금 한도·네트워크 비용·오입금 대응, 회원 간 보내기의 조회·받는 쪽 장부.
  - **요금과 혜택:** 페이백 제외 거래와 가맹점 분류, 프로모션, 보상률 변경 고지, 미사용 혜택 비용.
  - **기술과 운영:** 서버 인증·권한, 고객별 장부와 대사, 이벤트 중복 방지와 재처리, 카드 정보 보호, 보안 모니터링, 상담 이관([입출금과 백엔드 설계](funding-architecture.md)).
