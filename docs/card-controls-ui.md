# 서버에 연결된 카드 설정 화면

연결 모드(`VITE_DATA_MODE=server`)의 첫 화면에 내 카드와 잠금 설정을 표시한다. 카드 이미지는 Aqua의 장식용 디자인이며 서버가 제공하지 않는 카드번호·끝번호·카드 네트워크·멤버십 정보를 만들지 않는다. 공개 GitHub Pages의 브라우저 데모와는 별도 화면이다.

현재 설정은 Aqua sandbox 발급사 계약으로 동작한다. 실제 카드 발급사, 결제망과는 연결되지 않았다. 007 이후 [새 결제 승인 정책](card-authorization-policy.md)을 통해 잠금 요청이 접수되면 테스트 원장의 새 승인을 차단한다. 기존 승인 건의 매입·취소·환불은 계속 처리한다.

## 회원 흐름

카드가 연결된 회원은 화면 상단에서 확인된 상태를 볼 수 있다. 연결되지 않은 회원에게는 카드가 없다는 안내를 보여 주며 모의 발급 버튼은 제공하지 않는다.

`카드 잠그기`는 한 번 눌러 요청한다. `잠금 해제`는 확인창에서 요청하며 취소하거나 Escape를 누르면 전송하지 않는다. 확인창이 열려 있는 동안 배경을 조작할 수 없고, 닫으면 원래 버튼으로 초점이 돌아간다. 상태가 바뀌거나 최신 상태를 확인할 수 없게 되면 확인창을 닫는다.

| 상황 | 화면과 허용 동작 |
| --- | --- |
| 상태 확인 완료 | 확인된 잠금 상태와 변경 버튼 |
| 변경 요청 중 | 전송 중 안내. 새 요청 차단 |
| 접수됐으나 아직 미확정 | 처리 확인 중 안내와 마지막 확인 상태. 반대 요청 차단 |
| 접수 응답 유실 | 이전 요청 확인 버튼. 원래 요청 키와 내용을 유지 |
| 공급업체 명시적 거절 | 요청이 반영되지 않았다는 안내. 최신 상태 확인 후 다시 요청 가능 |
| 검토 필요 | 결과 확인에 시간이 걸린다는 안내. 새 요청 차단 |
| 연결 실패·오프라인·오래된 조회 | 마지막 확인 상태 표시. 새 요청 차단 |
| 운영 환경의 sandbox 조회 | 상태만 표시. 변경 버튼 제공하지 않음 |

HTTP 202는 접수 결과다. 화면은 `confirmedStatus`를 직접 바꾸지 않고 발급사가 확인한 새 조회를 기다린다. 카드의 `updatedAt`은 상태 기록의 변경 시각이므로 공급업체 확인 시각으로 표시하지 않는다.

`새 결제 승인`은 발급사 확인 상태와 별도로 표시한다. 잠금 요청이 접수되면 승인을 중단하고, 해제는 발급사가 성공을 확인해야 승인 가능으로 표시한다. 실패한 잠금 요청도 승인 중단 의도를 유지한다. 오래된 조회나 응답 유실 상태에서는 확인이 필요하다고 표시한다.

## 조회와 계정 경계

`GET /api/issuer-card`에도 `X-Aqua-Account`를 보내며 서버 세션과 일치해야 한다. 다른 탭에서 계정 쿠키가 바뀌면 409 `SESSION_CHANGED`를 반환하고 기존 화면을 종료한다. 로그인·로그아웃 이후 도착한 옛 응답은 다른 회원 화면에 적용하지 않는다.

보이는 화면에서 온라인일 때 5초 간격으로 조회하며 초점 복귀·연결 복구 때 다시 확인한다. 마지막 성공 조회가 15초를 넘거나 조회에 실패하면 변경을 막는다. 숨겨진 화면에서 폴링을 이어가지 않는다.

변경 요청 전에 기존 조회를 취소하고 이전 응답을 무효화한다. 요청이 접수된 뒤에는 새로 시작한 조회가 해당 카드의 접수 버전 이상을 확인해야 변경 제한을 해제할 수 있다. 오래된 카드 버전, 후퇴한 명령 상태, 형식이 맞지 않는 응답은 현재 상태로 사용하지 않는다.

## 응답 유실과 저장된 요청

전송 전에 카드 ID·목표 상태·기대 버전·요청 키·생성 시각을 `localStorage`에 저장하고 다시 읽어 확인한다. 저장할 수 없으면 전송하지 않는다. 계정별·요청별로 별도 항목을 써서 다른 탭의 요청을 덮어쓰지 않는다. 계정 정보, 비밀번호, 세션 쿠키, 공급업체 참조와 전송 비밀값은 저장하지 않는다.

새로고침·탭 닫기·재로그인 후에는 저장된 요청을 읽어 복구한다. 자동으로 변경 요청을 다시 보내지는 않는다. 회원이 `이전 요청 확인`을 누르면 같은 키와 내용을 재사용한다. 접수 결과를 검증했거나 서버가 기존 요청의 미접수를 확정한 경우에만 해당 항목을 정리한다. 읽기·쓰기·삭제 실패나 손상된 기록을 무시하고 새 요청으로 넘어가지 않는다.

여러 탭이 동시에 요청을 저장하더라도 각각의 기록을 보존한다. 서버의 카드 버전 확인과 미해결 명령 한 건 제한이 충돌을 막는다. 다른 탭의 저장소 변경은 새 조회를 요구하며, 늦은 응답이 다른 요청을 지우지 않는다. 저장소를 외부에서 지우거나 브라우저 프로필을 잃은 경우의 복구까지 보장하는 저장 장치는 아니다.

## 로컬 검증

일반 화면은 [서버 개발 안내](server-development.md)에 따라 API와 `npm run dev:server`를 실행한다. 카드 매핑과 발신 작업자 연결은 [발급사 요청·복구](issuer-command-outbox.md)의 운영자 명령을 사용한다. 회원 화면에는 테스트용 CLI나 공급업체 식별자를 노출하지 않는다.

브라우저 검사는 다음처럼 실행한다.

```bash
npm run build:server
npm run build:connected
npm run test:issuer:browser
```

검사 실행기는 `TEST_DATABASE_URL`의 로컬 PostgreSQL에 무작위 전용 스키마를 만든다. 기존의 `DATABASE_URL`·`DISPATCHER_DATABASE_URL` 역할에 해당 스키마의 제한된 권한만 부여하고, 컴파일한 API와 연결 화면을 `127.0.0.1:3006`에서 실행한다. 다른 포트가 필요하면 `AQUA_ISSUER_BROWSER_PORT`를 지정한다. 마지막에는 프로세스를 종료하고 생성한 스키마만 제거한다. 기존 개발 계정이나 다른 브라우저 검사의 가입 제한을 건드리지 않는다.

검사는 실제 회원 API·PostgreSQL·발신 작업자와 로컬 서명 HTTP 상대를 사용한다. 응답 유실·지연은 브라우저 네트워크 경계에서 재현한다. 화면과 결과는 `artifacts/issuer-server/`에 저장한다. CI에서도 같은 실행기를 사용한다. 모바일 너비 검사는 Chromium 모사이며 실제 iPhone Safari·Android 기기 검증과 다르다.

2026-11-19 검증에서 카드 설정·승인 정책 브라우저 검사 18개, 서버 검사 203개, 제품·클라이언트 검사 139개가 통과했다. 브라우저 검사는 잠금 후 새 승인 거절, 기존 승인 재전송·매입·취소·환불, 해제 후 거절 기록 유지, 응답 유실 후 새로고침·탭 닫기 복구, 오래된 조회 차단, 저장·삭제 실패, 오프라인, 공급업체 거절·검토·운영자 복구, 다른 탭과 계정 전환을 포함한다. 재시도 소진 검사만 작업자 시계를 전진시키며 실제 DB 상태와 서명 HTTP 경로를 유지한다.
