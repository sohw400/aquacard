# Aqua Card: 비교 기준과 PoC 정책 v1.3

작성일: 2026-10-13 · 적용 범위: 실제 자금을 취급하지 않는 제품 PoC

이 문서는 미정이던 보상률·페이백·수수료·한도를 **검증 가능한 모의 정책**으로 정한다. 실제 서비스 계약이나 수익률 약속이 아니다. 제품 코드의 정책 설정은 [`src/lib/policy.ts`](../src/lib/policy.ts)의 `POLICY`와 `PLANS`에서 관리한다. v1.3은 기존 자동 전환 구조에 입출금 단계, 출금 보류·취소·실패 복구, 네트워크 비용 예시를 추가한다. 네트워크 설정과 비용은 [`movements.ts`](../src/lib/movements.ts)에 있다.

## 1. 경쟁사 비교의 근거와 한계

2026-10-13 최초 조회에서 경쟁사 공식 사이트 접근이 프록시 `403 Forbidden`으로 실패했다. 이후 허용된 기존 HTTPS 경로로 다시 확인했을 때 **KAST 상품 페이지·공식 약관은 HTTP 200으로 읽었다.** 기본 TLS 검증을 유지했으며 인증서 검증을 끄거나 차단을 우회하지 않았다. Crypto.com·RedotPay의 최신 수치는 여전히 미검증이다. KAST 도움말도 접근하지 못해 앱의 최신 체인별 입출금 목록과 실거래는 확인하지 못했다.

| 비교 대상 | 이번 기획에서 사용하는 기준 | 수치 확인 상태 |
| --- | --- | --- |
| KAST | 코인 입금은 약관상 KAST에 매도·USD 채권 장부 기록, Reserve는 USD 잔액의 내부 장부 배정, 카드 사용 가능 | 공식 표시값 Standard 무료·페이백 1.5%·Reserve 8%, Premium 연 $1,000·2%·10%, Private 연 $10,000·3%·12%. 상품 페이지와 약관의 프로모션 요율·종료 일정 불일치. 자세한 한도·재원·출금 조건은 아래 참조 |
| Crypto.com 카드 | 토큰 보유 조건·등급별 카드 혜택을 비교할 후보 | 최신 등급·스테이킹/락업 조건·요율·지역별 조건 모두 미검증. Aqua에 해당 조건을 도입하지 않음 |
| RedotPay | 다중 가상자산을 소비에 연결하는 카드의 입금·전환·출금 비용을 비교할 후보 | 최신 발급비·거래 수수료·환율·지원 국가 모두 미검증 |
| 한국 체크카드·간편결제 | 무료 기본 이용, 원화 중심 화면, 익숙한 소비 내역, 혜택 상한·제외 거래의 투명성을 비교할 기준 | 특정 카드의 확정 요율을 인용하지 않음 |

**5%와 Basic 1%·Plus 1.5%, Plus 월 4,900원과 실물 발급 9,900원은 모두 Aqua의 자체 PoC 결정값이다.** KAST 공식 표시보다 보상 수치는 낮게 설정하고, 무료 Basic과 부담이 적은 월 구독 선택안을 검증한다. 통화·상한·재원·프로모션·계산 방식이 달라 실제 가치나 수익률을 동등하게 비교하지 않는다. PoC에서 월회비·실물 발급비를 실제 청구하거나 원금에서 차감하지 않는다.

KAST 공식 확인의 핵심:

- Standard는 Reserve 8% 표시, Premium은 최초 $50,000에 10%·초과분 8%, Private는 최초 $200,000에 12%·초과분 8%를 표시한다.
- Reserve 상품 페이지는 2027-07-01 도입 혜택 변경을 안내하지만 Reserve 약관은 2026-12-31 또는 전체 Reserve $100 million 도달 시 종료, 출시 뉴스는 2027-01부터 다른 요율을 설명한다. 사용자별 최종 적용 조건은 별도 확인해야 한다.
- 보상은 KAST 자체 기업 수익·재무제표에서 지급하는 고객 혜택으로 설명한다. 고객 자산 운용 수익을 비례 배분하는 모델이라고 확정하지 않는다.
- Reserve 보상, Card USD Cashback, KAST Points는 공식 문서에서 구분한다. Aqua의 결제 전용 리워드와 모두 같다고 설명하지 않는다.
- 원물 코인을 계속 보유하는 지갑과 입금 시 USD 채권 장부가 만들어지는 KAST 기본 구조는 다르다.

직접 인용·약관 시행일·조회 근거는 [KAST 자금 구조 확인](kast-funding-model.md), 현재 모의 구현과 실제 백엔드 계획의 구분은 [자금 아키텍처](funding-architecture.md)에 정리한다.

Basic과 Plus의 Reserve 보상률·상한·카드 결제 한도·전환비는 동일하다. 가입 보너스·초대 보상·일반 코인 스테이킹은 PoC 기본 혜택에서 제외하고 후속 실험으로 둔다. 국내·해외 수수료를 검증하지 못했으므로 실제 해외 사용 가능성이나 FX 우대는 약속하지 않는다.

### 멤버십 비교 예시

| 월 적격 결제액 | Basic 페이백 | Plus 페이백 | Plus에서 월회비 4,900원을 제외한 혜택 상당액 |
| --- | --- | --- | --- |
| 50만원 | 5,000원 | 7,500원 | 2,600원 |
| 100만원 | 10,000원 | 15,000원 | 10,100원 |
| 200만원 | 10,000원 | 30,000원 | 25,100원 |

수수료·제외 거래·리워드 사용분 없이 모두 적격 소비라고 가정한 산술 예시다. 같은 소비액에서 Plus의 추가 페이백이 월회비 4,900원에 도달하는 지점은 약 **98만원**이다. 이는 실제 유료 가입 추천이나 고객 수익률 계산이 아니며 카드 신청 화면에서 혜택 비교를 이해하는지 확인하기 위한 기준이다.

### 카드 신청부터 사용까지

미신청 → 모의 본인 확인 → Basic/Plus 선택 → 가상/실물 신청 정보 → 비용·약관 검토 → 신청 완료 → 모의 심사 → 가상 카드 발급·사용 시작을 기본 흐름으로 한다. 심사 상태는 접수·보완 필요·승인·거절을 구분한다. 실제 신분증·인증번호·결제정보를 수집하지 않는다.

실물 선택 시 배송 준비 → 배송 중 → 수령 → 활성화를 별도 흐름으로 제공한다. 카드 발급·물류·회비·발급비는 모두 모의이며 실제 발급사·카드망·배송과 연동하지 않는다. 모의 발급 전에는 결제를 허용하지 않고, 발급 후 카드 잠금·해제로 결제를 제어한다.

## 3. 자산 정책

- 충전 수단은 **원화 스테이블코인, USDC, USDT, BTC, ETH**다. 앱은 코인을 보유 자산으로 보여 주지 않는다. 실제 입금 주소·체인 트랜잭션을 생성하지 않는다.
- 원화 스테이블코인은 **발행사 제휴 준비 중**으로 표시하며 사용 가능한 토큰으로 발행하거나 가장하지 않는다. 결제 잔액과 Reserve의 원화 표시는 모의 원화 장부이며 새로운 원화 스테이블 토큰이 아니다.
- BTC·ETH·USDT·USDC 원화 평가는 고정 샘플 시세로 표시하고 실시간 체결가격이라고 표현하지 않는다. 초기 예시는 1 USDC/USDT=1,400원, 1 BTC=1억5천만원, 1 ETH=400만원이다. 시장의 현재 시세를 주장하지 않는다.
- 모의 네트워크 표시는 USDC Polygon, USDT Ethereum, BTC Bitcoin, ETH Ethereum이다. 실제 네트워크 입금·출금 연동을 의미하지 않는다.
- 코인 입금 흐름은 **보내는 곳 선택 → 주소 확인 → 입금 확인 → 자동 전환(모의) → 원화 스테이블 결제 잔액 반영**이다. KAST와 같이 코인 원물을 보유하는 지갑 모드는 두지 않는다.
- 이전 데모에서 남은 `holdings`(모의 보유 코인)는 저장 데이터를 불러올 때 고정 시세로 한 번 전환해 결제 잔액에 더하고 `보유 코인 자동 전환` 내역을 남긴다. 장부에는 더 이상 코인 수량이 없다.
- 첫 PoC의 Reserve와 자동 결제 충당은 원화 기준 데모 적격 잔액으로 한정한다. **Reserve 배정·해제는 이미 전환된 원화 장부의 내부 이동**이며 추가 매도·전환비가 없다.
- 코인 외부 출금 모의는 선택한 원화 총액을 `spend`에서 차감하고 전환비와 네트워크 비용을 제외한 코인 수량을 예상한다. Reserve와 리워드에서 부족분을 자동 충당하지 않는다. Reserve 원금을 출금하려면 먼저 결제 잔액으로 내부 이동한다.
- 변동 자산을 카드 승인 때 즉시 매도하는 기능은 후속 범위다. 사용자 동의, 승인 시간, 가격 변동, 전환 후 승인 실패 복구가 필요하다.

## 4. 산식과 경계 조건

### 신규 코인 입금·출금

`입금 총평가액 = floor(입금 수량 × 데모 시세)`

`전환 수수료 = ceil(원화 총액 × 0.005)`

`입금 순 원화액 = 원화 총액 − 전환 수수료`

`출금 순 원화액 = 원화 총액 − 전환 수수료 − 네트워크 비용`

입금은 순 원화액을 결제 장부에 더한다. 출금은 요청 원화 총액을 사용 가능 잔액에서 보류하고 `순 원화액 / 데모 시세`로 수령 예상 코인 수량을 보여준다. 총평가액 또는 출금 총액은 최소 1,000원이고, 비용 공제 후 수령액이 양수여야 한다. 실패나 허용 단계의 취소 시 보류 총액을 복원한다. 입력값·원화 안전 정수 범위와 실시간 30초 견적을 검증한다. 데모의 하루 진행 버튼은 견적 시간을 연장하지 않는다.

예를 들어 10 USDC를 1,400원 샘플 시세로 모의 입금하면 총 14,000원, 전환비 70원, 결제 잔액 증가 13,930원이다. 14,000원을 USDC·Polygon으로 출금하면 전환비 70원과 네트워크 비용 예시 140원을 제외해 13,790원 상당, 예상 9.85 USDC를 수령한다. 1,001원 출금에는 올림한 전환비 6원과 네트워크 비용 140원을 반영해 순액 855원을 적용한다. 실제 전송이나 비용 납부는 하지 않는다.

### Reserve

`적립 리워드 = min(적격 원금, 10,000,000원) × 0.05 × 보유 초 / 31,536,000`

계산 기준은 365일이며 복리 재투자는 없다. 내부 계산에서 소수원 누적분을 보존하고, 결제 가능 리워드는 사용 가능한 누적액을 원 단위로 내린다. 충전·인출·결제 보류·금리 변경 시점마다 구간을 나눠 산정한다. 이미 적립한 구간을 새 보상률로 재계산하지 않는다.

- 100만원을 24시간 유지하면 약 **136.99원 상당**, 30일이면 약 **4,109.59원 상당**이다.
- 100만원을 365일 유지하면 **50,000원 상당**이다.
- Reserve에서 10만원을 결제 재원으로 보류하면 나머지 90만원만 계속 적립한다.
- 전액 인출해도 이미 확정한 미사용 리워드는 남는다.
- 화면에서 보상이 실시간 증가하는 것과 그 보상이 실제 현금인 것은 다르다. `결제 전용 리워드`를 함께 표시한다.

### 페이백

`거래 페이백 = min(floor(적격 사용자 자금 정산액 × 등급별 지급률), 해당 월 상한 잔여액)`

Basic 지급률은 0.01·월 상한 10,000원, Plus 지급률은 0.015·월 상한 30,000원이다. 신청 시 선택한 등급을 기준으로 한다. 아래 숫자 예시는 Basic 기준이다.

리워드 사용분, 수수료, 취소된 결제액은 기준에서 제외한다. 결제 지갑과 Reserve에서 사용한 원금은 동일하게 인정한다.

- 20,000원 결제 중 리워드 2,000원, 결제/Reserve 원금 18,000원을 사용하면 **180원 상당**을 적립한다.
- 월 적격 소비 100만원이면 페이백이 **10,000원 상당**으로 상한에 도달한다.
- 월 잔여 한도가 30원이면 예상 산정액이 180원이더라도 실제 지급은 30원 상당이다.
- 리워드에 다시 페이백을 지급하는 순환 보상은 없다.

### 결제와 환불

- 가용 자금 총합이 부족하거나 카드가 잠겨 있거나 한도 초과이면 실패하며 원금·리워드를 차감하지 않는다.
- 승인 실패·취소는 보류를 해제한다. 적립되지 않은 예상 페이백은 지급하지 않는다.
- 전액 환불은 거래 당시 사용한 리워드는 리워드로, 사용자 원금은 결제 잔액으로 복원한다. 이미 원금으로 전환해 지출한 Reserve는 자동으로 다시 Reserve로 넣지 않는다.
- 환불에 해당하는 페이백을 조정한다. 이미 사용한 페이백은 향후 리워드에서 상계하는 기본안이며 사용자 원금을 임의 차감하지 않는다.
- 부분 환불은 원거래의 원금·리워드 구성 비율을 유지하고, 원 단위 반올림 잔여액은 마지막 환불에서 맞춘다. 부분 환불을 통한 현금성 리워드 전환을 허용하지 않는다.
- 재시도·중복 요청은 같은 거래를 두 번 적립·차감하지 않도록 처리한다.

PoC가 모든 예외를 구현했다는 뜻은 아니다. 제공된 UI와 테스트를 통해 구현된 범위를 별도로 확인한다.

## 5. 왜 5%·1%·0.5%인가

이 값들은 현재 확인 가능한 경쟁사 계약값을 복제한 결과가 아니라 **비용을 계산하면서 핵심 경험을 평가하기 위한 초기 가설**이다.

- Reserve 5%는 보유 보상과 카드 소비를 연결하는 가치를 보여준다. 실제 운용 수익이 생기거나 지급 가능한 상태라고 전제하지 않는다.
- 페이백 1%·월 1만원은 반복 소비의 동기를 주며 기본 무료 상품의 고객당 보상 비용을 제한한다.
- Plus 1.5%·월 3만원·월회비 4,900원은 기본 혜택보다 더 쓸 이유와 지불 의향을 평가하는 초기값이다. 실물 발급 9,900원은 카드·배송 원가 계약 전의 선택 가격 가설이며 이익률이 검증된 요금이 아니다.
- 전환 0.5%는 명시 비용을 사용자 판단에 포함하기 위한 가설이다. 네트워크 비용·유동성·실제 체결 스프레드가 추가될 경우 최종 비용과 함께 재설계해야 한다.
- 무료 Basic과 락업 없는 Reserve로 핵심 이용 흐름의 마찰을 줄인다. 유료 티어 수익은 기본 재원으로 가정하지 않는다.

**사용자 원금은 매출이 아니다.** 일반 카드 대금은 사용자 자금에서 나오지만 Reserve 리워드·페이백으로 제공한 추가 혜택은 별도 비용이다. 회사·제휴사의 계약 수익 또는 확정한 보상 예산을 배정해야 한다.

예를 들어 Reserve 평균 100만원, 월 적격 결제 100만원이면 연간 기준 Reserve 보상 월평균 약 **4,167원**, 페이백 **10,000원**으로 혜택 비용은 월 **14,167원 상당**이다. 같은 달 100만원을 한 번 전환하면 0.5% 수수료의 명목 수입은 **5,000원**이다. 이는 다른 수익과 비용을 포함하기 전부터 보상 재원 검증이 필요함을 보여준다. 매달 전체 잔액을 다시 전환한다고 가정하지 않으며, 낮은 리워드 사용률만으로 수익성을 주장하지 않는다.

실제 출시 전에는 카드 파트너 배분액, 자산 보관/전환 비용, 순 운용·제휴 수익, 유동성 비용, 리워드 사용률, 부정 거래/지원 비용을 넣어 지급률과 상한을 다시 확정한다. 한국에서의 제공 주체·가능 범위·파트너 조건도 확인한다.

## 6. PoC에서 확인할 것

1. 보유 평가액과 지금 카드로 쓸 금액을 구분하는가?
2. 입금→전환→Reserve→리워드→결제의 비용·결과를 예측할 수 있는가?
3. Reserve 자동 사용을 끄면 결제 가능액과 실패 조건이 정확히 바뀌는가?
4. 리워드·원금·페이백이 중복되거나 환불로 현금화되지 않는가?
5. 한도·월 상한·견적 만료·잔액 부족·카드 잠금에서 거래가 안전하게 멈추는가?
6. 사용자는 5% 보유 리워드와 Basic 1% 페이백만으로 기존 카드 대신 사용할 이유가 있는가?
7. Plus 월회비·추가 페이백·상한을 비교해서 등급을 선택하는가?
8. 신청·보완·심사·발급·배송·활성화·카드 잠금의 각 상태에서 다음 행동을 알 수 있는가?

외부 계정·API 키·실제 자금 없이 검증한다. 특정 기능의 구현 완료 여부는 앱 동작과 해당 기능의 테스트 결과를 기준으로 보고한다.
