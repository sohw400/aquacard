# 입출금 흐름

작성일: 2026-10-13 · v0.7 화면 기준

Aqua는 원화(법정화폐) 입출금을 지원하지 않는다. 잔액은 **원화 스테이블코인**으로 보관하고, 다른 코인은 받는 대로 원화 스테이블로 바꿔 잔액에 넣는다. KAST가 코인마다 청산 주소를 두고 받은 코인을 거래 확정 즉시 파는 것처럼, Aqua도 **코인을 보유 자산으로 들고 있지 않는다.** 그래서 코인별 지갑, 보유 코인 목록, 코인 현황 화면이 없고 자산 탭도 없앴다. 앱에 보이는 돈은 홈 맨 위의 잔액 하나와 리저브다. 코인은 충전 시트와 `지갑 주소로` 보내기 시트 안에서만 고른다([KAST 앱 구조와 Aqua 화면 대응](kast-alignment.md#4-kast-앱-구조와-aqua-화면-대응)). 원화 스테이블의 실제 이름·발행사·네트워크는 제휴 후 정하며 PoC는 `KRWS`라는 자리표시자를 쓴다(1 KRWS = 1원).

## 화면 구성

모든 입출금은 홈의 잔액 아래 `충전`과 `보내기` 두 버튼에서 시작한다. 처리 중인 입출금은 잔액 아래 한 줄로 보이고, 여러 건이면 거래 내역으로 이어진다. 출금 중인 금액은 잔액 아래 `보내는 중 N원`으로 따로 적는다.

| 경로 | 입력 | 확인 | 처리 결과 |
| --- | --- | --- | --- |
| 홈 › 충전 | 보내는 곳, 코인, 네트워크 → 받는 주소와 보내는 순서 → 보낸 수량(체험) | 원화 환산 금액, 입금 수수료 0원, 잔액에 더할 금액 | 입금 대기 → 네트워크 확인 → 원화 전환 → 완료 |
| 홈 › 보내기 › Aqua 회원에게 | 태그·이름·휴대폰 번호로 찾기 또는 QR 찍기 → 금액 | 받는 사람(이름 일부 가림과 태그), 수수료 0원, 보낸 뒤 잔액 | 바로 완료 |
| 홈 › 보내기 › 지갑 주소로 | 코인, 네트워크 → 받는 사람, 지갑 주소, 금액 | 잔액에서 빠질 금액, 전환 수수료(원화 스테이블은 없음), 네트워크 비용, 받는 금액, 보낸 뒤 잔액, **이메일 인증** | 출금 검토 → 네트워크 전송 → 완료 |
| 리저브 › 넣기·빼기 | 금액 | 수수료 0원, 옮기기 전후의 잔액과 리저브 | 완료 |

충전은 2단계, 지갑 주소로 보내기는 3단계이고 시트 머리에 단계 번호가 보인다.

## 충전: 보내는 곳

KAST처럼 "어디서 보내는지"부터 고르게 해 주소 복사 이후의 할 일을 줄였다.

| 보내는 곳 | 안내 |
| --- | --- |
| 국내 거래소 | 업비트·빗썸 같은 거래소 앱에서 출금을 누르고, 코인과 네트워크를 고르고, 주소를 붙여 넣고, 받는 곳은 Aqua·받는 사람은 본인 이름으로 넣는 4단계. 100만원 이상 보내면 트래블룰에 따라 거래소가 받는 곳을 묻는다는 안내를 덧붙인다 |
| 해외 거래소 | 트래블룰을 지원하는 해외 거래소에서만 받는다는 안내 |
| 내 지갑 | 메타마스크·팬텀 같은 개인 지갑에서 보내는 3단계 |
| 주소로 받기 | 주소를 복사해 보내는 2단계 |

받는 주소는 `aqua-preview:polygon:krws`처럼 코인과 네트워크마다 다른 체험용 식별자다. 실제 체인 주소나 QR로 보이지 않게 하고, 주소 주변과 최종 확인에서 실제로 보낼 수 없다는 점을 알린다. 받는 주소 아래에 최소 입금(1,000원 상당), 입금 확인 횟수, 입금 수수료(없음)를 적는다.

## 보내기: Aqua 회원에게

KAST Tag처럼 다른 Aqua 회원에게 태그, 휴대폰 번호, 이메일, QR로 보낸다. 체인을 거치지 않는 내부 이체라 수수료가 없고 바로 끝난다.

1. `Aqua 회원에게`(태그·이름·휴대폰 번호·이메일) 또는 `QR 코드 찍기`를 고른다.
2. 받는 사람을 찾는다.
   - **태그나 이름.**
     - 태그는 영문 소문자, 숫자, 점(.), 밑줄(_)로 3~20자이고 앞의 `@`는 빼도 된다.
     - 목록에서 고르거나 태그 전체를 넣고 `@태그 찾기`를 누른다.
     - 없는 태그는 `@태그 회원을 찾지 못했어요`, 내 태그는 `내 태그예요`로 알린다.
   - **휴대폰 번호.**
     - 숫자를 세 자리 이상 넣으면 번호 찾기로 바뀌고 회원 목록을 감춘다.
     - 번호 전체가 맞고(하이픈은 있어도 된다) 상대가 `휴대폰 번호로 찾기`를 켰을 때만 찾는다.
     - 일부만 넣으면 `휴대폰 번호를 끝까지 넣어 주세요`라고 알린다.
     - 없는 번호와 찾기를 끈 번호는 같은 문구(`이 번호로 찾을 수 있는 회원이 없어요`)로 알려, 가입 여부를 드러내지 않는다.
     - 내 번호는 `내 번호예요`로 막는다.
   - **이메일.**
     - `글자@`로 시작하면 이메일 찾기로 바뀌고 회원 목록을 감춘다.
     - 주소 전체가 맞고(대소문자는 무시) 상대가 `이메일로 찾기`를 켰을 때만 찾는다.
     - 일부만 넣으면 `이메일 주소를 끝까지 넣어 주세요`라고 알린다.
     - 없는 주소와 찾기를 끈 주소는 같은 문구(`이 이메일로 찾을 수 있는 회원이 없어요`)로 알린다.
     - 내 이메일은 `내 이메일이에요`로 막는다.
   - **QR.** 앱에서는 카메라로 상대의 QR을 찍는다. 체험판은 카메라를 켜지 않고, 체험용 회원 네 명의 QR 중 하나를 골라 찍은 것으로 한다.
3. 금액을 넣는다.
   - 받는 사람 줄에 찾은 방법(`휴대폰 번호로 찾음`, `이메일로 찾음`, `QR로 찾음`)이 같이 보인다.
   - 1,000원 이상 원 단위로, 잔액 안에서만 보낼 수 있다.
   - 10,000원·30,000원·50,000원 버튼이 있다.
4. 받는 사람(`김*지 · @minji.k`), 수수료 0원, 보낸 뒤 잔액을 확인하고 보낸다.
5. 완료 화면에 받는 사람, 보낸 시각, 남은 잔액이 나오고, 거래 내역에 `김*지님에게 보냄`이 남는다.

받는 사람 이름은 첫 글자와 끝 글자만 보인다.

체험판의 회원은 [directory.ts](../src/lib/directory.ts)에 있는 가상 회원 5명이다(@minji.k, @junho, @seoyeon_lee, @haneul, @aqua.coffee). 실제로 보내지 않는다.

- 휴대폰 번호는 010-0000으로 시작하는 가짜 번호다. 체험용 번호는 010-0000-0101(김*지)이다.
- 이메일은 예시용 도메인 `aqua.example`의 가짜 주소다. 체험용 이메일은 minji.kim@aqua.example(김*지)이다.
- @seoyeon_lee는 번호와 이메일로 찾기를 모두 끈 회원이다. @junho는 이메일로 찾기를 끈 회원이다.
- @aqua.coffee는 번호가 없는 가게다.

실제 서비스는 회원 서비스에서 태그와 번호를 조회하고, 받는 사람의 잔액에도 같은 금액을 더해야 한다.

### 내 태그와 QR

전체 › `내 태그와 QR`이나 보내기 시트의 `내 QR 보기`에서 연다.

- **내 QR.** `https://aqua.example/@태그`를 담는다. `.example`은 예시용 도메인이라 실제 사이트로 가지 않는다. 어두운 테마에서도 흰 바탕에 검은 무늬로 그린다.
- **처음 태그.** 가입 이메일 앞부분으로 만든다. 다른 회원과 겹치면 숫자를 붙이고(`junho2`), 너무 짧거나 숫자만 있으면 앞에 `member.`를 붙인다.
- **태그 바꾸기.** 바꿀 태그의 규칙은 이렇다.
  - 3~20자.
  - 점(.)과 밑줄(_)은 맨 앞과 맨 끝에 못 쓰고, 점은 이어 쓸 수 없다.
  - 숫자만으로는 만들 수 없다(휴대폰 번호와 헷갈리지 않게).
  - 다른 회원의 태그와 `aqua`·`admin`·`support` 같은 이름은 쓸 수 없다.
  - 바꾸면 이전 태그로는 받을 수 없고 QR도 새 태그로 바뀐다.
- **휴대폰 번호로 찾기, 이메일로 찾기.** 둘 다 꺼진 채 시작한다. 켜면 내 번호나 이메일 주소 전체를 아는 회원이 나를 찾을 수 있다.
- **받아 보기(체험).** 체험판에는 다른 사람이 없으므로 김*지가 내 태그로 10,000원을 보낸 것처럼 받는다(`RECEIVE_FROM_MEMBER`). 시트가 닫히고 `김*지님이 10,000원을 보냈어요` 알림이 뜬다. 잔액에 바로 더해지고 거래 내역에 `김*지님이 보냄 +10,000원`(상세는 `받기`)이 남는다.

태그 바꾸기 횟수 제한은 아직 없다. 실제 앱에서는 받은 돈을 휴대폰 알림으로도 보낸다(전체 › 알림의 입출금 알림).

## 연간 거래 내역

거래 내역 아래나 전체 › 카드의 `연간 거래 내역`에서 연다. 연도는 한국 날짜 기준이고, 체험 시간을 갱신일로 옮겨 다음 해가 생기면 연도를 고를 수 있다.

| 묶음 | 줄 | 기준 |
| --- | --- | --- |
| 들어온 돈 | 충전, 그중 코인을 바꾼 충전, 회원에게 받은 돈 | 완료된 충전만. 코인을 바꾼 충전은 원화 스테이블이 아닌 코인의 전환 금액 |
| 나간 돈 | 카드 결제(환불 뺀 금액), 회원에게 보낸 돈, 지갑 주소로 보낸 돈(그중 수수료와 네트워크 비용), 카드 연회비 | 완료된 보내기만. 연회비는 돌려받은 금액을 뺀다 |
| 받은 혜택 | 페이백, 리저브 보상 | 페이백은 확정된 결제분에서 환불로 줄어든 만큼을 뺀다 |

아래에는 세금 신고 안내가 있다. 코인을 원화 스테이블로 바꾼 충전은 가상자산을 판 것으로 볼 수 있다고 알리고, 페이백과 리저브 보상의 신고는 세무 전문가와 확인하라고 안내한다.

`내역 복사`는 그해 거래를 오래된 것부터 탭으로 칸을 나눠 복사한다. 엑셀이나 구글 시트에 붙여 넣으면 칸이 나뉜다. 칸은 일시, 구분, 내용, 금액(원), 상태, 코인, 수량, 상대, 메모다. 복사가 막힌 환경에서는 같은 내용을 글상자로 보여 주어 직접 선택해 복사하게 한다. 체험 링크 환경은 파일 내려받기를 막으므로 파일 대신 복사로 제공한다.

## 보내기: 지갑 주소로

이전의 출금 흐름이다. 잔액(원화 스테이블)에서 나가며, 받을 코인을 고르면 그 코인으로 바꿔 보낸다.

1. 코인(원화 스테이블·USDC·USDT·BTC·ETH)과 네트워크를 고른다. 네트워크마다 네트워크 비용과 예상 처리 시간이 보인다.
2. 받는 사람(이름이나 메모), 받는 지갑 주소, 금액을 넣는다. `예시 주소`와 `최대` 버튼이 있다. 주소는 형식만 검사한다.
3. 잔액에서 빠질 금액, 전환 수수료, 네트워크 비용, 받는 금액, 보낸 뒤 잔액을 확인하고, 가입한 이메일로 받은 6자리 코드를 넣은 뒤 `N원 보내기`로 요청한다.

KAST의 온체인 송금은 USDC와 USDT만 되지만 Aqua PoC는 다섯 코인 모두 보낼 수 있다. 범위를 줄일지는 [기획 v0.7](kast-alignment.md)의 결정 항목이다.

## 수수료

| 구분 | Aqua 수수료 |
| --- | --- |
| 충전 | 없음. 원화 스테이블이 아닌 코인도 전환 수수료 없이 바꿔 넣는다. 보내는 곳의 출금 수수료는 그쪽에서 따로 낸다 |
| Aqua 회원에게 보내기 | 없음 |
| 지갑 주소로 원화 스테이블 보내기 | 네트워크 비용만 |
| 지갑 주소로 다른 코인 보내기 | 전환 수수료 0.5%(원 단위 올림) + 네트워크 비용 |
| 리저브 넣기·빼기 | 없음 |

네트워크 비용 예시(고정값): Polygon 140원, Ethereum 2,800원(ETH는 2,000원), Bitcoin 1,500원. 예를 들어 잔액에서 USDC를 Polygon으로 10,000원 보내면 전환 수수료 50원과 네트워크 비용 140원을 빼고 9,810원 상당을 보낸다. 리워드와 리저브는 어떤 보내기에도 쓰지 않는다. 리저브에 있는 돈은 먼저 잔액으로 빼야 한다.

KAST 도움말은 코인 입금 전환에 2~5%, 온체인 송금에 $0.20~$6와 0.1%를 받는다고 안내한다. Aqua의 무료 입금은 제품 책임자가 정한 원칙이다.

## 인증

- 가입할 때 이메일 인증과 본인확인(휴대폰·신분증·얼굴·1원 계좌 인증·고객확인 질문)을 마쳐야 앱을 쓸 수 있다.
- 1원 인증에 쓴 은행 계좌는 본인확인에만 쓴다. 이 계좌로 원화를 넣거나 빼지 않는다.
- 지갑 주소로 보내기는 요청 전에 가입한 이메일로 받은 6자리 코드를 넣어야 한다. 체험판은 메일을 보내지 않고 코드를 화면에 보여 준다.
- Aqua 회원에게 보내기는 PoC에서 추가 인증 없이 확인 화면만 거친다. 출시 전에 금액별 추가 인증과 한도를 정한다.
- 실제 서비스는 출금 주소 화이트리스트, 기기 인증, 이상 거래 탐지를 더한다.

## 처리 중인 금액

지갑 주소로 보내기를 접수하면 총액을 잔액에서 예약한다. 처리 중인 금액은 다른 보내기·결제·리저브 이동에 쓸 수 없고 홈의 잔액 아래 `보내는 중`으로 보인다. 엔진의 총액 계산(`portfolioValue`)에는 완료 전까지 포함하지만 화면에 총자산 숫자는 없다. 입금 대기와 출금 검토 단계에서는 취소할 수 있고, 전송이 시작되면 취소할 수 없다. 모의 실패는 예약한 원금과 수수료 전액을 돌려준다. Aqua 회원에게 보내기는 바로 끝나므로 처리 중 상태와 취소가 없다.

이전 체험에서 코인을 보유한 상태로 저장된 데이터는 불러올 때 고정 시세로 원화 스테이블로 바꿔 잔액에 더하고, 거래 내역에 `보유 코인 자동 전환`을 남긴다. 진행 중이던 코인 출금도 원화로 돌려준다.

작업과 단계별 예정 시각은 브라우저에 저장된다. 창을 닫거나 새로고침해도 홈의 입출금 상태 줄이나 거래 내역의 `처리 내역`에서 같은 요청을 다시 열 수 있고, 같은 완료 처리를 반복해도 잔액은 다시 바뀌지 않는다.

## 받은 코인은 누가 파는가

KAST는 지원 자산마다 청산 주소를 두고, 그 주소로 보낸 코인을 거래가 확정되는 순간 실시간 시세로 자동 매도한다고 설명한다. 약관상으로는 보낸 자산의 소유권이 KAST로 넘어가고 사용자에게 USD 기준 장부 잔액이 생긴다. KAST가 받은 코인을 실제 시장에서 언제 처분하는지는 공개 자료에서 확인하지 못했다. Aqua도 사용자가 보기에는 같은 경험(받는 즉시 원화 스테이블 잔액)을 주되, 실제 전환은 제휴 거래소·OTC가 맡고 Aqua는 결과만 장부에 반영하는 구조를 기본안으로 한다. 자세한 비교는 [KAST 구조의 한국 적용](kast-alignment.md#받은-코인의-전환-kast는-어떻게-하나)에 정리했다.

## 구현 경계

현재는 브라우저 안의 모의 처리다. 단계 전환 간격(약 3초)은 실제 체인 처리 시간이 아니다. 실제 입금 감지·전송·정산, 서버 서명 견적, 수탁·거래 파트너 연동, 회원 조회와 내부 이체 장부, 여러 기기 사이의 동시성은 연동 전이다. 금융 서버 구조는 [백엔드 설계](funding-architecture.md)를 따른다.
