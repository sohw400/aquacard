# 리워드·페이백 표시 기준

작성일: 2026-10-13

## 결제 후 같은 잔액이 표시되는 경우

리워드 우선 사용을 켜면 승인 시 사용 가능한 리워드를 먼저 차감한다. 결제 확정 시에는 리워드 사용분을 제외한 원금 결제액에 새 페이백을 적립한다.

스탠다드(1%)에서 5,800원을 결제하고 리워드가 57원인 경우:

| 항목 | 금액 |
| --- | ---: |
| 결제 전 리워드 | 57원 |
| 이번 결제에 사용 | −57원 |
| 원금 결제액 | 5,743원 |
| 새 페이백 | +57원 |
| 결제 후 리워드 | 57원 |

이 결과는 리워드가 사용되지 않은 것이 아니다. 차감액과 새 적립액이 같아 최종 잔액이 동일한 것이다. 영수증에서 두 금액과 전후 잔액을 분리해 설명한다. 리워드 전용 결제에는 페이백을 적립하지 않는다.

`리워드 먼저 쓰기`를 끄면 리워드는 그대로 두고 잔액에서만 결제한다. 같은 5,800원 결제의 페이백은 58원(5,800원의 1%)이고 결제 후 리워드는 115원이 된다. 프리미엄(1.5%)이면 87원, 프라이빗(2%)이면 116원이다.

## 세 금액의 구분

- 사용 가능한 리워드: 다음 카드 결제에 쓸 수 있는 결제 전용 잔액. 출금은 불가하다.
- 리저브 보상: 1초마다 계산해 1원이 될 때마다 리워드에 바로 더한다. 받기 버튼이나 미수령 상태가 없다. 리워드 카드는 원 미만 소수점까지 실시간으로 올라가는 숫자를 보여 주고, 결제하면 리워드에서 먼저 빠진다.
- 이번 달 페이백: 원승인월 기준 확정 및 대기 페이백 현황. 보유 리워드 잔액과 다르다.

홈에는 어두운 리워드 블록의 실시간 리워드와 리저브 행만 둔다. 이번 달 페이백은 혜택 탭에서 확정액, 확정 전 금액, 남은 월 한도, 지급률과 함께 보여 주고, 같은 탭에 리워드 먼저 쓰기 설정, 리워드 내역(적립과 사용), 오늘·누적 리저브 보상이 있다. 리저브 보상은 받는 동작이 없으니 거래로 보지 않는다. 최근 거래와 거래 내역에는 넣지 않고, 리워드 내역에는 그날 쌓인 합계를 한 줄로, 연간 거래 내역에는 요약과 복사 내역으로 남긴다. 거래 내역 아래 접힌 `이번 달 카드 이용`에는 이번 달 결제, 오늘 결제, 받은 페이백과 월 최대가 있다. 내역의 시각은 실제 모의 적립·결제 시점이다.

## 월별 집계와 조정

`getCashbackSummary`는 `cashbackMonth`가 현재 집계월인 결제를 사용한다. 확정액은 확정된 원거래의 페이백에서 누적 환수액을 뺀 금액이다. 대기액은 미확정 원거래의 예상 페이백이다. 남은 한도는 지금 멤버십의 월 상한(스탠다드 10,000원, 프리미엄 30,000원, 프라이빗 100,000원)에서 `monthlyCashback`을 뺀다. 화면의 지급률과 월 한도도 지금 멤버십 기준이다. 이 상태값은 승인 시 예약액까지 포함하므로 지급 완료액으로 표시하지 않는다.

동월 환불은 확정액과 한도를 조정한다. 전월 승인 건이 이번 달에 확정되거나 환불돼도 원승인월 귀속을 유지하며, 새 월 한도를 복구하거나 점유하지 않는다.

이전 페이백 환수 부족분이 있으면 새 적립에서 먼저 상계한다. 영수증은 명목 새 페이백, 이전 조정액과 그중 사용 가능한 적립을 구분한다. 승인부터 확정 사이 다른 리워드 변동이 있었다면 별도 행으로 보여줘 전후 잔액이 일치하도록 한다. 브라우저 재접속으로 대기 건을 확정할 때 기존 영수증을 다시 생성하지 않는다.

## 검증

기존 금융 상태 테스트에 반복 결제의 실제 차감·재적립·중복 확정 방지 회귀 검증을 추가했다. 월별 집계 테스트는 승인 예약, 확정, 동월·전월 환불, 서울 월 경계, 과거 환수 상계를 검증한다. 브라우저에서는 반복 결제, 리워드 전용 결제, 우선 사용 설정 공유, 영수증과 카드·혜택 현황을 확인한다. 모든 거래는 실제 자금 없이 모의 상태에서 실행한다.
