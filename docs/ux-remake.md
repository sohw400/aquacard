# Aqua Card 화면 설계

개편일: 2026-10-13 (3차)

## 이번 개편에서 바꾼 것

2차 화면은 정보 배치는 정리됐지만 파란 강조색, 색 원 안의 아이콘, 색 배지, 같은 크기 카드의 반복 때문에 흔한 템플릿처럼 보였다. 3차는 KAST처럼 흑백 위주의 차분한 금융 앱을 기준으로 다시 정했다.

| 항목 | 2차 | 3차 |
| --- | --- | --- |
| 글꼴 | 기기 기본 글꼴 | Pretendard Variable 포함 배포 ([글꼴](fonts.md)) |
| 기본 버튼 | 파란 바탕 | 잉크색(`#121417`) 바탕, 다크 모드에서는 반전 |
| 강조색 | 파랑 `#1b64da` | 아쿠아 `#0b7285` 한 가지, 적립·진행 상태에만 사용 |
| 첫 탭 | 카드 | 홈 |
| 상태 표시 | 색 배지 | 점과 글자 |
| 목록 아이콘 | 색 원 안의 아이콘 | 회색 면 위 단색 아이콘, 결제는 가맹점 첫 글자 |
| 탭 아이콘 | 아이콘 라이브러리 | 직접 그린 SVG 4종, 선택 시 면 채움 |
| 색 구성 | 밝은 화면만 | 시스템 설정에 따른 다크 모드 |

## 정보 구조

주 메뉴는 홈, 자산, 혜택, 전체다. 카드 관리, 리저브, 이용 내역은 필요한 화면에서 여는 상세 화면이고 뒤로 가면 진입한 탭으로 돌아간다. 상세 화면에서도 시작한 탭의 선택 상태를 유지한다.

| 메뉴 | 주요 작업 | 상세 화면 |
| --- | --- | --- |
| 홈 | 카드 확인, 결제 가능 금액, 충전과 결제, 이번 달 페이백과 리워드, 최근 이용 | 카드 관리, 이용 내역 |
| 자산 | 총 보유 자산(결제 잔액·리저브), 충전·출금, 충전할 수 있는 코인, 입출금 진행 상황 | 리저브 |
| 혜택 | 리워드 잔액과 우선 사용, 이번 달 페이백과 한도, 리저브 보상 받기, 리워드 내역 | 리저브 |
| 전체 | 카드 관리, 이용 내역, 결제 설정, 한도와 요금, 체험 설정 | 카드 관리, 이용 내역 |

960px 미만 화면은 하단 탭, 960px 이상은 왼쪽 사이드바와 가운데 앱 컬럼을 쓴다. 같은 메뉴를 두 곳에 두지 않는다.

## 시각 원칙

색과 간격은 `src/app.css`의 `:root` 토큰에서만 관리한다. 컴포넌트 CSS에 색 값을 직접 쓰지 않는다. 예외는 실물 카드를 재현한 카드 표면이다.

- 바탕은 옅은 회색(`#f3f4f5`), 묶음은 흰 면과 반경 24px이다. 그림자 대신 면의 명도 차이로 구분한다.
- 글자색은 흰 바탕에서 4.5:1 이상인 `--ink`, `--muted`, `--subtle` 세 단계만 본문에 쓴다. `--faint`는 비활성 표시와 장식에만 쓴다.
- 강조색 아쿠아는 흰 바탕에서 5.59:1이다. 적립·입금 금액, 진행 중 상태, 보상률, 켜진 스위치, 한도 막대와 진행 단계처럼 의미가 있는 곳에만 쓴다. 버튼 바탕에는 쓰지 않는다.
- 기본 버튼은 잉크색, 보조 버튼은 회색 면이다. 한 묶음에 기본 버튼은 하나만 둔다. 선택된 탭도 강조색 대신 잉크색과 면 채움으로 표시한다.
- 금액은 숫자를 크게, `원`은 작게 쓴다. 입금과 적립은 아쿠아 `+`, 차감은 기본 글자색 `−`로 표시한다.
- 다크 모드는 같은 토큰 이름에 어두운 값을 넣는다. 기본 버튼은 밝은 바탕에 어두운 글자로 반전되고 토스트도 반전된다.
- 한국어는 `word-break: keep-all`로 어절 단위로 줄을 바꾼다.

## 화면 구성

**첫 화면(가입 전)**은 Basic·Plus 카드 두 장을 3D로 렌더링한 이미지를 맨 위에 두고 "쓰면 돌려받고 두면 쌓이는 카드"로 시작한다. 코인 이미지는 쓰지 않는다. Aqua는 카드 서비스이고 코인은 충전 수단일 뿐이기 때문이다.

**홈**은 위에서부터 큰 카드, 플랜과 카드 상태, 결제 가능 금액과 충전·결제 버튼, 리워드 카드, 이번 달 페이백 한 줄, 최근 이용 5건, 체험 안내 순서다. 결제 가능 금액 옆 `구성`을 누르면 결제 잔액, 리워드, 리저브 사용분을 펼친다. 모바일 첫 화면 머리에는 제목 대신 워드마크와 `체험판` 표시를 둔다.

**리워드 카드**는 어두운 바탕에 원 미만 소수점까지 실시간으로 올라가는 리워드 금액을 크게 보여 준다. 배경에는 로고의 물결을 새긴 금속 동전을 3D로 렌더링해 연하게 깐다(`src/assets/reserve-coin.webp`, 21KB). 깜빡이는 점이나 색 점 같은 장식은 쓰지 않는다.

**자산**은 총 보유 자산과 한 줄 구성 막대로 시작한다. 막대는 결제 잔액(원화 스테이블), 리저브, 출금 처리 중 금액을 비율대로 나눠 보여 주고 아래 범례에서 각 금액을 확인한다. 범례의 리저브 행을 누르면 리저브 상세로 간다. 그 아래 입출금 진행 상황, 충전할 수 있는 코인(원화 스테이블·USDC·USDT·BTC·ETH), 입출금 안내가 이어진다. 코인은 받는 즉시 원화 스테이블로 바꾸므로 보유 코인 목록은 없다. 코인을 누르면 그 코인으로 충전을 시작한다.

**혜택**은 사용 가능 리워드와 우선 사용 설정, 이번 달 페이백(확정, 확정 대기, 남은 한도, 한도 막대), 오늘·누적 리저브 보상, 리워드 내역 순서다. 리워드는 카드 결제 전용이며 출금할 수 없다는 점을 첫 묶음에 적는다.

**리저브**는 잔액과 변동 보상률, 오늘·누적 보상(실시간), 넣기·빼기, 결제 자동 사용 설정, 보상 조건 순서다. 보상은 받기 없이 리워드에 바로 더해진다.

**이용 내역**은 전체·카드·입출금으로 거르고 날짜별로 묶는다. 각 행의 `상세`를 누르면 거래 상세 시트가 열린다. 카드 결제는 결제 방식(매장·온라인·해외), 카드, 승인번호, 리워드·결제 잔액·리저브 사용액, 페이백, 환불액을 보여 주고 확정 결제에는 환불 버튼을 둔다.

**전체**는 프로필, 카드 관리와 이용 내역, 카드 설정(결제 한도, 온라인·해외 결제), 결제(리워드 우선·리저브 자동 사용), 계정(이메일·휴대폰·본인확인, 비밀번호 변경, 알림 설정, 로그아웃, 회원 탈퇴), 요금, 고객 지원(자주 묻는 질문, 약관 및 정책), 접힌 체험 설정 순서다. 메뉴 행에는 아이콘을 두지 않는다.

- **결제 한도**: 1회·하루·한 달 한도를 1만원 단위 슬라이더로 낮추거나 최대치까지 올린다. 오늘·이번 달 쓴 금액과 남은 한도를 함께 보여 준다.
- **온라인·해외 결제**: 각각 끄면 그 결제만 바로 거절된다. 결제 체험에서 결제 방식을 골라 확인할 수 있다.
- **알림 설정**: 결제·입출금 알림과 광고성 정보 수신 동의. 동의·철회한 날짜를 함께 보여 준다.
- **비밀번호 변경**: 지금 비밀번호 확인 후 새 비밀번호를 정한다.
- **회원 탈퇴**: 카드 해지, 진행 중인 결제·입출금 종료, 잔액 출금이 끝나야 진행되며 남은 할 일을 목록으로 보여 준다.

**카드 관리**의 신청은 3단계 진행 표시와 한 장의 묶음으로 구성한다. 선택한 플랜과 옵션은 잉크색 테두리로 표시한다. 실물카드를 고르면 배송지 입력(주소 찾기 → 상세 주소 → 받는 분 확인)을 거친다. 신청 확인에서 낼 금액(Plus 첫 달 이용료, 실물카드 발급비)과 지금 결제 잔액을 보여 주고, 모자라면 충전으로 안내한다. 발급 후에는 카드 정보와 잠금, 휴대폰 결제(삼성페이·Apple Pay), 플랜과 한도(다음 결제일, Plus·Basic 전환), 실물카드(신청·배송·비밀번호를 정해 활성화), 카드 관리(분실·도난 신고 후 재발급, 해지)를 나눠 보여 준다. 비용이 들거나 되돌릴 수 없는 동작은 확인 시트를 거친다.

## 시트와 움직임

충전, 출금, 결제, 환불, 리저브 이동, 영수증, 거래 상세, 카드 확인 시트는 640px 미만에서 아래에서 올라오는 시트, 그 이상에서 가운데 대화상자로 연다. 시트 위에는 손잡이를 두고, 제목과 확인 버튼은 고정한 채 본문만 스크롤한다. 출금 동의 행은 하단 버튼에 가려지지 않도록 본문 아래쪽에 붙여 둔다. 결제 체험에는 예시 결제처 3곳을 둔다.

움직임은 시트 등장, 토스트 등장, 누를 때 살짝 줄어드는 반응, 영수증 완료 표시만 쓴다. 동작 감소 설정에서는 모두 끈다. hover 효과는 마우스가 있는 기기에서만 적용해 터치 뒤에 강조가 남지 않게 한다.

## 문구

자동 생성 화면처럼 보이는 표현을 쓰지 않는다.

- 이모지, em dash, 장식용 영문 표제, 느낌표를 쓰지 않는다.
- `안전하고 간편한`, `스마트한` 같은 홍보 문구 대신 금액, 날짜, 조건을 쓴다.
- 버튼은 동작으로 끝낸다. 예: `충전`, `결제하기`, `9,900원 내고 신청`.
- 안내문은 사용자가 할 일과 제한을 한 문장으로 쓴다. 예: `받은 리워드는 카드 결제에 씁니다.`
- 금액은 `132,780원`처럼 쓴다. 이율은 `연 5%`처럼 기간을 붙인다.
- 체험판이라는 사실은 숨기지 않되 화면마다 반복하지 않는다. 홈 하단 안내와 머리의 `체험판` 표시로 알린다.

## 입출금과 영수증

충전은 보내는 곳(국내 거래소·해외 거래소·내 지갑·주소), 코인, 네트워크를 고르고 받는 주소와 보내는 순서를 확인한다. 입금 수수료는 없다. 출금은 결제 잔액에서 나가며 원화 차감액, 예상 코인 수량, 전환 수수료(원화 스테이블은 없음), 네트워크 비용을 확인하고 이메일 인증을 거친다. 자세한 기준은 [입출금 흐름](funding-flows.md)에 있다.

영수증은 완료 표시, 결제 금액, 사용한 원화와 리워드, 새 페이백, 결제 후 리워드 잔액을 나눠 보여준다. 이전 페이백 상계와 처리 중 다른 잔액 변동도 숨기지 않는다. 영수증이나 입출금 화면이 열려 있으면 토스트를 띄우지 않아 금액을 가리지 않는다.

## 접근성과 검증

주 메뉴, 뒤로 가기, 주요 버튼, 스위치는 44px 이상 누를 수 있다. 금액과 입력란 글자는 16px 이상이다. 시트와 대화상자는 초점을 가두고 Escape로 닫힌다. 3D 카드는 동작 감소와 터치 기기에서 정적으로 표시한다.

단위 테스트, 화면별 브라우저 검사, 320px부터 430px까지 5개 모바일 크기 검사를 실행한다(현재 수는 [테스트 안내](testing.md)). 실제 iOS와 Android 기기 검증은 별도다.

## 3D 이미지

리워드 카드의 동전과 첫 화면의 카드는 three.js로 오프라인 렌더링한 투명 WebP다. 금속·코팅 재질과 스튜디오 조명(소프트박스 반사)으로 실제 제품 사진처럼 보이게 했고, 앱은 이미지 파일만 쓴다(three.js를 번들에 넣지 않음). 동전은 로고 심볼(원 안의 물결)을 그대로 입체화했고, 카드는 앱 안의 Basic(네이비)·Plus(크림) 카드 디자인을 그대로 옮겼다.
