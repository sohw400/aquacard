# Aqua Card 화면·사용 흐름 개편

작성일: 2026-10-13

## 화면 원칙

카드가 서비스의 중심이다. 홈 상단에 카드 한 장을 크게 놓고 그 아래에 결제 가능 금액과 충전·결제 행동을 연결한다. 보유 자산 평가액, 출금 가능한 원금, 결제 전용 리워드는 구분한다. 홍보 문구, 영문 슬로건, 반복 배지, 장식용 차트와 보안 주장을 줄인다. 따뜻한 무채색 배경, 짙은 잉크색, 절제된 그린을 사용한다. 카드에는 네이비 또는 아이보리 소재, 벡터 금속 칩, 각인 워드마크, 미세한 반사광을 적용한다. 데스크톱은 최대 430px, 모바일은 본문 폭에 맞춘 실물 비율 카드다. 마우스·키보드에서 작은 3D 기울임을 제공하고 터치·동작 감소 설정·번호 공개 상태에서는 정적 표시한다.

| 화면 | 먼저 보여주는 정보 | 추가 정보 접근 |
| --- | --- | --- |
| 홈 | 큰 카드, 카드 상태, 사용 가능 금액, 충전·결제, 리워드·페이백 | 금액을 눌러 잔액 구성, 혜택 상세·리저브·최근 내역 |
| 지갑 | 원화 결제 잔액, 코인 충전·출금 | 기존 보유 코인 전환·출금, 자산 평가 안내 |
| 카드 | 카드 신청 또는 카드 정보·잠금, 월 페이백 현황 | 혜택 상세·실물 배송과 체험 도구 |
| 리저브 | 원금, 넣기·빼기, 적립 보상 | 보상 조건·변경 기록 |

주 메뉴는 4개이며 모바일에서는 하단에 배치한다. 이용 내역과 설정은 상단 보조 버튼으로 접근한다. 입출금은 한 화면에서 코인·수량 또는 원화 금액을 선택하고 적용 네트워크·비용·받는 금액을 확인한다. 리저브는 방향이 정해진 모달에서 금액만 입력한다. 코인 전환 수수료와 결제 출처·예상 페이백은 확정 전에 표시한다.

## 카드 신청

1. 샘플 본인확인과 체험 안내를 확인한다.
2. Basic 또는 Plus를 선택한다. 가상카드를 기본 제공하고 실물카드는 추가 옵션으로 둔다.
3. 비용·혜택을 확인하고 신청한다.

신청 후 모의 심사·가상 발급·활성화는 약 2.25초에 자동 진행한다. 내부 상태와 검증 순서는 유지한다. 보완·거절·배송 상태는 접힌 체험 도구로 확인하며, 심사 도구를 열면 자동 진행이 일시 정지된다. 실제 출시에서는 본인확인·카드 대행사 응답에 따라 처리해야 한다.

## 잔액·혜택 설명

홈의 사용 가능 금액은 리워드 우선 사용 및 리저브 자동 사용 설정에 따라 계산한다. 리저브 자동 사용은 결제 잔액 부족분에만 적용하고 사용한 원금은 이후 적립 대상에서 빠진다. 적립 중인 보상과 결제용 리워드 잔액을 구분하며, 리워드는 출금할 수 없다. 원화 스테이블은 발행사 제휴 후 지원 대상으로 표시한다.

연 5% 변동 보상, Basic·Plus 페이백, 수수료·한도·환불·보상 계산은 이번 개편에서 변경하지 않았다. 시간 진행과 보상률 변경은 설정의 접힌 체험 도구로 옮겼다.

## 리워드·페이백 현황

홈과 카드에서 확정 페이백·대기액·남은 월 한도와 지급률을 바로 보여준다. 혜택 상세는 사용 가능한 리워드와 리저브의 미수령 보상을 구분하고, 적립·사용 내역과 우선 사용 설정을 제공한다. 결제 완료 영수증에서는 결제 전 리워드, 사용액, 새 페이백과 결제 후 잔액을 각각 표시한다. 리워드를 차감한 만큼 새 페이백을 받은 경우에는 잔액이 같아진 이유를 설명한다. 집계와 상계 기준은 [리워드·페이백 표시 기준](rewards-visibility.md)을 따른다.

## 검증

금융·혜택 집계 로직 41개, 브라우저 시나리오 19개, 320–430px 기기 프로필 5개를 검증한다. 프로필 테스트는 Chromium 모사이며 실제 Safari·Android 하드웨어 테스트와 구분한다. 모의 체험과 실제 자금 이동·카드 발급이 없다는 사실은 모든 화면에서 안내한다.

## 입금부터 결제까지

신규 코인 입금은 견적 확인과 함께 원화 결제 잔액에 반영한다. 과거 모의 보유 코인은 유지하며 사용자 선택으로 전환한다. 출금은 원화 결제 잔액만 사용하고 수수료·예상 코인 수량을 보여준다. 리저브는 결제 잔액의 내부 배정으로 추가 매도가 없고, 외부로 출금하려면 먼저 결제 잔액으로 빼낸다. 이 흐름은 [KAST 공식 약관 조사](kast-funding-model.md)를 참고하되 보상률·수수료는 Aqua 자체 정책이다.

모든 금액 입력과 금융 처리는 모의 동작이다. 등장 효과는 짧게 제한하고 영수증이나 입출금 창이 열린 동안 토스트가 금액·확인 버튼을 가리지 않도록 한다. 실제 백엔드 이벤트·원장·정산의 후속 범위는 [입출금 아키텍처](funding-architecture.md)에 별도로 명시한다.
