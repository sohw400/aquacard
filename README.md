# Aqua Card PoC

한국 사용자를 위한 카드 서비스 **Aqua Card**의 인터랙티브 PoC입니다. 코인을 보내면 받는 즉시 원화 스테이블로 바뀌어 잔액이 되고, 카드로 쓰면 페이백을, 리저브에 두면 1초마다 보상을 받습니다. KAST의 구조(받은 코인 자동 매도, 세 멤버십, 회원 간 무료 송금)를 한국 원화 스테이블에 맞춰 옮겼고, 멤버십 요금과 요율은 한국 카드 시장에 맞췄습니다.

React·TypeScript·Vite로 만든 웹 앱입니다. 기본 웹 데모의 자금·카드·본인확인은 브라우저 안의 모의 처리이고, 별도 서버 연결 모드는 PostgreSQL 테스트 원장을 사용합니다. 실제 입금, 카드 발급, 개인정보 확인, 외부 송금이나 과금은 하지 않습니다.

## 실행

Node.js 24 LTS를 사용합니다.

```bash
npm ci --no-audit --no-fund
npm run dev
```

개발 서버는 5173번 포트를 씁니다.

## 서버 연결 개발

서버 기반은 **Node.js 24 LTS·Fastify 5·PostgreSQL 18**입니다. `docker compose up -d --wait postgres`로 로컬 DB를 실행하고 `.env.example`을 참고해 접속 정보를 설정한 뒤 `npm run db:migrate`, `npm run server:dev`를 실행합니다. 별도 터미널의 `npm run dev:server`에서 가입·로그인·회원 간 송금과 카드 결제 내역을 확인합니다. 신규 계정은 0원에서 시작하며 브라우저 체험 잔액을 가져오지 않습니다. CLI 적립은 테스트 금액이며 실제 자금·카드·본인확인과 연결되지 않습니다.

카드 승인·부분 매입·취소·환불은 내부 테스트 명령 `npm run server:card -- <event.json>`으로 처리합니다. 승인액은 별도 보류 계정에 확보해 송금에 다시 쓰지 못하며 화면에서 사용 가능·보류·전체 잔액과 결제 상태를 확인합니다. [카드 서버 처리 안내](docs/card-payment-server.md)에 JSON 예시와 확인 순서가 있습니다. 실제 발급사 API나 일반 회원용 결제 실행 API는 연결하지 않았습니다.

카드 전용 리워드와 스탠다드 페이백도 서버 장부로 처리합니다. 원금과 리워드·회사 재원을 분리하고, 부분 매입·환불·이미 쓴 페이백 회수 및 설정 재시도를 처리합니다. 기본 비활성이며 테스트 재원을 넣은 뒤 활성화합니다. [리워드 서버 처리 안내](docs/rewards-server.md)에 정책·운영자 명령·내부 대사와 출시 전 남은 범위를 정리했습니다.

카드 이벤트는 서명한 sandbox HTTP 또는 `server:inbox` 명령으로 먼저 보관하고 별도 작업자가 처리할 수 있습니다. 같은 결제의 매입 순서, 중복 전달, 서버 중단, 제한된 재시도와 운영자 이력을 관리합니다. 수신 202는 카드 승인 결과가 아닙니다. [카드 이벤트 수신·재처리 안내](docs/card-event-inbox.md)에 별도 DB 역할과 실행 방법을 정리했습니다.

서버 연결 화면의 카드 홈에서 카드 상태와 잔액, 이번 달 페이백을 보고 잠금·해제를 요청합니다. 이용 내역에서 결제·송금을, 내 계정에서 이메일과 로그인 기기를 확인합니다. 요청 접수와 발급사 확인을 구분하며, 응답이 끊기거나 탭을 다시 열어도 원래 요청으로 확인할 수 있습니다. 잠금 요청이 접수되면 테스트 원장의 새 승인을 차단하고, 기존 승인 건의 매입·취소·환불은 계속 처리합니다. [카드 승인 정책](docs/card-authorization-policy.md), [카드 설정 화면](docs/card-controls-ui.md)과 [발급사 요청·복구 안내](docs/issuer-command-outbox.md)에 흐름·권한과 검증 범위를 정리했습니다. 실제 카드 결제망에는 연결되지 않았습니다.

[카드 거래 운영 조회](docs/card-operations.md)는 이벤트 번호나 수신함 번호로 승인·거절·정산 상태를 확인합니다. 전용 운영 권한을 사용하고, 변경 불가 조회 기록을 먼저 커밋한 뒤 제한된 결과를 읽습니다. 승인 변경이나 재처리 권한은 포함하지 않습니다.

[고객 거래 자격·로그인 기기 관리](docs/customer-access-security.md)는 로그인과 거래 허용을 분리합니다. 신규·기존 계정은 기본 거래 제한 상태이며, 테스트 운영자의 명시적 허용과 이메일 확인을 모두 마쳐야 새 송금·카드 승인·잠금 해제가 가능합니다. 동결 후에도 기존 결제의 정산·환불과 과거 요청 재조회는 유지됩니다. 로그인 기기 조회·개별 해제·다른 기기 일괄 해제와 최근 비밀번호 확인을 제공합니다. 실제 본인확인과 MFA는 아직 연결되지 않았습니다.

[이메일 확인·복구 안내 발송](docs/email-verification-delivery.md)은 인증용 토큰과 암호화된 발송 대기열을 함께 저장하고 별도 작업자로 처리합니다. 개발 환경에서는 비공개 파일 메일함을 사용하며 SES 어댑터는 실제 발송 계정·도메인·권한 설정이 필요합니다. `server:mail:worker`로 작업자를 실행합니다. 실제 외부 메일은 발송하지 않았으며 이메일 확인이 고객 심사 승인을 대신하지 않습니다.

[서버 실행·검증 안내](docs/server-development.md)와 [기술 선택·배포 방향](docs/technology-decisions.md)에 재현 절차와 구현·계획을 구분했습니다. 운영 대상은 AWS 서울 리전 ECS Fargate·RDS PostgreSQL이며 아직 AWS 리소스나 유료 인프라를 생성하지 않았습니다. 공개 GitHub Pages는 기존 데모 모드를 유지합니다.

## 검증

마감된 날의 매입·환불은 `npm run --silent server:reconcile:statement -- <파일>`로 외부 테스트 명세서와 대조할 수 있습니다. [명세서 예시와 정산 차이 확인](docs/issuer-statement-reconciliation.md)

서울 AWS 계정에 스테이징을 처음 만들 때는 사설 네트워크, RDS·ECR·ECS, DB 초기화, 점검기 순서로 설치합니다. 배포 입력과 대기 중 과금되는 항목을 정리했습니다. [서울 스테이징 설치](docs/staging-setup.md)

원장 차이, 미처리 거래, 작업자 중단은 `npm run server:monitor`와 CloudWatch 경보로 점검합니다. 점검 계정은 건수·대기 시간만 읽습니다. [운영 경보와 장애 대응](docs/operations-monitoring.md) · [실거래 개방 전 확인할 사항](docs/launch-readiness.md)

합성 거래가 담긴 PostgreSQL 논리 백업은 `npm run test:recovery`로 복원합니다. `npm run test:pitr`는 물리 백업 이후의 거래 기록을 지정 시각까지 재생하고, 복원본에서 환불과 중복 요청을 검증합니다. [복원 훈련과 기대 금액](docs/server-development.md#postgresql-백업-복원-훈련) · [서울 스테이징 시점 복구와 경보 수신](docs/staging-recovery.md)

```bash
npm test
npm run build
```

개발 서버가 떠 있고 Chromium이 있는 환경에서는 브라우저 흐름도 확인합니다.

```bash
npm run test:browser
npm run test:devices
```

Chromium 경로는 `CHROMIUM_PATH`, 서버 주소는 `AQUA_BASE_URL`로 바꿀 수 있습니다(기본 `/usr/bin/chromium`, `http://127.0.0.1:5173`).

PR마다 서버·제품 테스트, 백업 복원, 경보 설정과 서버 연결 브라우저 흐름을 검사합니다. 브라우저 검사는 송금·결제, 리워드·페이백, 카드 잠금·해제, 고객 상태·로그인 기기, 이메일 확인·복구를 포함합니다. 실제 iOS·Android 기기 검증은 남아 있습니다. [자동 검사](.github/workflows/server-check.yml) · [검증 방법](docs/testing.md)

브라우저 데모는 2026-11-26 기준 브라우저 검사 57개, 320~430px 기기 프로필 5개를 통과했습니다. 기기 프로필은 Chromium에서 화면 크기와 터치를 **모사**한 것이며 실제 iOS Safari·Android 실기기 검증과 다릅니다. 자세한 절차는 [테스트 안내](docs/testing.md)에 있습니다.

## 둘러보기

[모바일·데스크톱 화면과 결제·환불 전표 보기](docs/ui/README.md)

[Aqua Card 웹 데모](https://sohw400.github.io/aquacard/)는 `main`에 반영된 버전입니다([배포 안내](docs/deployment.md)). 가입 직후 체험 잔액은 128,500원입니다.

1. **가입**: 이메일 인증 → 비밀번호 → 휴대폰 인증 → 신분증·얼굴 확인 → 본인 계좌 확인(1원 인증, 샘플 계좌) → 고객확인 질문. 가입을 마쳐야 앱을 쓸 수 있고 로그인·비밀번호 찾기를 지원합니다.
2. **홈**에서 카드 신청 또는 결제를 시작합니다. 지갑 잔액, 사용 가능한 리워드, 이번 달 확정 페이백을 각각 표시하며 최근 거래를 누르면 전표가 열립니다.
3. **충전**에서 코인(원화 스테이블·USDC·USDT·BTC·ETH), 네트워크, 보내는 곳을 차례로 고르면 받는 주소와 보내는 순서를 안내합니다. 입금 수수료는 없고, 받은 코인은 확인 즉시 원화 스테이블로 바뀌어 잔액이 됩니다.
4. **보내기**: 홈 › 보내기에서 `Aqua 회원에게`(태그·이름·휴대폰 번호·이메일로 찾아 수수료 없이 바로, 예: @minji.k, 010-0000-0101, minji.kim@aqua.example. 금액 화면에 남은 한도가 나옵니다), `QR 코드 찍기`(체험판은 체험용 QR을 골라 대신함), `지갑 주소로`(네트워크 비용, 원화 스테이블이 아닌 코인은 전환 수수료 0.5%, 이메일 인증) 중 고릅니다.
5. **카드**: 카드 › 카드 만들기에서 본인확인 → 멤버십(스탠다드·프리미엄·프라이빗, 실물카드와 배송지) → 신청 확인. 스탠다드는 실물카드까지 무료라 신청해도 잔액이 128,500원 그대로입니다. 발급 후 카드 정보·잠그기·결제해 보기, 삼성페이·Apple Pay 추가, 실물카드 비밀번호·활성화, 분실 재발급, 해지를 지원합니다.
6. **멤버십**: 카드 › 멤버십에서 프리미엄으로 바꾸면 연회비 100,000원이 잔액에서 바로 나갑니다(128,500원 → 28,500원). 이미 실물카드를 받았다면 메탈 카드(프라이빗은 골드 카드)를 새로 보내고, 받아서 `새 카드 쓰기 시작`을 누를 때까지 지금 카드를 그대로 씁니다. 프라이빗으로 올리면 프리미엄 연회비의 남은 몫을 빼고 냅니다. 내리기는 갱신일에 바뀌도록 예약되고, 갱신일에 잔액이 모자라면 스탠다드로 바뀝니다. 갱신 30일 전부터 홈과 카드 화면에 날짜·연회비·부족한 금액이 나옵니다. 카드 탭 아래 체험 도구의 `갱신 30일 전으로 이동`, `갱신 7일 전으로 이동`, `갱신일로 이동`으로 바로 확인할 수 있습니다.
7. **리저브와 리워드**: 리저브에 둔 금액의 보상이 1초마다 쌓여 1원 단위로 리워드에 바로 더해집니다(받기 버튼 없음). 리워드는 카드 결제에 먼저 쓰이며 출금할 수 없습니다.
8. **결제**: 리워드 → 잔액 → (켠 경우) 리저브 순서로 씁니다. 결제 방식(매장·온라인·해외), 사용자가 정한 결제 한도, 온라인·해외 결제 차단을 적용하고 확정되면 페이백을 적립합니다. 스탠다드에서 `리워드 먼저 쓰기`를 끄고 5,800원을 결제하면 페이백 58원이 쌓입니다.
9. **거래 내역**: 오른쪽 위 거래 내역 버튼에서 엽니다. 거래 상세(승인번호, 결제 구성, 페이백), 부분·전액 환불, 입출금 처리 내역을 봅니다.
10. **전체**: 프로필, 내 태그와 QR(태그 바꾸기, 휴대폰 번호·이메일로 찾기 허용, 회원에게 받기 체험), 카드(결제 한도, 온라인·해외 결제, 연간 거래 내역), 결제 순서(리워드·리저브 자동 사용), 계정(비밀번호 변경, 알림·광고성 정보 동의, 로그아웃, 회원 탈퇴), 요금, 도움말(자주 묻는 질문, 약관), 체험 설정.

주 메뉴는 홈·카드·혜택·전체이고 리저브, 거래 내역, 연간 거래 내역은 상세 화면입니다. 연간 거래 내역은 연도별 요약과 세금 신고 안내를 보여 주고, 내역을 표 형태로 복사해 엑셀이나 구글 시트에 붙여 넣을 수 있습니다. 모바일은 하단 탭, 넓은 화면은 왼쪽 사이드바로 표시하고 기기 설정에 따라 다크 모드로 바뀝니다. 앱 문구는 해요체로 씁니다. 글꼴은 앱에 포함한 Pretendard Variable입니다([글꼴](docs/screen-design.md#글꼴)). 첫 화면·홈·카드 소개에 three.js로 만든 3D 카드를 사용합니다. 카드는 실시간으로 렌더링해서, 누르거나 마우스를 올리면 살짝 기울고 빛반사가 따라 움직입니다(동작 감소 설정에서는 정지 이미지). 화면 구조는 [화면 설계](docs/screen-design.md)를 따릅니다.

상태는 이 브라우저의 localStorage에만 저장됩니다. 실제 이름·휴대폰·신분증·주소를 넣지 마세요. 화면의 `체험용 주소 넣기`, `샘플 정보 채우기`, 예시 주소 검색을 쓰면 됩니다. 비밀번호는 해시만 저장합니다. 이전 체험의 Basic·Plus 데이터는 스탠다드로 불러옵니다.

## 기본 정책

기준 파일은 [policy.ts](src/lib/policy.ts)입니다. 멤버십은 KAST의 세 등급 구조를 따르고 금액은 한국 카드 시장에 맞췄습니다([요금과 정책](docs/policy.md#1-한국-시장에-맞춘-파라미터)).

| 항목 | 스탠다드 | 프리미엄 | 프라이빗 |
| --- | --- | --- | --- |
| 연회비 | 무료 | 100,000원 | 500,000원 |
| 카드 페이백 | 1%, 월 100만원 결제까지(최대 1만원) | 1.5%, 월 200만원 결제까지(최대 3만원) | 2%, 월 500만원 결제까지(최대 10만원) |
| 리저브 보상 | 연 5% 단리·변동형, 1천만원까지 | 연 5.5%(+0.5%p), 3천만원까지 | 연 6%(+1%p), 5천만원까지 |
| 실물카드 | 선택, 무료 | 메탈 카드 포함 | 골드 카드 포함 |
| 재발급 | 무료 | 무료 | 무료 |

연회비는 잔액에서 먼저 내고 1년마다 같은 날 다시 냅니다. 갱신 30일 전과 7일 전에 날짜와 금액을 알립니다(체험판은 홈과 카드 화면의 안내로 보여 줍니다). 카드를 해지하면 연회비를 날짜로 나눠 남은 몫을 잔액으로 돌려주고(오늘부터 갱신일 전날까지의 날수 ÷ 365, 원 단위 내림), 등급을 올리면 그 몫을 새 연회비에서 빼고 냅니다. 내리기는 갱신일까지 지금 혜택을 쓰므로 갱신일에 바뀌도록 예약하고 돌려주지 않습니다. 갱신일에 잔액이 모자라면 스탠다드로 바뀝니다.

| 모든 등급 공통 | 내용 |
| --- | --- |
| 입금 | 무료. 코인은 받는 즉시 원화 스테이블로 전환 |
| Aqua 회원에게 보내기 | 무료, 바로 처리. 한 번에 100만원·하루 200만원·한 달 500만원(가입 30일 동안과 추가 확인을 받은 계정은 절반) |
| 지갑 주소로 보내기 | 네트워크 비용. 원화 스테이블이 아닌 코인으로 보내면 전환 수수료 0.5% |
| 결제 한도 | 최대 1회 50만원·하루 100만원·한 달 500만원, 사용자가 낮출 수 있음 |

원화(법정화폐) 입출금은 지원하지 않습니다. 원화 스테이블의 실제 이름·발행사·네트워크는 제휴 후 정하며 PoC는 `KRWS`라는 자리표시자를 씁니다. 시세는 고정 예시입니다.

KAST는 지원 자산마다 청산 주소를 두고 받은 코인을 거래 확정 즉시 자동 매도해 USD 잔액 하나만 보여 줍니다. Aqua도 코인을 보유하지 않으므로 코인 지갑이나 코인 현황 화면이 없습니다. 실제 전환은 제휴 거래소·OTC가 맡는 구조를 권합니다([KAST 비교와 한국 적용](docs/kast-alignment.md), [KAST 공식 자료 확인](docs/kast-funding-model.md), [입출금 흐름](docs/funding-flows.md)).
